## 1. 为什么智能体需要记忆（30 秒版）

- **大模型记忆**：干预模型内部状态（长上下文架构、缓存、注意力稀疏化）——目标是把"窗口变大"；
- **智能体记忆**：给决策智能体一个**可演化的外部记忆库**——目标是把"经验留住、让行为变强"。
- 大模型 vs 智能体记忆的核心差异：智能体记忆支持**跨任务持久化、环境驱动适应、有意的记忆操作**（写入/检索/进化）。
- 与 RAG 的差异：RAG 供给**静态外部知识**；智能体记忆内嵌于**持续交互**，不断纳入自身行为与环境反馈。
- 一句话：**上下文工程管"窗口内的资源调度"，记忆管"跨时间的认知连续性"**。
> 依据：`00_综述/笔记_Zhang2024-Survey-Memory-Mechanism.md`；`docs/03` 第 16–17 节。

## 2. 记忆分类：短期 / 长期 / 程序

| 记忆类型 | 时间尺度 | 内容 | 代表论文 |
|---|---|---|---|
| **短期 / 工作记忆** | 任务内 | 当前上下文、中间结果、约束 | MemGPT、SCM、LLMLingua、LongLLMLingua、ICAE |
| **长期记忆 · 事实** | 跨任务 | 客观事实、参数、事件 | MemoryBank、Zep（时序知识图谱）、ChatDB（SQL） |
| **长期记忆 · 经验** | 跨任务 | 成败教训、策略 | Reflexion、ExpeL、Memp、LARP |
| **程序性记忆** | 跨任务 | "怎么做"的可执行流程/技能 | Memp、Voyager（技能库）、LARP 动作空间 |

**长期 vs 短期两把尺子**（对齐 `docs/03` 第 18.1 节）：
1. **来源**：任务内（短期）vs 跨任务（长期）；
2. **时间尺度**：当前会话内有效 vs 持久沉淀。

> 依据：各模块笔记；`docs/03` 第 16、18 节。

## 3. 记忆操作统一框架：写入 → 读取 → 管理（进化）

综述（Zhang 2024）把记忆流程抽象为三类操作，三者协作服务于 LLM 推理：

```
             ┌──────────────┐
  感知信息 ──▶│  ① 写入 Writing │──▶ 记忆库
             └──────────────┘     │
             ┌──────────────┐     │
  查询/推理 ─▶│  ② 读取 Reading  │◀──┘（按相关性/任务导向）
             └──────────────┘
                    ▲
             ┌──────┴────────┐
             │ ③ 管理 Management │
             │ 合并 Merging      │
             │ 反思 Reflection   │
             │ 遗忘 Forgetting   │
             └───────────────────┘
```

### 3.1 写入（存什么、怎么表示）

| 策略 | 代表 | 要点 |
|---|---|---|
| 存原始 + 结构化 | TiM | 抽取实体关系三元组，相似内容同组存储 |
| 控制器决定何时写 | SCM | LLM 记忆控制器自主调度读写时机 |
| 自我驱动更新 | MemGPT | LLM 自主调用读写函数"分页"换入换出 |
| 摘要式写入 | MemoryBank / MemoChat | 对话 → 每日高级摘要 / 主题索引 |
| 预存储推理（写入即推理） | PREMem | 写入时抽取事实/经验/主观片段 + 跨会话链接推理 |

### 3.2 读取 / 检索（怎么取）

| 检索范式 | 代表 | 适用 |
|---|---|---|
| 向量语义 Top-K | ExpeL（Faiss） | 经验/语义相似召回（近似） |
| 符号精确查询（NL→SQL） | ChatDB | 事实/结构化精确召回 |
| 时序知识图谱 | Zep/Graphiti | 跨会话多跳、时序推理 |
| LSH 近似检索 | TiM | 超长会话低成本召回 |
| 记忆链（Chain-of-Memory） | ChatDB | 多步查询规划 |
| 多策略混合主动检索 | MIRIX（讲义引用） | 按查询特点自主选路（embedding/BM25/string） |

> 检索设计要点：**任务感知查询**（查询列表显式化）决定召回质量；检索与进化解耦（检索只读、进化只写）便于独立评测。

### 3.3 管理 / 进化（合并 · 反思 · 遗忘）——**本主题的重点**

| 操作 | 定义 | 代表论文 | 实现要点 |
|---|---|---|---|
| **合并（Merging）** | 冗余条目去重、冲突消解、生成高阶记忆 | TiM（merge）、MemoryBank（摘要综合）、PREMem（链接对 θ=0.6） | 相似度阈值 + LLM 判定 |
| **反思 / 抽象（Reflection）** | 从低层记忆提炼高阶教训/画像/策略 | Reflexion（语言反思）、Generative Agents（事件触发反思）、TiM（Post-thinking） | 事件积累触发；反思文本注入后续上下文 |
| **遗忘（Forgetting）** | 淘汰低价值/过时记忆，控制库规模与噪声 | MemoryBank（**艾宾浩斯遗忘曲线**）、TiM（**时间衰减**） | 时间流逝 + 重要性打分；命中强化 |
| **程序化（Proceduralize）** | 经验 → 可执行技能/程序 | Voyager（技能库）、Memp（指令+脚本蒸馏） | 轨迹蒸馏 + 更新/纠正/弃用 |
| **更新纪律（Update）** | 记忆内容持续校正 | Memp（Update/Deprecate）、Zep（图谱增量更新） | 与最新经验同步，防过时 |

**三条"进化"技术路线（按复杂度递进，适合汇报讲演进故事）**：

1. **规则/操作驱动（2023）**：TiM 的 Insert/Forget/Merge + 时间衰减；MemoryBank 的艾宾浩斯曲线——操作明确、可解释、工程简单；
2. **控制器驱动（2023）**：SCM 的 memory controller 决定"何时写、何时读、读什么"——把调度显式化；
3. **预存储推理 / 可学习操作（2025）**：PREMem 把推理负担前移到写入时刻（链接对跨会话综合）；MemSkill/StructMem 把"INSERT/UPDATE/DELETE/SKIP"做成**可学习**的记忆操作——进化本身成为可消融、可量化的设计。

> 依据：`04_记忆进化/` 三篇笔记 + `00_综述` Table 3 操作清单。

## 4. 记忆进化效果为什么重要（量化证据链）

- **遗忘有依据才可信**：MemoryBank 证明"选择性遗忘"比全存/全忘更接近人类、检索更聚焦；赛题可用"时间衰减 + 重要性打分"（`docs/04` 避坑点 4）。
- **进化提升可测量**：TiM（记忆动态演化减少偏置）、ExpeL（经验积累 → 成功率一致提升）、Memp（记忆精化 → 成功率与效率双升）、PREMem（全规模模型提升，小模型≈大模型）。
- **防止"静态 RAG 化"**：长期记忆 ≠ 静态资料库；核心差异就是**可演示、可量化的进化**（`docs/04` 避坑点 1）。

## 7. 与赛题③的映射（汇报收尾段）

```
智戎规划管线 ⇄ 记忆系统
 ① 规划（目标/约束 + 查询列表 Q）
 ② 检索：短期（工作记忆装载）+ 长期（事实 SQL/图谱 + 经验向量）   ← ChatDB/ExpeL/Zep
 ③ 短期工作记忆：容量受限 + 主动操纵 + 必要时压缩              ← MemGPT/SCM/LLMLingua
 ④ 长期记忆：事实（结构化）+ 经验（摘要+向量）                 ← MemoryBank/Reflexion/Memp
 ⑤ 记忆进化：写入 / 合并 / 遗忘 / 抽象                        ← TiM/PREMem/MemoryBank
 ⑥ AFSIM 反馈 → 新经验写回                                    ← Reflexion/Memp
```

- 创新点映射：**A 记忆进化链路**（PREMem 预存储推理 + MemSkill 可学习操作）→ `04_记忆进化/`；**C 查询列表显式化** → ChatDB Chain-of-Memory；**E 可解释溯源** → 每条记忆带 source+场次+时间戳。
- 六组消融（G0–G5）对应"无记忆 → 短期 → +事实 → +经验 → +进化 → +检索策略"逐层加码，见 `docs/04` 第 5.3 节。
