## 一句话总结

**从"计算机体系结构"而非"生物大脑"取经：让 LLM 把 SQL 数据库当作"符号记忆"，用「记忆链（Chain-of-Memory）→ 一系列 SQL 指令」完成复杂多跳推理，把记忆从"神经的、近似易错的"变成"符号的、精确可查询的"。**

## 摘要（归纳）

LLM 的记忆设计深受生物大脑影响，但神经记忆**近似、易累积误差**，难以支撑复杂推理。ChatDB 提出**符号记忆框架**：
- 由 **LLM + 一组 SQL 数据库**构成（LLM 生成 SQL 指令操作数据库）；
- 推理时先规划 **Chain-of-Memory**（一系列 SQL 查询/更新语句），再逐条执行，把中间结果作为生成依据；
- 记忆内容 = 数据库表（结构化、可精确查询、可更新），而非向量/文本块。
在需要复杂推理的合成数据集上验证了有效性，回答可溯源（每个结论可回溯到 SQL 执行结果）。

## 技术路线

```
用户问题
  └─① 记忆规划：LLM 生成 Chain-of-Memory（阶段化 SQL 计划）
       └─② 逐条执行 SQL → 更新/查询数据库（符号记忆）
            └─③ 汇总执行结果（表格/摘要）
                 └─④ LLM 基于检索结果生成最终回答
```

## 关键结果

| 方面 | 效果 |
|---|---|
| 多跳复杂推理 | 合成数据集上符号记忆显著优于无记忆 / 神经记忆基线 |
| 可解释性 | 记忆读取可通过 SQL 语句审查（可溯源、可调试） |
| 记忆写入 | 以 SQL 精确更新，避免文本记忆的语义漂移 |

## 优点 / 局限

- **优点**：符号记忆精确、可查询、可更新，天然支持结构化的"事实记忆"（装备参数、条令、战例台账）；回答可溯源；避开了向量检索的近似性。
- **局限**：需要把非结构化信息**先结构化落库**（建表/清洗成本）；SQL 生成质量依赖 LLM，复杂查询易错；对模糊语义（经验类）记忆支持弱。
