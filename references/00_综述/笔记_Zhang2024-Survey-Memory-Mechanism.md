## 摘要（归纳）

LLM Agent 相比原始 LLM 的核心特性是**自进化能力**（self-evolving），支撑长期、复杂的「智能体-环境」交互；而支撑这种交互的关键组件是**智能体记忆**。已有记忆机制散落在不同论文中，缺乏系统性综述。本文：
1. 讨论 LLM Agent 中记忆的"是什么 / 为什么需要"；
2. 系统回顾记忆模块的**设计与评估**方法；
3. 综述记忆在各类 Agent 应用中的重要作用；
4. 分析现有工作局限与未来方向，并维护配套仓库（论文清单持续更新）。

## 技术路线 / 综述框架

```
第 1 部分  记忆基础：什么是记忆（信息处理视角）、为什么需要（自进化、长期交互）
第 2 部分  记忆设计空间：
  ├─ 记忆来源（source）：环境感知 / 内部推理 / 用户反馈
  ├─ 记忆目标（target）：自我 / 任务 / 用户 / 群体
  └─ 记忆形式（form）：文本记忆 vs 参数记忆（效率 / 可解释性权衡）
第 3 部分  记忆管道（Memory Pipeline）—— 核心：
  ├─ 记忆写入（Writing）：存什么、怎么表示
  ├─ 记忆管理（Management）：合并（Merging）/ 反思（Reflection）/ 遗忘（Forgetting）
  └─ 记忆读取（Reading）：按相关性 / 任务导向检索
第 4 部分  记忆评估：评估方法 / 基准梳理
第 5 部分  Agent 应用：开放世界游戏、技能与知识、具体应用…
第 6 部分  局限与未来方向
```

## 关键结论与洞察（对赛题最有价值）

1. **三类记忆操作**是智能体记忆的统一抽象：**写入 → 管理 → 读取**，三者协作把信息供给 LLM 推理（论文 Table 3 对 30+ 模型逐项打勾）。
2. **代表性机制对照**（论文 Table 3，节选）：
   - 写入做得好的：TiM（关系三元组结构化存储）、SCM（记忆控制器决定何时写）、MemGPT（自主更新）、MemoChat（片段摘要 + 主题索引）；
   - 管理做得好的：MemoryBank（艾宾浩斯遗忘曲线 + 每日摘要 + 用户画像）、Voyager（环境反馈精化技能库）、Generative Agents（事件积累足够后触发反思）；
   - 读取做得好的：ChatDB（Chain-of-Memory → SQL 查询）、ExpeL（Faiss 向量库 Top-K 相似成功轨迹）、MPC（记忆池检索 + 忽略无关记忆的 CoT）。
3. **文本记忆 vs 参数记忆**的权衡：文本记忆**写入高效、可解释**但读取成本随上下文增长；参数记忆**读取高效、信息密度高**但写入需训练、不可解释。对话/上下文类任务适合文本记忆；大规模知识类任务适合参数记忆。
4. **反思与遗忘**是"管理"的关键：反思从低层记忆生成高阶信息；遗忘淘汰无关/过早记忆，避免检索噪声。

## 优点 / 局限

- **优点**：统一的"设计空间 + 管道"框架便于横向对比；Table 3 的逐模型操作清单可直接当"选型速查表"；配套 GitHub 仓库持续维护论文列表。
- **局限**：止于 2024 年初（未见 2024–2025 的 PREMem/StructMem/MemSkill/RMM/Zep 等新工作）；对**评估**（benchmark 细节、指标口径）着墨较少；对多模态记忆几乎没有涉及。
