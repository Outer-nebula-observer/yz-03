## 一句话总结

**用"自撰 memo"维持长程开放域对话一致性：把长对话拆成片段，片段内先"记忆化"成结构化 memo（主题抽取 + 摘要 + 记忆片索引），再走「记忆化-检索-作答」循环，并用从公开数据集重构的三阶段指令对 LLM 微调——在三个测试场景中超过强基线。**

## 摘要（归纳）

MemoChat 提出一条**指令精炼流水线**，让 LLM 学会用**自撰 memo（便签）**维持长程开放域对话一致：
1. 将长对话划分为**对话片段（dialogue segments）**；
2. 每个片段执行**记忆化（memorization）**：抽取主要讨论主题（keys）、生成片段摘要、汇总为结构化 **memo** 并建立索引（主题→memo 的检索映射）；
3. 后续对话走 **检索-作答（retrieval-response）**：按当前话题召回相关 memo，作答时参考。
针对"记忆化、检索、作答"各自阶段**精心设计定制指令**，并从公开数据集重构训练数据微调 LLM；专家人工标注长程对话一致性测试集。在开源与 API 型聊天机器人大规模三个场景上验证，优于强基线。

## 技术路线

```
长对话流
  ├─① 片段划分（dialect segments）
  ├─② 记忆化（memorization）：主题抽取 → 摘要 → 结构化 memo（含 topic keys 索引）
  └─ 循环：③ 检索（当前话题 → 相关 memo）→ ④ 作答（融合 memo 保持一致）
       （每个阶段配定制指令 + 重构数据集微调 LLM）
```

| 方面 | 效果 |
|---|---|
| 长程一致性 | 专家标注测试集上长程对话一致性显著优于基线 |

## 优点 / 局限

- **优点**：memo 结构化（主题键 + 摘要）让检索有明确索引入口；记忆粒度（片段级而非逐句）控制成本；三阶段指令微调思路清晰可复现。
- **局限**：需要微调（不能直接套在黑盒模型上）；索引以主题键为主，语义/向量检索能力弱；面向对话一致性，复杂推理/事实精确召回未展开。

## 与赛题③的联系

| 借鉴点 | 说明 |
|---|---|

| 检索入口设计 | memo 的主题索引可在赛题检索层增加"符号/关键词路"（与 ChatDB、ExpeL 呼应） |
