## 一、阶段一 P0：答辩前必做（预计 3–5 个工作日）

### 1.1 消融 v2 真模型重跑（最高优先级——所有"不可外推项"的最终裁决）

**做什么**：`MemoryController(llm=get_llm("glm"), embedding=get_embedding("glm"), factual=FactualStore(db, glm_emb), experiential=ExperientialStore(glm_emb))` 组装后重跑 `python -m eval.ablation`。

**裁决的三个问题**（docs/12 §2.6 列明的 Mock 不可外推项）：

| # | 问题 | Mock 下的状态 | 真模型预期 |
|---|---|---|---|
| Q1 | **C 类转述命中**（"黑夜机动吃过什么亏"→"夜间行军未派先遣侦察遭伏击"） | 0.63（靠判别性单字，非真语义） | 语义泛化主张的真正检验 |
| Q2 | **G5 hybrid vs vector 单路** | 负结果（hybrid 0.857 < vector 0.929，p=0.626） | 三路互补主张的真正检验（词袋无语义时混合只剩噪声稀释） |
| Q3 | **任务层引用率的真实含义** | 度量"上下文构造正确"（MockLLM 回显） | 度量"LLM 善用记忆"（验证 T6 已见宽松引用率 1.00、规划含"避免重蹈覆辙…的教训"） |

**验收标准**：
- [ ] G0–G6 全组真模型数字 + 随机基线对照（eval/stats.py 已就位）
- [ ] Q1/Q2/Q3 有明确结论（**无论正负**——负结果同样写入报告，与 Mock 负结果对照本身是有价值的 finding）
- [ ] G4 跨场次（p 值应随真语义提升）与 G6 阶段亲和复查

**⚠️ LLM 非确定性**：两次验证运行中抽取条数已现波动（3 vs 2 条、约束满足率 0.50 vs 1.00）。真模型消融必须：每组 **≥3 次运行取均值±std**（`stats.py` 的 bootstrap/置换检验直接支持）；LLM 侧 temperature 已固定 0.2。

### 1.2 min_score / θ 重标定（消融重跑的前置）

**探针数据已量化重标定必要性**（v0.4 实测，GLM embedding × 融合权重 α=0.5）：

```
负例 top1 融合分: max=0.139  中位=0.102   （6 条负例）
正例 top1 融合分: min=0.238  中位=0.464   （4 条正例）
→ 当前 min_score=0.16：负例 0 泄漏，但负例边际仅 0.02（薄）
→ 建议重标定为 0.18–0.20（负例留 0.04+ 余量，正例 min 0.238 仍全保留）
```

**做法**：跑消融 v2 的 **E 噪声研究**（12 条负例 × min_score 网格）+ **S 敏感性扫描**（θ 近重复对/误拦率），按"负例 top1 最大值 vs 正例 p25"取分离点。**注意**：融合权重使等效余弦阈值 = min_score/α（0.16/0.5=0.32）——扫描时同时记录 α 变体下的分离度。

**验收标准**：
- [ ] 新 min_score 有标定表支撑（负例返回率 ≤5%，正例 hit@5 不降）
- [ ] θ 决策落定（Mock 数据显示 0.6 优于默认 0.8——docs/12 §2.5 遗留决策项；真 embedding 分布不同，须重扫）
- [ ] 标定过程写入 docs/12 增补节（协议可复现）

### 1.4 Scaling 曲线：场次数 vs 规划质量（"越用越强"的最强证据）

**做什么**：连续 20 个场次（同型任务变体，goal/地形/教训各变化），每 5 场测一次：H 类复用 hit@5、任务层引用率、约束满足率、错误重复率（同一教训是否二犯——用 GLM 判断规划是否采纳了已知教训）。画曲线。

**预期形态**：前期上升 → 遗忘/查重介入后趋稳。**若平坦**：本身就是 finding（库规模稀释检索精度 → 引出 §2.3 检索精度研究）。

**验收标准**：
- [ ] 一张 20 场次曲线图（报告核心图）
- [ ] 至少 3 次重复取均值

## 二、阶段二 P1：课程收尾（按价值排序）

### 2.1 四处关键词模板 → LLM 升级（接口已留，逐个灰度）

| # | 模板 | 位置 | 升级收益 | 回归保障 |
|---|---|---|---|---|
| 1 | 阶段查询生成 | `stages.py STAGE_TEMPLATES` | 查询随 goal 语义化（当前 goal 仅占位注入），P5 的完全体 | G6 阶段决胜对 |
| 2 | 教训阶段归因 | `stages.py attr_stage` | 消除"未识别默认归 coa_analysis"的亲和混杂 | G6 + 归因抽检 |
| 3 | G2 晋升门控 | `boundary.py PROMOTION_PATTERNS` | 关键词可被"教训"二字绕过 → LLM 语义分类 | 审计日志 + 闲聊拒绝用例 |
| 4 | **NL→attrs 解析** | retrieval 层新增 | "红方 T-90 多快"→`{"装备":"T-90"}`——**sql 精确路最后一环**（当前 attrs 需手写） | A 类属性用例 |

每处都有 Mock 回退（`get_llm` 切换），先并行跑对比再切换默认。

### 2.2 测试集扩容 ≥100 条 + 统计功效补强

- H 类 6→20、G 类 4→12（当前 p=0.059/0.127 的瓶颈是样本量）；
- 标注协议（谁标/双标一致性）写入 testset.py 头注释——防循环论证最后一环；
- 分层报告矩阵：{fact, experience} × {精确, 语义} × {有干扰, 无干扰}。

### 2.3 机制深化（按价值排序）

1. **经验可信度/结果加权（最推荐）**：importance 从静态 → 动态信任分——教训被装载后追踪该场次 AFSIM 结果，成功 +信任、失败 −信任；`experiential_store.search` 的重要性加权项换成信任分。这是 ExpeL/RMM 正统路线，也是 scaling 曲线的机制解释器；
2. **冲突消解（真实缺口）**：merge 只处理相似不处理矛盾（"预备队早投入"vs"晚投入"可共存）。最小版：时间戳新者优先 + LLM 仲裁记录；
3. **知识锚定校验**（docs/04 §1.2 未兑现承诺）：复盘候选入库前与权威知识库比对，杜绝"库外经验"——接智戎知识库后做，触碰课程"防编造"主线；
4. **时间敏感检索（G7）**：`HybridRetriever(time_decay_weight=...)` 钩子已实现未消融——验证创新点 F"遗忘提升检索精度"；
5. **合并/抽象升级**：相邻成对启发式 → PREMem 式聚类全量比对。

## 三、阶段三 P2 / 研究延伸

| 方向 | 核心问题 | 与现有工作的衔接 |
|---|---|---|
| **R1 场次制智能体的记忆生命周期** | 一条教训的"寿命"由什么决定（写入→复用→校准→遗忘） | §1.4 曲线 + §2.3 信任分 + F 遗忘研究合成一篇完整工作；"mission-oriented agent memory"是较新场景 |
| **R2 记忆污染与鲁棒性** | 错误教训混入后：自然淘汰还是被保护线"永生"污染？（当前 importance≥2 一视同仁——人工标的错误教训同样永生） | 对抗视角（红方注入假教训）+ 防御（锚定校验/信任分/出处可信度）——可直接用 GLM 生成污染注入实验 |
| **R3 阶段感知检索的机理验证** | stage_bonus 增益来自"标签正确"还是"仅是额外排序信号"？消融：正确标签 vs **随机打乱标签** vs 无标签 | MDMP 阶段亲和是机制级最有原创性的点（MIRIX 路由的阶段化扩展），目前仅 4 对证据 |
| **R4 多席位共享记忆** | 红蓝对抗推演多席位共享经验库：隔离（防泄露）vs 共享（协同进化） | AFSIM 对抗场景天然契合，"集成进智戎"叙事延伸 |
| **R5 公开基准定位** | LoCoMo / LongMemEval 上对比，确认通用性边界 | 领域测试集是强项也是软肋；一组公开基准数字显著提升可信度 |

**工程项（按需）**：BM25 增量更新替代全量重建（万级库前的必要项）、asyncio/SSE 服务化、WebUI 多场次并发、LLMLingua 第三档压缩真跑、embedding 批量接口（当前逐条，100 条库建库约 100s）。
