# 面向作战规划智能体的可进化外部记忆系统：设计、实现与验证

> 版本：v0.8（DeepSeek 接入、P0 智戎适配落地后整理）
> 本文档采用“问题定义 → 研究问题 → 思路 → 实现 → 验证 → 讨论”的叙述主线。
> 代码位于 `code/课题3_长短期记忆/`，实验脚本与结果集中在 `eval/`、`examples/`、
> `integration/zhirong_kit/`。

---

## 摘要

作战规划智能体以场次为单位连续接收任务，但模型自身不保存场次间状态，导致经验无法跨场次积累。本文提出一套外部记忆系统，将记忆组织为短期工作记忆与长期双库（事实库、经验库），并以“复盘晋升”作为两层之间的唯一写通道。系统具备写入查重、合并、艾宾浩斯遗忘与抽象四类进化操作，检索层采取向量、BM25、属性精确三路融合。我们在自建 50 条 8 类作战测试集上开展分层消融：双库在固定用例集上的贡献显著（配对置换检验 p=0.0001）；第一场复盘沉淀的教训在第二场相关任务中召回率为 0.83，对照组为 0；负例滤噪在标定阈值下为 0；遗忘保护线无误删。随后以 DeepSeek deepseek-flash 验证真实模型能力，生成规划时对装载记忆的宽松引用率为 1.00。局限在于测试集规模有限、语义泛化与混合检索增益尚需真向量模型复测。

## 1 引言

### 1.1 研究背景

作战规划任务以场次（session）方式到达：智能体接受任务、生成方案、推演反馈、进入下一场。场次之间不存在天然状态传递，模型权重与上下文窗口均不保留跨场次信息。由此形成一类典型问题：同一类夜间进攻任务，第一场在隘口遭遇伏击，第二场可能重蹈覆辙——系统缺少“历史教训”的显式承载。

已有三类技术路线未能完整覆盖该需求：
- 长上下文：扩大窗口，但窗口内信息仍随场次结束而消失；
- 检索增强生成（RAG）：解决外部知识供给，但不解决“经验如何沉淀、更新、淘汰”；
- 模型内记忆：通过微调或状态注入改变模型本身，代价高且不可审计。

因此需要一套位于模型之外的、具备读写与演化能力的记忆系统。

### 1.2 问题定义

将上述场景中的记忆需求形式化为四类失败模式（P1–P4），并在研究过程中由导师反馈补充第五类（P5）：

| 编号 | 问题 | 后果 |
|---|---|---|
| P1 | 跨场次经验无法积累 | 同类错误反复出现 |
| P2 | 场次内上下文超限且硬约束丢失 | 规划违反作战约束 |
| P3 | 参数级精确查询与语义级经验查询混用单一路径 | 参数错值或经验召回失败 |
| P4 | 复盘内容无差别入库、缺少淘汰与审计 | 记忆库噪声累积、不可解释 |
| P5 | 以任务目标文本直接检索，语义信息量不足 | 检索结果泛化、相关性弱 |

### 1.3 研究问题与主要思路

围绕上述问题给出五个可验证的研究问题（Research Questions, RQ）：

- **RQ1（双库贡献）**：将经验记忆与事实记忆分离存储，是否在固定的检索用例集上带来可测的召回增益？
- **RQ2（跨场次复用）**：第一场复盘写入的经验能否在第二场相关任务中被检索召回，并优于“不写入”的基线？
- **RQ3（检索策略）**：三路融合相对单路检索的增益是什么？在字符词袋环境下是否成立？
- **RQ4（滤噪与遗忘安全）**：负例查询能否被阈值过滤；遗忘机制是否只淘汰低价值记忆而不误删受保护记忆？
- **RQ5（真实模型能力）**：接入真实 LLM 后，规划生成是否实际引用装载记忆而非仅回显上下文？

整体思路可概括为：**把跨场次知识组织成一个可演化的外部系统**，以“写入—检索—更新—淘汰”为生命周期，以可回放、可审计为约束。该思路用第 2 节相关工作说明来源，用第 3 节设计落地，用第 4–5 节实验回答 RQ1–RQ5。

### 1.4 文章组织

第 2 节梳理相关机制及其借鉴取舍；第 3 节给出系统设计，含形式化定义与实现要点；第 4 节描述实验方法；第 5 节报告结果；第 6 节讨论发现、局限与效度威胁；第 7 节总结；第 8 节给出配图与汇报建议。

## 2 相关工作与设计依据

本章按“记忆形态—上下文组织—长期存储—检索—进化—任务驱动”六个方面梳理已有工作，
说明本文在每一条线索上借鉴了什么、不沿用哪一部分，以及取舍的依据。

### 2.1 记忆形态与操作框架

Zhang 等（2024）的智能体记忆综述把记忆工作归纳为“形式—操作—应用”三层框架：记忆可以是
自然语言摘要、结构化知识或嵌入向量；操作包括写、读、更新、遗忘；评估关注记忆的持久性、
准确性与对任务的影响。多数系统只覆盖其中一两层——例如检索增强只解决读，长上下文只解决
容量。本文的定位是在该框架下补齐“写、更新、遗忘”的完整闭环，并把每一项操作做成可审计事件。
这一综述没有给出可直接部署的实现，但为我们区分“静态知识供给”与“可演化记忆”提供了概念基础。

### 2.2 上下文组织与工作记忆

**MemGPT** 把 LLM 上下文当作操作系统内存，划分主上下文与外部存档，由模型自主决定何时换页，
实现“超出窗口也能调用历史”。其核心贡献是把上下文管理从“一次性填满”变为“按需换页”。
本文采用其分层思想（常驻关键区＋滚动消息队列），但将换页决策改为**确定性阈值**（0.7 预警、
1.0 flush）：自主换页难以在消融中复现，确定性阈值使压缩行为可测试、可断言。

**SCM** 提出 flash/archived 双记忆与记忆控制器，控制器显式决定“何时读、何时写、何时归档”。
本文沿用了“控制器作为唯一调度者”的职责划分，并将“何时写长期记忆”进一步收窄为复盘晋升
通道（见 3.6）。

**LLMLingua / LongLLMLingua / ICAE** 从压缩角度缓解上下文超限：前者按困惑度删 token，
后者用可学习压缩器重构提示。这三条路线依赖训练或语言模型，本文未直接采用，只借用两个结论：
长提示中首尾信息的保持优先（LongLLMLingua 的位置偏置），以及压缩对象应限定为历史消息而非
不可丢的约束。压缩器本身在 `compression.py` 预留了适配接口，作为后续对照实验的扩展点。

### 2.3 长期记忆存储

**ChatDB** 把数据库当作符号记忆，将自然语言查询翻译为 SQL，实现精确的事实问答。本文沿用了
“数据库即记忆”这一设定，但只保留属性精确过滤（`search_attrs`）这一子集，不实现完整 NL→SQL；
原因是作战参数查询往往由系统已有结构化字段驱动，意图解析的收益在真实接口到位前无法验证。

**ExpeL** 从成功与失败轨迹中抽取“经验库”，并以向量检索相似经验供新任务参考。本文的经验库
在形态上与其一致（教训/对策文本 + 向量召回），但补充了重要性加权与 SQLite 持久化，并把
“经验如何产生”限定到复盘晋升，避免轨迹噪声直接入库。

**Reflexion** 用语言反思记录失败原因，并在下一轮显式引用。本文借鉴“语言形式经验”这一低成本的
表示方式；不采用其在线强化更新策略，因为战场经验的可信度标注（成功/失败归因）需要与 AFSIM
反馈绑定，属于后续“动态信任分”的工作。

**MemoryBank** 引入艾宾浩斯遗忘曲线 `R=e^{-t/S}` 与“召唤强化”机制，用于长期记忆的自动淘汰。
本文直接采用该模型，并作两处领域化改动：一是以天为时间单位修正单位失配；二是增加
`importance≥2` 的保护线，避免“失败教训被遗忘”在防御场景中造成不可接受的后果。

**Zep** 以时序知识图谱和事件记忆组织长期事实，强调时间戳与溯源。本文没有采用图存储（构建
与纠错成本高），但从其设计中保留了“每条记忆携带来源、时间戳、场次”的溯源字段，支撑
可解释检索与审计。

### 2.4 记忆检索

**MIRIX** 面向多智能体场景提出多策略主动检索，按查询特点在 embedding、BM25、字符串等策略间
选择或组合。本文压缩为两类记忆上的三路（vector/bm25/sql）并行融合：不引入六类记忆体系，
因为作战场景当前只需区分事实与经验；同时保留“按查询路由”的接口语义（QueryItem.route），
以备真实场景需要更细粒度策略时扩展。

**TiM 的 Recalling** 在生成前从外部记忆检索与当前上下文相关的历史信息，并把检索结果与
生成任务耦合。本文把这一过程显式化为“查询列表→检索→装载”步骤，并将每个查询的命中回填到
`answer_memory_ids`，使检索计划可审计——这是对 Recalling 的实现层强化，而非新机制。

**RMM** 用前向多粒度摘要构建记忆库、后向在线强化精化检索。本文借鉴了“前向摘要”的思想雏形
（抽象操作），但保留确定性执行，不引入在线强化，原因是强化所需的奖励信号在课程场景中
尚不稳定。

### 2.5 记忆进化

**PREMem** 提出“预存储推理”：写入前对候选内容做聚类与链接对推理，再决定是否入库，以
降低记忆冗余。本文采用其“相似度阈值 θ 判定语义重复”的核心思路，但未实现完整聚类流程，
保留为成对比较的启发式；原因是在 50 条量级下全量聚类带来的收益尚无法被统计显著地观测。

**StructMem** 以事件级绑定和跨事件整合组织层次化记忆。本文的“抽象”操作从其“周期性整合”
思想演化而来：把多条具体经验合成一条通用教训。StructMem 的完整分层存储没有采用，因当前
两类记忆已足够表达作战流程知识。

**MemSkill** 把记忆操作建模为可学习的 INSERT/UPDATE/DELETE/SKIP 技能。本文采用了操作类型化
的接口形态（`MemoryOp` 枚举与 `op_history`），但执行仍为确定性规则，学习部分留作未来工作。

**Mem-α / MemAST** 将记忆更新工具化，由模型或强化学习选择执行。本文借鉴“建议—执行分离”：
语言模型建议候选，确定性代码执行写入、合并、遗忘、抽象。这一分离保证了复盘可审计，也是
后续把“建议侧”替换为可学习策略的接口边界。

### 2.6 任务/阶段驱动的记忆供给

**Synapse** 将轨迹示例（trajectory-as-exemplar）注入方案生成，使新任务参考相似历史方案。
本文在“方案拟制”阶段借鉴此思路，通过阶段模板检索相似战例与对策，即案例推理（CBR）的
一种轻量实现。

**事件分段理论（Event Segmentation Theory）** 认为人把连续活动切分为离散事件段来理解与
记忆。本文据此与军事决策流程（MDMP）结合，将记忆供给按七个规划阶段组织：不同阶段需要不同
类型记忆，并由 `stage` 字段与亲和加分实现“阶段对阶段”的复用。这一设计回应 P5。

### 2.7 小结：本文的定位与差异

逐项看，多数机制都能在已有工作中找到原型；本文的差异体现在两个层面。第一，**组合层面**：
将上下文分层、符号/向量双存储、三路检索、四类进化操作组合进同一个可审计闭环，并以
“复盘晋升”这一条通道连接短期与长期，这是已有工作各自未完整覆盖的编排方式。第二，
**领域化层面**：加入失败教训保护线、属性精确命中绕过相似度阈值、阶段化记忆供给等面向
作战场景的约束。选择标准始终一致：机制可确定性复现、可独立消融、面向参数级精确与可审计。
## 3 系统设计

### 3.1 设计目标与总体架构

设计目标可归纳为四点：**(G1) 可进化**——记忆随场次写入与淘汰；(G2) 可审计——每次写入/删除可回放；(G3) 可替换——检索/进化模块可独立开关；(G4) 可部署——零第三方依赖，离线可运行，并可接入真实模型。

架构上分为四层：模型层（统一数据对象）、能力层（短期/长期/检索/进化，四模块互不依赖）、跨切面（边界与阶段）、编排层（控制器与管线）。四能力层只通过数据对象交互，物理上为“可独立消融”提供前提。

### 3.2 短期工作记忆

**动机**：存放当前场次的目标、约束、查询计划与滚动消息；约束不可因压缩丢失（回应 P2）。

**方法**：采用 MemGPT 式分层，即常驻关键区与滚动消息队列，并设置确定性阈值（0.7 预警、1.0 flush）。flush 将最旧消息移出队列并递归生成摘要，摘要与原始信息保留在归档区，供复盘晋升使用。

**实现要点**：渲染函数将“装载记忆”段显式放入注入 LLM 的上下文（置于头部关键区），使检索结果真正进入生成环节。此前系统仅登记记忆 id、未渲染正文，导致“检索增强”在生成端断链——这是实现阶段发现并修复的关键缺陷。

### 3.3 长期双库

**动机**：参数查询要求零容错（T-90 与 M1A2 同库时不得张冠李戴），经验查询要求跨措辞泛化。两种需求对存储命中的要求相反（回应 P3），分库是自然选择。

**方法**：
- 事实库：SQLite 行存 + 属性键值过滤（`search_attrs`），辅以向量近似召回；
- 经验库：向量语义召回 + 重要性加权，可选 SQLite 持久化。

**实现要点**：属性精确命中（`attrs`）在融合阶段**绕过 min_score**——查询方显式指定过滤条件，命中即相关，不应被相似度阈值否决。这一设计避免了“符号路命中却被阈值过滤”的逻辑矛盾。

### 3.4 记忆检索：三路融合与单路模式

设检索结果为记忆条目集合，每条经三个路由各得一个归一化分数：

```
s_hybrid(id) = Σ_{r ∈ {vector,bm25,sql}} w_r · n_r(id)   (融合式)
s_single(id) = n_route(id)                               (单路式)
```

其中归一化 `n_r`：向量路取余弦（裁剪至非负）；BM25 路以查询自匹配得分为上界（避免单字巧合被放大）；SQL 属性路恒为 1。随后叠加阶段亲和增量 `stage_bonus`，过滤低于 `min_score` 的条目，对最终结果执行一次命中强化。

单路模式（`mode="single"`）权重视为 1，用于 G5 消融中分离“多路互补”与“单路质量”。这一口径修正了早期实现中“路由仅标注、三路总合”导致的分路实验失真问题。

### 3.5 记忆进化：写、合、忘、抽

进化模块采用“建议-执行分离”：语言模型或规则负责从复盘文本提出候选，确定性代码负责查重、落库、合并、遗忘与抽象。

四类操作的形式化：
- **写入**：候选向量与库内条目余弦相似度超过阈值 θ 则拒绝（语义去重）；
- **合并**：新写入的相似条目合成一条，记录 `merged_from`；
- **遗忘**：留存率 `R=e^{-t/S}` 低于阈值且 `importance<2.0` 时删除；`importance≥2.0` 受保护；
- **抽象**：同场新经验不少于两条时，生成一条通用教训。

实现中修复了一处机制交互缺陷：抽取规则曾将“教训”句自动标为 `importance=2.0`，恰等于保护线阈值，导致所有教训永久免于遗忘。修复后自动抽取取 `1.5`，保护线仅保留显式标注与抽象产物。该缺陷的发现是本系统机制级交互研究的一个实例。

### 3.6 边界与阶段感知

短期内容进入长期库的唯一通道是复盘晋升，经三道门控：复盘驱动、类别判定、语义查重；每次判定写入审计日志（回应 P4）。

阶段感知针对 P5：查询不再由目标文本字面生成，而按 MDMP 七阶段模板生成，并为阶段匹配的记忆增加亲和分；复盘教训按关键词归因至阶段，供后续同阶段检索优先召回。

### 3.7 实现与可复现性要点

所有外部依赖（LLM、Embedding、存储）通过依赖注入注入控制器，业务代码不感知具体实现。离线默认 Mock 组件，保证确定性；真实模型通过 `.env` 配置切换。消融脚本固定随机种子，统计推断不依赖第三方库。

## 4 实验方法

### 4.1 数据集

自建 “作战规划记忆测试集”，共 50 条 8 类：

| 类 | 数量 | 考察内容 | 对应 RQ |
|---|---|---|---|
| A 属性精确 | 6 | sql/attrs 参数召回 | RQ1 |
| B 事实语义 | 6 | 转述查询 | RQ1 |
| C 经验转述 | 8 | 同义不同词 | RQ1/RQ3 |
| D 词法 | 4 | BM25 | RQ3 |
| E 负例 | 12 | 噪声过滤 | RQ4 |
| F 参数干扰 | 4 | 张冠李戴检验 | RQ1 |
| G 阶段决胜 | 4 | 阶段亲和 | RQ1/RQ3 |
| H 跨场次 | 6 | 第一场→第二场 | RQ2 |

构造策略：查询与答案刻意避免共享关键词（转述类），并显式加入负例与干扰项，以降低“作者自证”的循环风险。

### 4.2 评估协议

检索侧指标：hit@k、recall@k、MRR、NDCG。任务层指标：约束满足率、记忆引用率、噪声污染率。

对照组原则：**固定用例集，以依赖注入开关能力**。例如关闭经验库通过注入空经验库实现，而非删减用例；跨场次 gold 在运行期解析（写入条目 id 仅在进化后可得）。

### 4.3 统计方法

- 随机基线采用解析期望 `1-C(n-g,k)/C(n,k)`；
- 均值置信区间采用 bootstrap（不假设正态）；
- 两组差异采用配对置换检验（逐用例配对，交换符号构造零分布）。

统计功效受限之处（H 类 6 条、G 类 4 对）在结果与讨论中明确标注。

### 4.4 配置

离线实验使用 MockEmbedding（字符词袋）与 MockLLM（规则抽取）；真实模型验证使用 DeepSeek deepseek-flash，检索端仍为 MockEmbedding。此配置差异在解释真实模型结果时必须保留。

## 5 结果

### 5.1 RQ1：双库贡献

| 组 | 配置 | hit@5 | 分类别 C/D/G |
|---|---|---|---|
| G2 | 仅事实库 | 0.341 | 0 / 0 / 0 |
| G3 | 双库全开 | **0.636** | 0.63 / 1.0 / 1.0 |

差值 0.295，配对置换 p=0.0001。经验类用例在 G2 下全 0 属预期语义（库中无经验）；随机基线 0.357，G3 显著高于随机。需说明：0.636 仍距 1 较远，失分集中于转述类（C），反映字符词袋对同义改写的局限，也为 RQ3 的负结果铺垫。

### 5.2 RQ2：跨场次复用

| 配置 | H 类 hit@5 |
|---|---|
| 处理组（第一场复盘→第二场查询） | 0.833 |
| 对照组（不跑第一场，gold 不可达） | 0 |

负控（第一场渡河教训 vs 第二场巷战查询）返回 0，排除“什么都召回”。p=0.059 受样本量（5）限制，结论为方向性证据。

### 5.3 RQ3：检索策略

| 配置 | hit@5 | 干扰压制 |
|---|---|---|
| hybrid | 0.857 | **1.0** |
| vector 单路 | **0.929** | 0.875 |
| bm25 单路 | 0.786 | 0.875 |
| sql 单路 | 0.214（仅 attrs 用例） | 0.375 |

字符词袋下混合未显著优于 vector 单路（p=0.626），但干扰压制显著更优（1.0 vs 0.875）。该负结果定义的边界是：多路互补的价值依赖真实语义向量，需在真模型中复测。

### 5.4 RQ4：滤噪与遗忘安全

min_score 扫描（0.05/0.10/0.16/0.25）对应负例返回率 92%/58%/0%/0%，正例 hit@5 从 0.96 降至 0.82；取 0.16 为标定拐点。遗忘研究：30 天未召回未保护条目删 10/10，受保护删 0，新写入删 0；删除后对应查询命中为 0/5/5，无系统性误删。

### 5.5 RQ5：真实模型能力

DeepSeek deepseek-flash 验证 20/20 通过。规划生成输出中出现“东侧为唯一装甲通行方向”“夜间行军必须提前派先遣侦察，防止遭伏击”，分别对应装载的地形事实与历史教训；宽松引用率 1.00，约束满足率 1.00，抽象无指令残留。该结果证明真实模型确实使用装载记忆，但受限于检索端仍是 MockEmbedding，属于方向性证据。

## 6 讨论

### 6.1 主要发现

结构层面的结论较为稳健：双库贡献显著（RQ1）、跨场次写入可被召回（RQ2）、遗忘保护无误删（RQ4）、负例滤噪在标定阈值下有效（RQ4）。这些结论不依赖语义模型质量。

### 6.2 局限

- 统计功效：跨场次 6 条、阶段决胜 4 对，p 值仅方向性；
- 循环论证残余：测试集由项目组自建，虽刻意措辞分离，同一作者生成两端仍存在风险；
- 检索口径：真实模型验证在 MockEmbedding 之上，未覆盖真向量下的效果；
- RQ3 在词袋环境为负结果，混合增益待真向量复测。

### 6.3 效度威胁

- **内部效度**：对照组采用依赖注入，且每组独立 controller，跨组污染风险低；但 “gold 运行期解析”依赖写入顺序，脚本中已固定执行顺序。
- **外部效度**：虚构作战数据与真实智戎知识库在词汇分布、条目粒度上存在差异，迁移时需按第 8 节领域巡检重新标定。

### 6.4 未来工作

真向量检索重跑与重标定、跨场次测试集扩容、动态信任分与经验冲突仲裁、知识锚定校验、智戎真实链路接入。

---

## 7 结论

本文将跨场次记忆组织为可演化的外部系统，以分层消融验证了双库与跨场次机制的结构性贡献，并以 DeepSeek 验证了真实模型对装载记忆的实际使用。受限于数据集规模与检索口径，语义泛化与混合增益仍需真向量复测。后续工作将优先完成真实环境下的复测与领域标定。
