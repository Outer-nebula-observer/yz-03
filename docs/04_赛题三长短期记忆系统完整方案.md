## 0. 一句话目标与验收底线

**一句话目标**：为智戎作战规划智能体构建一个**可演化的外部记忆系统**——短期（工作）记忆支撑"当前规划内的上下文与中间结果"，长期记忆沉淀"跨任务的事实与经验"，通过**记忆检索**按需供给、通过**记忆进化**完成写入 / 合并 / 遗忘 / 抽象，使规划结果更可靠可信，并随推演场次持续变强。

**自定验收底线（保底）**：

- 端到端链路跑通：`规划 → 查询列表 → 检索 → 短期/长期记忆 → 规划输出`；
- 短期记忆：能装载并压缩当前场次上下文，支持"容量受限 + 主动操纵"；
- 长期记忆：≥ 100 条持久化条目，区分**事实记忆**与**经验记忆**两类；
- 记忆检索：任务感知查询能命中相关长期记忆（Recall@5 达标并记录）；
- 记忆进化：演示"写入 / 合并去重 / 遗忘（衰减或淘汰）/ 抽象"至少 3 类操作；
- 集成：在智戎规划链路（或 mock）中完成一处真实调用并记录时延；
- 评估：按 `03` 第 20 节指标给出不少于 5 组消融实验结论。

## 1. 系统总体架构

### 1.1 分层架构（对齐你的设想）

```
                 ┌──────────────────────────────────────────────┐
                 │          智戎规划管线（启动→分析→生成→分析      │
                 │              →比较→批准→指令）                 │
                 └──────────────┬───────────────────────────────┘
                                │ ①规划：意图理解 · 任务分解
                                │      生成查询列表 Q = [q1..qn]
                                ▼
                 ┌──────────────────────────────────────────────┐
                 │ ② 检索（任务感知查询 → 记忆库 → 返回 m_t）      │
                 │   · 短期记忆：当前场次上下文/中间结果/约束        │
                 │   · 长期记忆：事实记忆 + 经验记忆               │
                 └──────────────┬───────────────────────────────┘
                                │
                 ┌──────────────▼───────────────────────────────┐
                 │ ③ 长期 / 短期记忆                              │
                 │   · 短期工作记忆：m_t 装载进上下文（必要时压缩）  │
                 │   · 长期记忆：规划结束后触发记忆进化             │
                 │     （写入 / 合并 / 遗忘 / 抽象）               │
                 └──────────────┬───────────────────────────────┘
                                ▼
                 AFSIM 对抗推演 → 结果评估 → ④反馈：沉淀为新经验
```

### 1.2 与智戎系统的挂接点

| 智戎环节 | 记忆系统做什么 | 对应模块 |
|---|---|---|
| LLM 认知协调者（意图理解/任务分解） | 生成结构化查询列表，记录本次规划目标与约束 | ①规划 + 查询列表 |
| 规划管线（分析/生成/比较/批准） | 每一步读写短期工作记忆；需要知识时触发检索 | ②检索 + ③短期记忆 |
| 知识锚定（只许用库内数据） | 长期记忆同样受知识锚定约束，杜绝"库外经验"混入 | ③长期记忆 + 记忆进化 |
| 专业技能池 / AFSIM 推演 | 推演结果与评估作为"环境反馈"写回 | ④反馈 + 记忆进化 |
| 跨场次复用 | 历史战例/经验作为长期记忆被召回，影响新一轮规划 | ③长期记忆 + ②检索 |

### 1.3 概念数据模型（待补代码）

- **短期工作记忆槽位**：`{plan_id, goal, constraints, query_list[], loaded_memory[], intermediate_results[], status}`；
- **长期记忆条目**：`{id, type(fact|experience), content, source, timestamp, importance, decay, embeddings, links[]}`；
- **查询列表项**：`{q_id, intent, target(memory_type), query_text, query_vector}`；
- **检索结果**：`{m_id, score, modality, memory_type, evidence, rank}`。

> 数据模型只在概念层定清"四类对象 + 关键字段"，具体结构随代码骨架阶段落地。

## 2. 四大模块技术路线

> 每模块按「职责 → 候选方法（引用 03 论文）→ 选型建议 → 验证点」给出；全部论文要点见 `03` 第 19 节。

### 2.1 短期 / 工作记忆层

- **职责**：容量受限、临时存储、主动控制，只保留与当前任务高度相关的信息；把检索到的 m_t 格式化后装载进上下文。
- **候选方法**：
  - MemGPT 的 `working context`（高频关键事实/偏好/角色设定）+ `FIFO queue`（消息/回复/系统消息）——**工作记忆的组织范式**；
  - SCM 的 `flash memory`（短期记忆）+ 记忆控制器——**主动决定哪些短期信息进入当前输入**；
  - LongLLMLingua / LLMLingua / ICAE——**上下文压缩**（短期记忆容量有限时压缩历史交互）。
- **选型建议**：先用"槽位式工作记忆 + 长度截断/摘要压缩"跑通，再引入 LLMLingua 式压缩作为消融对比。
- **验证点**：上下文超限时能否自动压缩；压缩后关键约束是否保留；是否与"容量受限 + 主动操纵"的认知定义一致。

### 2.2 长期记忆层

- **职责**：可演化的外部记忆库，持久积累 + 按需检索；分两类：
  1. **事实记忆**（Factual）：过去事件、用户特定信息、外部环境状态（装备参数、条令、战例客观信息）；
  2. **经验记忆**（Experiential）：长期积累的行为策略与成败经验（哪类规划有效/失效）。
- **候选方法**：
  - Generative Agent 记忆流 / MemoryBank——**摘要式事实记忆**；
  - Reflexion（语言形式经验）、Voyager（可执行技能库）、Memp（程序性记忆）、LARP（角色长期记忆）——**经验记忆**；
  - Zep（时序知识图谱）——**事实 + 时序关系**的结构化长期存储；
  - SCM 的 `archived memory`——**归档长期记忆**。
- **选型建议**：底层用"向量库（语义召回）+ SQLite/图（符号精确查询）"双存储；事实记忆走结构化，经验记忆走摘要 + 向量。
- **验证点**：事实记忆能否精确召回（参数级）；经验记忆能否在相似新任务中被激活并改变规划行为。

### 2.3 记忆检索

- **职责**：构造**任务感知**查询，返回相关记忆 m_t，并格式化为 LLM 策略可直接使用的形式（文本片段序列或结构化摘要）。
- **候选方法**：
  - ChatDB——SQL 符号检索（记忆链 → SQL，精确结构化查询）；
  - ExpeL——向量库 Top-K（相似成功轨迹召回）；
  - MIRIX——多策略主动检索（`embedding_match` / `bm25_match` / `string_match`，按查询特点自主选择）；
  - RMM——后向反思检索（基于 LLM 引用的证据，在线强化学习迭代精化检索）；
  - TiM——Recalling（从外部记忆检索与当前上下文相关的历史信息）。
- **选型建议**：**混合检索**打底（向量 + BM25 + SQL），再加"查询列表 → 分路检索"的编排；RMM 式反思精化作为进阶。
- **验证点**：检索层单独打分（Hit Rate / MRR / NDCG@K / Recall@K）；查询列表中的每个 q 是否都能落到对应记忆类型。

### 2.4 记忆进化（写入 / 合并 / 遗忘 / 抽象）

- **职责**：将记忆候选整合进现有记忆库：冗余合并、冲突消解、低价值丢弃、结构重组，生成更高阶记忆。
- **候选方法**：
  - TiM——Post-Thinking + 记忆更新（时间衰减、相关性评估、插入/遗忘/合并）；
  - MemoryBank——高级摘要 + 用户画像洞察（日常演化）；
  - RMM——前向反思（utterance/turn/session 多粒度摘要构建个性化记忆库）；
  - PREMem——**预存储推理**（写入时即做跨会话综合：聚类 → 链接对 → 链接对推理，θ=0.6）；
  - StructMem——事件级绑定 + 跨事件整合（分层记忆、降本）；
  - MemSkill——**可学习记忆操作**（INSERT / UPDATE / DELETE / SKIP，技能库 S 自我进化）。
- **选型建议**：先用**规则 + LLM 摘要**实现四种操作（写/改/删/跳），作为 MVP；进阶引入 PREMem 式预存储推理与 MemSkill 式可进化操作作为创新点。
- **验证点**：合并是否减少冗余；遗忘是否只淘汰低价值记忆；抽象是否产生可复用的高阶经验；每次进化是否可回放、可解释。

## 3. 编排闭环：规划 → 查询列表 → 检索 → 长期/短期记忆

| 步骤 | 动作 | 输出 | 涉及模块 |
|---|---|---|---|
| ①规划 | 意图理解 + 任务分解，明确本次规划目标与约束 | 结构化任务 + 查询列表 Q | 短期记忆写入 |
| ②查询列表 | 把"需要哪些知识/经验"显式化为 q1..qn（事实型 / 经验型 / 约束型） | 查询计划 | 查询列表 |
| ③检索 | 每个 q 走任务感知检索（向量/SQL/混合） | 相关记忆 m_t + 引用 | 记忆检索 |
| ④长期/短期记忆 | m_t 装载进工作记忆（必要时压缩）；规划全程读写短期记忆 | 增强后的上下文 | 短期/工作记忆 |
| ⑤规划输出 | 基于增强上下文完成分析/生成/比较/批准/指令 | 规划方案 | 规划管线 |
| ⑥反馈 | AFSIM 推演 + 结果评估 | 成功/失败信号 | 环境反馈 |
| ⑦记忆进化 | 把本场"产物 φ_t"选择性转存：写入经验、合并去重、遗忘低价值、抽象高阶教训 | 更新后的长期记忆 | 记忆进化 |

> 这条链路把讲义的"记忆形成 / 记忆检索 / 记忆进化"三段式，映射成了可演示、可评测的**七步闭环**。

## 5. 评估方案（大纲）

### 5.1 指标（复用 `03` 第 20 节）

- **检索质量**：Hit Rate、MRR、NDCG@K、Recall@K（分短期/长期、分事实/经验统计）；
- **有效性**：结果正确性（Accuracy）、引用准确性（F1）；
- **生成质量**：上下文相关性、答案忠实度、答案相关性；
- **效率**：时间开销 Δt=(1/M)Σ(t_end−t_start)、计算开销（峰值 GPU 显存）；
- **记忆维度**：工作记忆（短期信息保持、上下文压缩效率）、情景记忆（事件时序一致性）、语义记忆（概念关联）、事实记忆（客观召回）、经验记忆（行为策略有效性）、任务内 vs 跨任务（信息保持 vs 长期迁移）。

### 5.2 测试集（两类）

1. **通用 benchmark**（借用 `03` 第 20.4 节）：对话类（LoCoMo / LongMemEval / MemoryBank / DialSim）、功能智能体类（MemBench / MemoryAgentBench）；
2. **自建作战规划测试集**（核心，待补）：构造 ≥ 40 条"跨场次经验复用"与"事实记忆召回"问题，每条标注 relevant memory + gold answer + 任务内/跨任务标签。

### 5.3 消融实验（v2 设计 · 已实现于 eval/ablation.py）

> v1 设计存在四个缺陷（对照组被用例集污染、分路对比无效、进化产物不在 gold、无任务层指标/基线/显著性），v2 全部修复——设计原则：**固定用例集 + 依赖注入开关能力 + 随机基线 + 配对置换检验**。

| 组 | 配置 | 验证什么 | v2 实现 |
|---|---|---|---|
| G0 | 无记忆（检索旁路） | 任务层基线（引用率=0） | `_NullRetriever` 注入 |
| G1 | 仅短期工作记忆 | 会话流程本身贡献 | 同上（走完整会话） |
| G2 | + 长期事实记忆 | 事实记忆贡献 | **空经验库注入**（固定 44 条用例集） |
| G3 | G2 + 经验记忆 | 经验记忆贡献 | 双库全开（主配置） |
| G4 | G3 + 记忆进化（跨场次） | **"越用越强"**：场次1 复盘写入→场次2 召回（gold=场次1 沉淀，运行期解析；含无关迁移负控） | H 类 6 条 vs 无场次1 对照 |
| G5 | 检索策略对比 | hybrid vs 真单路（vector/bm25/sql）× 融合权重 | `mode="single"` + `route_override` |
| G6 | 阶段亲和 on/off | stage_bonus 是否让对口记忆排在干扰前 | 同内容不同 stage 决胜对 |
| E | 噪声研究 | 负例返回率 × min_score（**标定协议**） | 12 条负例扫描 |
| F | 遗忘研究 | 保护线行为 / S×时间 / 误删率 | 合成老化条目 |
| C | 压缩研究 | 压缩率 / 约束保留 / 关键信息保留 | truncate vs summarize |
| S | 敏感性 | θ 查重 / min_score / stage_bonus | 扫描矩阵 |

测试集（eval/testset.py，50 条 8 类）：属性精确 / 事实语义 / 经验转述（刻意零字面重叠）/ 词法 / **负例** / **参数干扰**（T-90 vs M1A2 同库考张冠李戴）/ **阶段决胜对** / **跨场次**。结果与统计检验见 `docs/12_评审修复与消融v2报告.md`。

## 6. 创新点候选（大纲）

- **A（首选）记忆进化链路**：PREMem 式"写入时预存储推理" + MemSkill 式"可学习记忆操作"，把"何时写、写什么、怎么合并/遗忘"做成可量化消融；
- **B 作战域双记忆库**：事实记忆（结构化/SQL）+ 经验记忆（摘要/向量）双通道，绑定知识锚定约束；
- **C 查询列表显式化**：把"规划 → 查询列表 → 检索"做成可解释的检索计划，而不是隐式检索；
- **D 反思抽象**：TiM Post-Thinking / Reflexion 风格，把本场规划抽象为跨场次可复用的"作战教训"；
- **E 可解释溯源**：每条注入规划的记忆带 `source + 场次 + 时间戳`，规划输出强制引用；
- **F 遗忘与时间敏感检索**：时间衰减 + 重要性打分，证明"遗忘"能提升检索精度而非降低。

> 2–3 周内建议主攻 **A + C + E**（与你的流程设想绑定最紧）；B/D/F 作为有余力加分项。

## 8. 降级预案与风险

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 代码包与长短期记忆无关 | M0 发现只有文本 RAG | 复用其检索/存储组件，短期/长期/进化三层自建 |

## 10. 避坑要点（赛题③专属）

1. **别把"长期记忆"做成又一个静态 RAG 库**：核心差异在"进化/更新/遗忘"，务必可演示、可量化；
2. **短期与长期边界要清晰**：来源（任务内 vs 跨任务）与时间尺度两把尺子（对应 `03` 第 18.1 节）；
3. **检索与进化解耦**：检索只读、进化只写，二者独立评测，避免互相污染；
4. **遗忘必须有依据**：时间衰减、重要性打分、冲突检测三者至少取一，并在论文里给出量化证据；
5. **经验记忆要"能改变行为"**：验证标准不是"召回了"，而是"召回后规划输出真的变了"；
6. **知识锚定同样约束长期记忆**：外部经验/幻觉混入长期记忆会让"防编造"防线失效。
