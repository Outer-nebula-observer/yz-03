## 0. 汇报速览（30 秒版）

> 我们给作战规划智能体做了一套**可演化的外部记忆系统**：短期工作记忆管"当前场次的上下文资源"，长期双库（事实+经验）管"跨场次知识沉淀"，通过**复盘晋升**打通两层，按**七步闭环**运转。系统不是 RAG（只读），而是**可进化**的：写入有查重、遗忘有艾宾浩斯、抽象可复用，并且**全链路可审计**。我们用 50 条作战测试集 + 随机基线 + 配对置换检验做了 G0–G6 消融：双库贡献 p=0.0001、"越用越强"跨场次复用 0.83 vs 对照 0、负例滤噪 0%；同时接入了 GLM 真模型，验证了"LLM 会真的用记忆写规划"（引用率 1.00）。**一句话卖点：把记忆从上下文工程升级为可进化的外部系统，并用实验而不是演示来论证它。**

## 1. 设计框架

### 1.1 问题驱动（为什么做）

| # | 失败模式 | 具体表现 | 后果 |
|---|---|---|---|
| P1 | 每场从零开始 | 第一场夜战吃亏，第二场照犯 | 经验不积累，越用不变强 |
| P2 | 场内信息超窗 | 战报挤爆上下文，粗暴截断丢掉"禁止越境" | 违反硬约束 |
| P3 | 查询口径混杂 | 查"T-90 速度"要精确、查"夜战教训"要语义 | 单一检索两头不讨好 |
| P4 | 记忆越攒越脏 | 同一条教训写十遍、流水账混进知识库 | 库越大越难用、不可审计 |
| P5 | goal 字面直查没意义 | 任务一句话信息量太薄，检索结果泛化（老师意见） | 检索相关度差 |

### 1.2 总体架构：两层四模块 + 双循环

```
编排层：pipeline.py（七步闭环）· controller.py（总调度）
跨切面：boundary.py（边界/三道门/审计）· stages.py（MDMP 阶段感知）
能力层：short_term（工作记忆）· long_term（事实/经验双库）
        retrieval（BM25+三路混合）· evolution（写/合/忘/抽）
模型层：schema.py（统一数据模型+遗忘模型+溯源）
        llm.py / embeddings.py（Mock ↔ 真模型，依赖注入）
```

- **七步闭环**（记忆系统节律）：①建槽→②查询列表→③检索→④装载→⑤规划输出→⑥AFSIM反馈→⑦复盘进化；
- **MDMP 七阶段**（规划过程节律）：任务分析→方案拟制→…→命令拟制；查询列表按阶段模板滚动生成（P5 落地）。

### 1.3 三个关键设计决策（答辩重点）

1. **双库分治**：事实走"属性精确"（ChatDB 符号路），经验走"语义召回"（向量）——因为两类查询需求互斥（参数错一个数就事故 vs 同义不同词要能召回）；
2. **建议-执行分离**：LLM/规则只提"写什么"，查重/落库/遗忘/抽象由确定性代码执行——保证可回放、可审计（"为什么删这条记忆"能回答）；
3. **复盘晋升**：短期→长期唯一通道是场次复盘 + 三道门（G1 复盘驱动 / G2 类别门 / G3 θ查重），杜绝场次流水账污染长期库。

## 3. 具体实现方案与关键代码解读

### 3.1 数据模型（schema.py）

```python
@dataclass
class MemoryEntry:
    id: str
    type: MemoryType            # fact / experience
    content: str
    source: str                 # 来源（复盘:P001 / seed）—— 可解释溯源
    importance: float           # 遗忘模型 S 初值 + 保护线判据
    decay_strength: float       # 艾宾浩斯 S：每次召回 +1
    recall_count: int
    last_recalled_at: float|None
    merged_from: list           # 进化回放
    op_history: list
    def retention(self, now):   # R = e^(-t/S)，t 单位为天
    def mark_recalled(self):    # S+1、重置 t（间隔效应）
```

**关键代码解读**：
- `retention()` 是遗忘机制的核心：越久不用衰减越快，每次命中强化"巩固"一次；
- `last_recalled_at` 与 `timestamp` 区分"上次使用"与"创建"，支撑间隔效应；
- v0.3 修复过单位失配 bug（秒→天），否则长期记忆 1.2 秒就清光。

### 3.2 三路检索（retrieval/hybrid.py）

```python
def retrieve(self, q, top_k=5, mode="hybrid"):
    # mode="hybrid": 三路并行 → 归一 → 加权融合
    # mode="single": 只执行 q.route（消融 G5 真单路对照）
```

- **vector**：纯向量（事实库 `search_vector`，经验库带重要性加权）；
- **bm25**：Okapi BM25，用 **self_score（查询自匹配得分）** 作归一上界（v0.3 修掉了"池内最大值归一放大单字巧合"的噪声问题）；
- **sql**：`QueryItem.attrs` → `search_attrs` 属性精确过滤；**属性精确命中绕过 min_score**（构造性相关）；
- **min_score**：融合分阈值，默认 0.16（按 50 条测试集负例分布标定）；换 embedding 后必须按 E 噪声研究协议重标定。

### 3.3 记忆进化（evolution/memory_evolution.py）

```python
def evolve_from_review(review_dialogue, session_id):
    ops = llm.extract_memory_ops(review_dialogue)   # 建议侧（可换真模型）
    for op in ops:
        gate = boundary.promote(op["content"])      # G2 门控
        new_id = self.write(mtype, content)          # G3 查重
    # 合并 → 遗忘 → 抽象
```

**关键代码解读**：
- **句子级抽取 + 前缀剥离**（v0.3）：`MockLLM.extract_memory_ops` 按 `。！？` 切句，剥离"复盘："前缀，避免"教训+经验+流水账混装一条"；
- **importance 交互修复**（v0.3）：自动抽取教训 importance=1.5，**不越过保护线 2.0**——否则"所有教训永久免遗忘"导致遗忘机制系统性失效；
- **抽象无指令残留**（v0.3）：`llm.abstract(material, theme)` 单列协议，指令留在实现侧，Mock 为分句拼接、真模型为 LLM 归纳。

### 3.4 工作记忆（short_term/working_memory.py）

```python
def render(self):
    # 【评审修复·关键】装载记忆必须真正进入注入 LLM 的上下文
    if self.slot.loaded_briefs:
        parts.append("【装载记忆】\n" + "\n".join(...))
```

- MemGPT 式：`working_context` 常驻 + `fifo_queue` 滚动 + 70% 预警 / 100% flush；
- 约束字段永不被压缩（`compress()` 只动 FIFO）；
- v0.3 修复了"检索结果从未进入 prompt"的最后一公里断点（此前只登记 id，规划 LLM 看不到记忆正文）。

### 3.5 边界与阶段（boundary.py / stages.py）

- `boundary.promote()`：短期→长期唯一通道（G1/G2/G3），每次决策进 `audit_log()`；
- `controller.write_long_term()`：运行时唯一正规写入入口（v0.3 新增，避免绕过边界）；
- `stages.py`：MDMP 七阶段模板生成查询 + 阶段亲和加分（`stage_bonus=0.15`）+ 复盘教训阶段归因。

### 3.6 真模型接入（llm.py / embeddings.py）

```python

```

- HTTP 走标准库 `urllib`，**零第三方依赖**；`parse_llm_json` 容忍 ```json 围栏/括号平衡/单对象；
- GLM-4.5 系默认禁 thinking（否则抽取 20s+）；指数退避重试（应对 SSL 瞬断）+ embedding 内容缓存。

## 4. 消融实验如何设计

### 4.1 测试集（eval/testset.py，50 条 8 类）

| 类 | 数量 | 目的 |
|---|---|---|
| A 属性精确 | 6 | sql+attrs 参数级召回（ChatDB 路） |
| B 事实语义 | 6 | vector 转述查询 |
| C 经验转述 | 8 | **刻意零/少字面重叠**——语义泛化检验 |
| D 经验词法 | 4 | bm25 路 |
| E 负例 | 12 | 测 min_score 滤噪（旧集完全没有） |
| F 参数干扰 | 4 | T-90(60km/h) vs M1A2(67km/h) 同库——**张冠李戴检验** |
| G 阶段决胜 | 4 | 同内容不同 stage——阶段亲和唯一判别 |
| H 跨场次 | 6 | 场次1复盘→场次2召回（**越用越强量化**，gold 运行期解析） |

**防循环论证设计**：查询与记忆正文刻意不共享关键词（C 类如"黑夜机动吃了什么亏" ↔ "夜间行军未派先遣侦察遭伏击"）；负例与干扰项显式构造。

### 4.2 对照组设计（G0–G6 关键原则）

- **固定用例集**：所有组用同一批用例，**不因配置删用例**（v1 的 G2 跳过经验类用例被评委指出"分母不同"）；
- **依赖注入开关能力**：G2 用**空经验库注入**实现"仅事实库"，而不是改用例；
- **跨场次对照组**：G4 的对照组 = 不跑场次1（gold 不可达应全 miss），处理组 = 跑场次1 复盘进化；
- **单路对照**：G5 用 `mode="single"` 真单路（v1 的 route 只是标签、三路全跑，消融无效——已修复）。

### 4.3 统计方法（eval/stats.py）

- **随机基线**（解析式）`random_hit_at_k`：C(n-g,k)/C(n,k)——防止"全 1.0 但随机也 0.83"的误判；
- **配对置换检验**：同一用例两配置的逐条指标做符号翻转检验（零依赖）获得 p 值；
- **Bootstrap CI**：均值 95% 置信区间（不假设正态）；
- **多组独立 controller**：互不污染，Mock 确定性可复现。

## 5. 消融实验结果

### 5.1 主对照（G0–G3）

| 组 | 配置 | hit@5 | 分类别 C/D/G | 任务层引用率 |
|---|---|---|---|---|
| G0 | 无记忆 | — | — | **0**（无装载） |
| G1 | 仅短期 | — | — | **0** |
| G2 | 仅事实库（空经验库注入） | 0.341 | **0 / 0 / 0** | 0.67 |
| G3 | 双库全开 | **0.636** | **0.63 / 1.0 / 1.0** | 0.75 |

- **双库贡献：Δhit@5=+0.295，配对置换 p=0.0001（n=44）**——最硬的统计结论；
- 随机基线（n=14）：hit@5=0.357——G3 的 0.636 显著高于随机；v1 的"全 1.0"在 n=6 时随机基线 0.833，无判别力（方法论修复的量化证明）；
- F 类参数干扰：hit@5=1.0 且 **干扰压制 1.0**（查 T-90 时 M1A2 恒排后）。

### 5.2 核心主张："越用越强"（G4 跨场次）

| 配置 | H 类 hit@5 | 复用来源 | 负控（无关迁移） |
|---|---|---|---|
| G4（场次1 复盘→场次2 查询） | **0.833** | 平均 0.83 条来自场次1 | 0（渡河教训未混入巷战查询） |
| 对照（无场次1） | 0 | 0 | 0 |

p=0.059（n=5，样本少——如实标注，扩样本是下一步）。

### 5.3 检索策略（G5）——一个诚实的负结果

| 配置 | hit@5 | 干扰压制 |
|---|---|---|
| hybrid | 0.857 | **1.0** |
| vector 单路 | **0.929** | 0.875 |
| bm25 单路 | 0.786 | 0.875 |
| sql 单路 | 0.214（仅 attrs 用例） | 0.375 |

> **解读**：Mock 字符词袋下，hybrid 的 hit@5 不优于 vector 单路（p=0.626），但**排序质量（干扰压制）显著更好（1.0 vs 0.875）**。这不是 bug，而是"词袋没有可融合的语义差异"——**真 embedding 后的 G5 重跑是下一步裁决点**。

### 5.4 专项研究（E/F/C/S）

- **E 噪声**：min_score 扫描 0.05/0.10/0.16/0.25 → 负例返回率 92%/58%/**0%**/0%，正例 hit@5 0.96/0.96/**0.86**/0.82——**0.16 为标定 knee**；
- **F 遗忘**：30 天未召回·未保护(1.5)删 10/10；保护(2.0)删 0；新写入删 0；被删记忆查询命中 0、保护/新记忆 5/5——**无误删**；
- **C 压缩**：truncate 压缩率≈0（早已 auto-flush）；summarize 89.9%（Mock 为截断式拼接，真模型后才有保真含义）；约束保留 True；
- **S 敏感性**：θ=0.6 拦截近重复 100% 且误拦 0%（默认 0.8 拦截 0%——**数据推翻直觉**，待决策）。

### 6.3 ⚠️ API 接入验证实况（2026-09 本次实测）

| 项目 | 结果 |
|---|---|

- **你需要现在做的事**：登录 [bigmodel.cn](https://open.bigmodel.cn) → API Keys → 创建/恢复一个有效 Key → 更新仓库根 `.env` 的 `GLM_API_KEY` → 重跑：
```bash

```
- **历史有效证据仍在**：`eval/results/llm_verification.json` 记录了 v0.4 首次接入时 23/23 通过的结果（T6 引用率 1.00、T7 语义分离 0.63），答辩可引用"接入已通过验证"，但**现场演示前必须用新 Key 重新验证一次**。

### 6.4 接入后必做（真模型消融重跑）

1. min_score 按 E 噪声协议重标定（GLM embedding 探针：负例 top1 max=0.139、正例 min=0.238 → 建议 0.18–0.20）；
2. θ 按 S 扫描重定（Mock 数据支持 0.6）；
3. `python -m eval.ablation` 真模型重跑，裁决三个"不可外推项"（C 类转述、G5 混合增益、任务层引用率）。
