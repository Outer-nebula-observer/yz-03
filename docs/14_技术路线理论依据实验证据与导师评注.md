## 一、技术路线详解

### 1.1 总体架构：两层四模块 + 双循环

```
┌────────────────────────────────────────────────────────────┐
│ 编排层  pipeline.py（七步闭环）· controller.py（总调度）        │
├────────────────────────────────────────────────────────────┤
│ 跨切面  boundary.py（长短期边界/三道门/审计）· stages.py（MDMP） │
├────────────────────────────────────────────────────────────┤
│ 能力层（四个模块互不 import，只经 schema 数据对象交互）           │
│   short_term/   工作记忆：槽位 + FIFO + 阈值换页 + 压缩三档      │
│   long_term/    事实库(SQLite/精确) + 经验库(向量/语义)         │
│   retrieval/    BM25 + 三路混合/单路检索 + 阶段亲和             │
│   evolution/    写入(查重) / 合并 / 遗忘(艾宾浩斯) / 抽象        │
├────────────────────────────────────────────────────────────┤
│ 模型层  schema.py（统一数据模型 + 遗忘模型 + 溯源）              │
│         llm.py / embeddings.py（Mock ↔ 真模型，依赖注入）       │
└────────────────────────────────────────────────────────────┘
```

**三条铁律**（代码注释里的契约，`memsys/long_term/base.py`）：
1. **检索只读、进化只写**——独立评测互不污染；
2. **依赖注入**——`MemoryController(llm=?, embedding=?, ...)` 全可替换，Mock/真模型业务代码零改动；
3. **数据模型单一事实源**——一切改动从 `schema.py` 出发。

**双循环**：
- **七步闭环**（记忆系统节律）：① 规划建槽 → ② 查询列表 → ③ 检索 → ④ 装载 → ⑤ 规划输出 → ⑥ AFSIM 反馈 → ⑦ 复盘进化；
- **MDMP 七阶段**（规划过程节律）：受领任务 → 任务分析 → 方案拟制 → 方案推演 → 方案比较 → 定下决心 → 命令拟制。**交汇点**：查询列表由阶段模板生成（P5 老师意见的落地）。

### 1.2 长短期边界：两把尺子 + 三道门

- **两把尺子**（认知科学判断，写进类型系统）：来源（任务内/跨任务）+ 时间尺度（场次周期/持久）；
- **三道门**（短期→长期唯一通道=复盘晋升）：
  - G1 复盘驱动：只有 close_session 的复盘材料可晋升；
  - G2 类别模板（Mock）/LLM 分类（真模型）：纯场次流水账被拒；
  - G3 θ 查重：与库内内容相似度超过阈值即跳过（PREMem 链接对思想）；
- **双向禁止**：短期→长期必须走 promote（controller.write_long_term 是运行时唯一正规入口）；长期→短期只能以检索结果形态进入（validate_load）。

### 1.3 双库分治：为什么分家

| 库 | 载什么 | 最怕什么 | 因此用什么 |
|---|---|---|---|
| 事实库 Factual | 装备参数/条令/地形（"是什么"） | 召回"差不多"的错数（T-90 60km/h vs M1A2 67km/h） | SQLite 行存 + attrs 属性精确过滤 + 向量辅助 |
| 经验库 Experiential | 成败教训/对策（"怎么做"） | 字面不同漏召回（"夜战吃亏"查不到"夜间遭伏击"） | 向量语义召回 + 重要性加权 + SQLite 持久化 |

认知科学对应：陈述性记忆 vs 程序性记忆。

### 1.4 三路检索：hybrid / single 双模式

- **vector 路**：纯向量（事实库 `search_vector` 不含 LIKE 兜底；经验库带重要性加权）；
- **bm25 路**：Okapi BM25，自匹配得分 `self_score` 作归一上界（v0.3 防单字巧合放大噪声）；
- **sql 路**：`QueryItem.attrs` → `search_attrs` 属性精确过滤（ChatDB 符号路）；无 attrs 时退化 LIKE（兜底）；**属性精确命中绕过 min_score**（构造性相关）；
- **`mode="hybrid"`**：三路并行 → 归一（裁剪余弦 / bm25÷self_score / sql=1）→ 加权融合（α=0.5, β=0.3, γ=0.2）→ 阶段亲和 → min_score；
- **`mode="single"`**：只执行指定路（权重=1），是消融 G5 真单路对照的基础。

### 1.5 记忆进化：LLM 建议 × 代码执行

```
复盘文本 ──LLM/Mock──► 操作建议 [{op:write, type, content, importance}]
        ──代码执行──► G2门控 → G3查重 → 写入(带阶段归因) → 合并 → 遗忘 → 抽象
```

- **写入**：PREMem θ 查重（θ=0.80 默认；敏感性扫描显示 Mock 下 0.6 更优——待决策项）；
- **合并**：同簇相似条目 → 一条（`merged_from` 溯源）；
- **遗忘**：艾宾浩斯 `R=e^(-t/S)`，命中强化 S+1；`importance≥2.0` 永不遗忘（**保护线**）；
- **抽象**：≥2 条经验 → 一条通用教训（`llm.abstract`，指令留在实现侧，无残留）。

### 1.6 阶段感知（MDMP 七阶段驱动）

三层：① 按阶段模板生成查询（`stages.py`）；② 检索时**阶段亲和加分**（`stage_bonus=0.15`，对口记忆优先）；③ 复盘教训按关键词归因到阶段（`attr_stage`）——下场同阶段优先召回。理论根基：MIRIX 路由思想的阶段化扩展 + 事件分段理论。

### 1.7 真模型接入（v0.4）

- `GLMClient`：bigmodel.cn OpenAI 兼容，stdlib urllib 零依赖；thinking 控制、重试、`parse_llm_json` 围栏容错；
- `GLMEmbedding`：embedding-2（dim=1024），重试 + 内容缓存；
- Prompt 强化：importance 分级约定（2.0=永不遗忘，慎用）+ content 保留"教训：/经验："前缀（配合 G2 门控与归因）。

## 三、实验结果支撑：证据链分级

### 3.1 结构正确性证据（Mock 消融 v2，50 条测试集，可复现）

| 主张 | 证据 | 强度 |
|---|---|---|
| 双库分治有贡献 | G3 vs G2：Δhit@5=+0.295，**配对置换 p=0.0001**（n=44）；经验类查询 C/D/G 在空经验库下全 miss | ★★★★ |
| 越用越强（跨场次复用） | G4：hit@5=**0.83** vs 对照（无场次1）**0**；从场次1 复用的命中 0.83；无关迁移负控=0 | ★★★★ |
| 参数级精确/不张冠李戴 | F 类干扰 4 条：hit@5=1.0 且**干扰压制 1.0**（查 T-90 时 M1A2 恒排后） | ★★★★ |
| 负例滤噪 | E 类 12 条：min_score=0.16 下**返回率 0%**（旧实现 58%——BM25 归一 bug 已修） | ★★★★ |
| 阶段亲和机制 | G6 决胜对：bonus 开=干扰压制 1.0 / 关=0（n=4，p=0.127 功效有限） | ★★★ |
| 遗忘保护线与误删 | 30 天未召回·未保护(1.5)删 10/10；保护(2.0)删 0；新写入删 0；**无误删**（被删查询命中 0、保护/新记忆 5/5） | ★★★★ |
| 任务层有装载记忆 | G0/G1 引用率=0 vs G3=0.75（Mock 口径=上下文构造正确性） | ★★★（Mock 语义） |

**随机基线对照**（解析式）：单 gold hit@5=0.357（n=14）——G3 的 0.636 显著高于随机；**v1 的"全 1.0"在 n=6 时随机基线 0.833，无判别力**（这是消融 v2 方法论价值）。

### 3.2 真模型证据（GLM，`python -m eval.verify_llm` 23/23）

| 项 | 结果 | 意义 |
|---|---|---|
| 抽取 | GLM 识别出 Mock 关键词盲区的 **fact**；importance 有区分度、无 2.0 滥用、无标记残留 | 抽取"质变"量化 |
| 抽象 | 29~34 字通用教训、**零指令残留** | 修复后的最终确认 |
| 进化端到端 | write=2 + abstract=1；经验库无指令/JSON 残留 | 真模型抽取×检索闭环可用 |
| **规划任务层** | **宽松记忆引用率 1.00**；输出含"仅东侧可装甲通行""避免重蹈覆辙…的教训"；约束满足≥0.5 | **Mock 无法度量的"LLM 善用记忆"** |
| embedding | 语义分离 Δ=0.63（同义 0.82 / 无关 0.19） | 真语义能力 |
| 稳定性 | SSL 瞬断偶发 → 已内置重试（chat/embed 均 3 次退避）+ 缓存 | 生产可靠性 |

### 3.3 诚实边界 / 负结果（这些不是失败，是证据的一部分）

1. **G5 Mock 负结果**：hybrid hit@5（0.857）不优于 vector 单路（0.929，p=0.626）——但 hybrid 干扰压制 1.0 优于单路 0.875。**含义**：字符词袋没有可融合的语义差异，混合增益须真 embedding 裁决（这是消融 v2 的主要待做项之一）；
2. **C 类转述命中在 Mock 下只是"判别性单字"**（0.63），真语义泛化待真 embedding 重跑；
3. **任务层引用率在 Mock 下度量的是"上下文构造正确"**（回显），真模型后才度量"LLM 善用记忆"（已验证 T6）；
4. **θ 数据推翻直觉**：Mock 下 0.6 优于默认 0.8（拦截 100% vs 0%）——待决策项；
5. min_score=0.16 是 Mock 标定值；GLM embedding 探针显示负例 top1 max=0.139（边际仅 0.02）→ **建议重标定 0.18–0.20**。

## 四、导师评价（站在导师视角）

### 4.1 值得肯定之处

1. **方法论自觉**：项目罕见地把"如何证明"放在与"如何实现"同等位置——随机基线、配对置换检验、负控、诚实负结果，这些是研究生论文级的标准；
2. **架构可测试性**：依赖注入 + Mock/真模型双实现 + 检索只读/进化只写，使"离线可验证"成为可能，也让消融成为一等公民；
3. **文献工作的扎实度**：21 篇精读笔记 + "每模块一主论文 + 明确不借什么"的反杂糅论证，远超课程平均水平；
4. **自我修正能力**：评审→修复→回归的闭环，尤其"数据推翻直觉"（θ、BM25 归一、遗忘保护线交互）这类 finding，本身就是研究价值的体现；
5. **工程诚信**：诚实边界声明、负结果如实报告——这是很多高年级学生都做不到的。

### 4.2 主要不足（按严重度）

| # | 不足 | 说明 |
|---|---|---|
| 1 | **核心主张的最终证据未闭环** | "记忆让规划变强"还需：真 embedding 消融重跑 + 20 场次 Scaling 曲线。当前"结构正确"证据充分，但"效果"证据只有 1 个 T6 样例（虽强但不系统） |
| 2 | **机制级原创点证据偏薄** | 阶段亲和（G6 n=4）、跨场次（G4 p=0.059）受样本量限制——不是机制有问题，是数据不足以支撑强结论 |
| 3 | **知识的来源可信度/冲突管理缺失** | importance 是静态的；错误教训一旦被标 2.0 就"永生"；矛盾经验共存无仲裁——这是记忆系统从"能存"到"可信"的必经之路 |
| 4 | **知识锚定承诺未兑现** | docs/04 §1.2 声称"长期记忆受知识锚定约束"，但入库前无权威库比对——涉及课程"防编造"主线 |
| 5 | **工程化缺环** | 无并发/流式、WebUI 单进程内存、BM25 全量重建、无批量 embedding——服务化前的必要项 |
| 6 | **文档与实现有小幅漂移风险** | 多轮快速迭代后部分老文档（如 docs/04 早期表述）仍可能残留旧描述，建议交付前做一次"文档-代码对照审查" |

### 4.3 风险提示

- **时间风险**：课程窗口有限，P0 三项（消融重跑/重标定/智戎链路）应优先于任何"新机制"探索；
- **API 依赖风险**：GLM 额度/稳定性不可控——Mock 路径必须永远可回退（当前已满足）；
- **密钥风险**：密钥曾在对话中暴露，务必在课程结束后轮换；
- **过度承诺风险**：答辩时把"已证实"与"待验证"分开讲——导师最反感混为一谈。

### 6.3 关键代码摘录精读（三处最值得讲给别人的设计）

**① 装载记忆真正进入上下文（v0.3 关键修复）**——`working_memory.py::render`：
```python
# 【评审修复·关键】检索命中的事实/教训必须真正出现在注入规划 LLM 的
# 上下文里（放在约束之后——头部关键区，LongLLMLingua 位置偏置）。
if self.slot.loaded_briefs:
    lines = [f"· {brief}" for brief in self.slot.loaded_briefs.values()]
    parts.append("【装载记忆】\\n" + "\\n".join(lines))
```
> 配套：`controller.retrieve_and_load` 在 `load_memory(id, brief=...)` 时把内容摘要写进 `loaded_briefs`；`controller` 还做了跨查询去重。

**② 单路模式与融合权重解耦（G5 消融的口径基础）**——`hybrid.py::retrieve`：
```python
if mode == "single":
    weights = {"vector": 1.0, "bm25": 1.0, "sql": 1.0}
else:
    weights = {"vector": self.alpha, "bm25": self.beta, "sql": self.gamma}
```
> 动机：单路模式下若仍用加权（sql 0.2×1.0=0.2），就会恒低于 min_score=0.35，单路对比失真。

**③ 遗忘保护线 × 抽取规则的交互修复**——`llm.py::MockLLM.extract_memory_ops`：
```python
"importance": (1.5 if any(k in sent for k in ("失败", "教训"))
               else 1.0),
```
> 动机：原实现给所有"教训"打 2.0=保护线 → 遗忘机制系统性失效、经验库无界增长。改 1.5 后，普通复盘教训仍会被遗忘淘汰；2.0 只留给显式标注/抽象产物（max+0.5 越线）——抽象产物天生的"更重要"语义由此体现。
