# 技术路线：长短期记忆系统（赛题③）

> **课题**：异构多模态数据环境下大模型作战规划智能体记忆系统构建
> **基础平台**：「智戎」大小模型协同作战规划系统
> **配套**：文献依据见 `references/组会汇报_模型记忆体系综述.md` 与 `references/记忆系统核心要点提炼.md`；代码实证见 `paper_code/`（14 个仓库已 clone，路径在文中标注）；文献与代码导览见 `docs/06_文献与思路梳理_结合代码.md`。

## 0. 目标与验收底线

**目标**：为"智戎"作战规划智能体构建**可演化的外部记忆系统**——短期工作记忆支撑"当前规划上下文与中间结果"，长期记忆沉淀"跨任务的事实与经验"，靠**检索**按需供给、靠**记忆进化**完成写入/合并/遗忘/抽象，使规划随推演场次持续变强。

**验收底线（保底）**：端到端链路跑通；短期记忆能装载+压缩；长期记忆 ≥100 条、分事实/经验两类；任务感知检索 Recall@5 达标；进化演示写入/合并/遗忘/抽象 ≥3 类；智戎链路一处真实调用；按指标给 ≥5 组消融结论。

## 1. 系统总体架构

```
智戎规划管线（启动→分析→生成→分析→比较→批准→指令）
        │ ①规划：意图理解·任务分解 → 生成查询列表 Q=[q1..qn]
        ▼
┌──────────────────────────────────────────────┐
│ ② 检索（任务感知查询 → 记忆库 → 返回 m_t）        │
│   · 短期：当前场次上下文/中间结果/约束            │
│   · 长期：事实记忆 + 经验记忆                    │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ ③ 长期/短期记忆                                  │
│   · 短期工作记忆：m_t 装载进上下文（必要时压缩）    │
│   · 长期记忆：规划结束后触发记忆进化             │
│     （写入/合并/遗忘/抽象）                       │
└──────────────┬───────────────────────────────┘
               ▼
   AFSIM 对抗推演 → 结果评估 → ④反馈：沉淀为新经验
```

**七步闭环**：①规划→②查询列表→③检索→④长期/短期装载→⑤规划输出→⑥AFSIM反馈→⑦记忆进化。把讲义"记忆形成/检索/进化"三段式落成可演示、可评测的闭环。

## 2. 分模块技术路线与代码实证

### 2.1 短期 / 工作记忆层

| 项 | 选型 | 代码实证（paper_code/） |
|---|---|---|
| 组织范式 | **MemGPT 式分层**（working context + FIFO queue + 阈值驱动归档） | `01_短期记忆/MemGPT/`（注：此仓库现为 Letta landing page，实现见 `letta-ai/letta-code` 或 `archive` 分支） |
| 调度控制器 | **SCM 记忆控制器**决定"何时写/读" | `04_记忆进化/SCM4LLMs/core/chat.py`（对话核心）、`core/cfg.py`（配置）、入口 `dialogue_demo.py` |
| 上下文压缩 | 截断/摘要（MVP）→ **LLMLingua 式删 token** | `01_短期记忆/LLMLingua/llmlingua/prompt_compressor.py`（`PromptCompressor` 类，已入 LangChain/LlamaIndex） |
| 进阶压缩 | LongLLMLingua（问题感知+子序列恢复）/ ICAE（可学习槽位） | 同 `LLMLingua` 仓库；ICAE 未 clone |

**MVP 实现**：槽位式工作记忆（`{plan_id, goal, constraints, query_list, loaded_memory, intermediate_results, status}`）+ 长度截断/摘要压缩；把 LLMLingua 的 `PromptCompressor` 作为消融对照组。

**验证点**：上下文超限能自动压缩；压缩后关键约束保留；符合"容量受限+主动操纵"认知定义。

### 2.2 长期记忆层（事实 + 经验双库）

| 子类 | 存储形态 | 代码实证 |
|---|---|---|
| **事实记忆**（参数/条令/战例客观信息） | SQLite 表 + NL→SQL（ChatDB 式精确）→ 进阶 **Zep 时序知识图谱** | `02_长期记忆/graphiti/`（Graphiti 引擎，含 Docker、`docker-compose.yml`）；ChatDB 仅项目主页 |
| **事实·摘要式**（对话/事件摘要+画像） | DPR 双塔 + FAISS + 艾宾浩斯遗忘 | `02_长期记忆/MemoryBank-SiliconFriend/memory_bank/`、`eval_data/` |
| **经验记忆**（成败教训） | 语言反思 + 情景记忆缓冲（Reflexion 式） | Reflexion 未 clone（`noahshinn024/reflexion`，可用 `--only Reflexion` 补下） |
| **经验·向量库**（相似成功轨迹召回） | Faiss Top-K + 提炼 insights | `03_记忆检索/ExpeL/memory/episode.py`（轨迹存储）、`agent/{expel,reflect}.py`、`insight_extraction.py` |
| **经验·程序性**（"怎么做"步骤/脚本） | Build/Retrieve/Update 三策略 | `02_长期记忆/MemP/ProcedureMem/`、`requirements.txt` |
| **对话长期记忆** | 片段→结构化 memo（主题键+摘要） | `02_长期记忆/MemoChat/{code,data,model}/` |

**选型建议**：事实走"结构化表/图谱"（精确召回），经验走"摘要+向量"（语义召回）；底层"向量库 + SQLite/图"双存储。

**验证点**：事实能精确召回（参数级）；经验能在相似新任务被激活并**改变规划行为**。

### 2.3 记忆检索（任务感知）

| 范式 | 代表 | 代码实证 |
|---|---|---|
| 向量 Top-K | ExpeL | `03_记忆检索/ExpeL/`（Faiss + `memory/episode.py`） |
| 符号 SQL | ChatDB | 仅项目主页 |
| 时序知识图谱 | Zep/Graphiti | `02_长期记忆/graphiti/`（三层图 episode/semantic/community + 双时态） |
| 多策略路由 | MIRIX（embedding/BM25/string） | `03_记忆检索/MIRIX/mirix/`、`main.py`、`public_evaluations/` |
| 可学习构建 | Mem-α（RL 训记忆工具选择） | `03_记忆检索/Mem-alpha/functions.py`（记忆工具 OpenAI tool schema）、`memory.py`、`memory_server.py`、`main.py` |

**MVP**：**混合检索**（向量+BM25+SQL）打底 + "查询列表→分路检索"编排；RMM 式反思精化进阶。

**关键代码可复用**：Mem-α 的 `functions.py` 把记忆操作封装成 **OpenAI tool schema** 让 LLM 调用——这套"工具化记忆操作"接口设计可直接借鉴做我们的记忆操作 API。

### 2.4 记忆进化（写入/合并/遗忘/抽象）——创新重点

| 操作 | 实现 | 代码实证 |
|---|---|---|
| 写入 | TiM insert / SCM 控制器 / MemGPT 自主函数 | `04_记忆进化/SCM4LLMs/core/`；TiM（`--only TiM` 补下） |
| 合并去重 | PREMem 链接对 θ=0.6 / Memp Add⊖Del⊕Update | `04_记忆进化/PREMem/src/`、`prompts/`、`script/` |
| 遗忘 | 艾宾浩斯 R=e^(-t/S) / 时间衰减 | `MemoryBank-SiliconFriend/memory_bank/` |
| 抽象 | TiM Post-thinking / StructMem 周期语义整合 | `04_记忆进化/LightMem/`（`StructMem.md` + `src/` + `experiments/`） |
| **可学习操作**（创新点 A） | MemSkill：控制器选技能+执行器生成+设计师进化 | `04_记忆进化/MemSkill/main.py`（`src/trainer`、`src/memory_bank`、`src/executor`、`rag_utils.py`、`prompts/prompt_pool.py`） |

**MVP**：规则+LLM 摘要实现四操作（TiM 范式）；**进阶创新点 A**：PREMem 式"写入时预存储推理" + MemSkill 式"可学习记忆操作"。

**关键洞察**：MemSkill 的 skills 是**元记忆（meta-memory）**——"记什么、怎么记、保什么、忘什么"的方法，而非记忆内容本身。这正好对应赛题"操作策略可消融"的设计。

## 4. 评估方案

**指标**（复用 `docs/03` 第 20 节）：
- 检索质量：Hit Rate / MRR / NDCG@K / Recall@K（分短期/长期、分事实/经验）；
- 有效性：结果正确性 Accuracy、引用准确性 F1；
- 生成质量：上下文相关性/答案忠实度/答案相关性；
- 效率：时间开销 Δt、峰值 GPU 显存；
- 记忆维度：工作/情景/语义/事实/经验、任务内 vs 跨任务。

**基准**（标准 + 自建）：
- 标准：**LoCoMo / LongMemEval / DMR**（对话/时序，论文多用）+ MemBench/MemoryAgentBench（功能 agent）；
- 自建：≥40 条"跨场次经验复用"+"事实召回"作战问题，每条标 relevant memory + gold answer + 任务内/跨任务标签。
- 现成可复用评测：`03_记忆检索/Mem-alpha/evaluate_agent_results.py`、`MemSkill/eval_locomo.sh`、`eval_longmemeval.sh`、`MIRIX/public_evaluations/`。

**消融 G0–G5**：

| 组 | 配置 | 验证 |
|---|---|---|
| G0 | 无记忆（纯 LLM 规划） | 基线 |
| G1 | 仅短期工作记忆 | 短期贡献 |
| G2 | G2 + 长期事实记忆 | 事实贡献 |
| G3 | G3 + 经验记忆 | 经验贡献 |
| G4 | G4 + 记忆进化（合并/遗忘/抽象） | 进化贡献 |
| G5 | G4 + 检索策略对比（向量/SQL/混合/反思精化） | 检索贡献 |

## 5. 里程碑与风险

| 里程碑 | 交付物 | 通过标准 |
|---|---|---|
| M0 | 代码包盘点+缺口清单 | 跑通基线，明确四块各补什么 |
| M1 | 短期记忆 MVP | 单场次上下文装载+压缩+查询列表可用 |
| M2 | 长期记忆+检索 | 事实/经验双库建成，任务感知检索召回达标 |
| M3 | 记忆进化闭环 | 写/合并/遗忘/抽象四操作可演示可回放 |
| M4 | 评估+集成 | 6 组消融 + 智戎链路一处真实调用 |
| M5 | 四件套 | 论文/代码/演示视频/答辩 PPT |

**风险预案**：代码包与长短期记忆无关→复用其检索/存储组件，三层自建；进化做不完→先保"写入+合并去重"，遗忘降级为时间衰减规则；遗忘难量化→改用"存储规模 vs 检索精度"与"时间敏感问题命中率"；经验召回差→改走"摘要+检索+反思精化"，必要时人工写 20 条种子经验；压缩破坏约束→关键约束打"不可压缩"标记。

## 6. 避坑要点

1. 别把"长期记忆"做成又一个**静态 RAG 库**——核心差异在"进化/更新/遗忘"，务必可演示可量化；
2. 短期与长期边界清晰：来源（任务内 vs 跨任务）+ 时间尺度两把尺子；
3. **检索与进化解耦**：检索只读、进化只写，独立评测防互相污染；
4. **遗忘必须有依据**：时间衰减/重要性打分/冲突检测三选一，给量化证据；
5. 经验记忆要"能改变行为"——验证标准不是"召回了"而是"召回后规划输出真的变了"；
6. **知识锚定同样约束长期记忆**——外部经验/幻觉混入会让"防编造"防线失效。

## 7. 执行摘要

我们给智戎规划智能体做**可演化的外部记忆**。架构是七步闭环：规划→查询列表→检索→短期/长期装载→规划输出→AFSIM反馈→记忆进化。短期用 **MemGPT 分层范式**（working context + FIFO queue + 阈值归档），压缩用 **LLMLingua**（现成 `PromptCompressor` 类）；长期分**事实**（SQLite + NL→SQL，进阶 **Zep 时序图谱**）和**经验**（**ExpeL** 的 Faiss 召回 + Reflexion 语言反思 + **Memp** 程序性记忆）；检索做**混合**（向量 + BM25 + SQL）+ 查询列表分路；进化做四操作（TiM 范式），创新点是 **PREMem 预存储推理 + MemSkill 可学习操作**。评估用 LoCoMo / LongMemEval + 自建作战测试集，做 **G0–G5 六组消融**。创新主攻 A（进化链路）+ C（查询列表显式化）+ E（可解释溯源）。关键代码均已 clone 到 `paper_code/`：`03_记忆检索/ExpeL`、`03_记忆检索/Mem-alpha`、`04_记忆进化/MemSkill`、`04_记忆进化/SCM4LLMs`、`01_短期记忆/LLMLingua`、`02_长期记忆/graphiti` 等 14 个，可直接复用其接口设计（尤其 Mem-α 的记忆工具 tool-schema）。
