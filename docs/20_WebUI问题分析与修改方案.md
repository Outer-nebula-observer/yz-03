# 20 WebUI 问题分析与修改方案

> **范围**：`webui/`（server.py 982 行、app.js 995 行、index.html 254 行、style.css 344 行，21 个 API 路由，约 63 个前端函数）。
> **目的**：从架构、功能、交互、性能、安全、可维护性、一致性 7 个层面系统盘点问题，并按优先级给出可执行的修改方案。

---

## 0. 现状快照

| 指标 | 数量 | 信号 |
|---|---|---|
| server.py | 982 行 | 单文件承载全部后端逻辑，偏大 |
| app.js | 995 行 | 单文件 + 手写 DOM，无模块化 |
| API 路由 | 21 个 | 数量可接受，但没有分组/版本化 |
| 前端函数 | 63 个 | 全局函数 + 依赖 DOM id，耦合重 |
| 测试覆盖 | 66 项 API 自测 | 多为“能返回/能通过”，前端交互无自动化测试 |

---

## 1. 架构层面

### 1.1 后端单文件、无分层

- `server.py` 把 HTTP 层、全局状态、业务逻辑（检索、场次、战役、遗忘）、数据组装全放在一个文件；`Handler` 路由表 + 模块级 `STATE` 全局单例。
- **问题**：难以单独测试业务逻辑；新端点容易“哪里顺手插哪里”，函数间隐式依赖（`STATE`、`hit_dict`、`report_dict` 等全局符号）。
- **修改方案**：
  1. 拆成 `webui/state.py`（AppState + 数据组装）、`webui/api.py`（各端点函数）、`webui/server.py`（仅 HTTP 路由）；
  2. 为所有 session 条目定义 dataclass `SessionRecord`（不再用裸 dict，杜绝漏字段）；
  3. 路由表迁移到显式 `routes: list[tuple[method, path, handler]]`，支持后续分组/版本前缀 `/api/v1/`。

### 1.2 前端单文件、无状态管理

- `app.js` 995 行全部是全局函数 + 直接读写 DOM id；`lastSessions / lastMemItems / selectedMemId / curTab / campaignOptions` 等散落全局变量。
- **问题**：状态与 DOM 双向手工同步，改动一处容易漏；多面板（页签/抽屉/曲线/详情）数据互相引用时难以追踪。
- **修改方案**：
  1. 引入一个极简状态对象 `const UI = {sessions:[], memories:{fact:[],experience:[]}, ...}`，所有渲染函数从 `UI` 读取、由 `refreshAll()` 统一写；
  2. 把渲染按“区域”拆成独立模块文件（`ui/events.js`、`ui/memories.js`、`ui/drawer.js`…），用 `<script type="module">` 或打包；
  3. 前期不引入框架，保持零构建；用模块化即可大幅提升可读性。

### 1.3 前后端契约隐式

- 前端直接踩 21 个端点、依赖返回字段；后端没有独立 schema/文档，改字段前端不会报错只会“神秘失效”。
- **修改方案**：为关键响应写一个 `docs/api.md`（或 OpenAPI yaml），并在 `_selftest` 里增加“字段存在性”断言（已有部分，可扩展为契约测试）。

## 2. 功能与数据层面

### 2.1 运行数据不持久化

- 场次历史、事件流、遗忘日志均在内存，刷新/重启即失；只有长期记忆库可落盘（且默认内存）。
- **影响**：答辩演示一旦刷新，历史轨迹丢失；遗忘日志无法跨进程审计。
- **修改方案**：
  1. 新增 SQLite `ui_state.db`（表：sessions、events、forgotten_log），`webui` 默认启用（可 `--memory` 禁用）；
  2. AppState 写操作同步落盘（低频，量小）；启动时加载最近 N 条；
  3. 或至少把“场次历史 + 事件流 + 遗忘日志”导出 JSON（按钮），作为演示快照。

### 2.2 事件流有上限、信息回流不够

- 事件流最多 300 条截断；场次详情的 `retrieved` 在手动多次检索时被覆盖，而不是“每轮检索都留存”。
- **修改方案**：
  1. 场次内 `retrieved` 改为数组的数组（`retrieve_rounds`），每次检索追加一轮；
  2. 事件流上限提高到 1000 并按场次分组折叠（已有场次详情，可让“旧场次”默认折叠）；
  3. 场次详情增加“每次检索快照”列表。

### 2.3 遗忘日志与记忆库不对齐展示

- 遗忘日志是全局列表，不能从“某场次/某来源”筛选；场次详情里看不到本场被遗忘的是哪些。
- **修改方案**：`forgotten_log` 条目增加 `session_id`/`source`（已部分有），场次详情里展示“本场相关遗忘”；抽屉遗忘日志增加筛选输入。

### 2.4 WebUI 与实验体系脱节

- 消融/评估结果只在 CLI；WebUI 不展示测试集得分、检索指标、真模型验证状态。
- **修改方案**：新增“评估”页签，读取 `eval/results/*.json`（或新增 `/api/health` 汇总：库规模、受保护数、低于遗忘线数、最近遗忘、最后自检结果），一屏看清系统状态——这也正好承接“可视化进度”需求。

## 3. 交互与可用性层面

### 3.1 破坏性操作无确认

- `清空重置`、`模拟老化+遗忘` 都会真实删除记忆/数据，但没有二次确认。
- **修改方案**：为破坏性按钮统一 `confirm()`（或弹层）；`apiForgetDemo` 默认 `days` 提供下拉，并在执行前显示将受影响记忆数。

### 3.2 错误/加载反馈弱

- footer `#err` 不显眼且会被覆盖；真模型调用可能耗时几十秒，无 loading 指示，用户以为卡死。
- **修改方案**：
  1. 新增顶部 toast（`showToast(msg, type)`，3 秒自动消失）；
  2. 为所有异步按钮加 `disabled + “处理中…”`，用 `withLoading(fn)` 包装；
  3. 真模型生成时显示进度提示（“DeepSeek 生成中，约 5~30s”）。

### 3.3 操作路径/新手引导缺失

- 不知道先开“场景·战役”还是“操作台”；页签切换后状态容易断（比如导入战役后在“场景·战役”，但阶段按钮在“操作台”）。
- **修改方案**：
  1. “一键导入”后自动切到“操作台”页签并高亮“下一场”按钮；
  2. 提供“演示向导”步骤条（开箱→导入→下一场→查看详情→看遗忘）作为可选 overlay；
  3. 关键操作失败时 toast 提示“先在操作台开场”。

### 3.4 窄屏/可访问性

- 三栏布局在窄屏下挤；抽屉可用但无 `aria` 焦点管理；按钮无 `title`。
- **修改方案**：加 `@media (max-width: 900px)` 改为单列；抽屉加 `role="dialog"`、`aria-modal`、Esc 关闭、焦点圈闭；按钮加 `title`。

## 4. 性能层面

### 4.1 全量刷新无缓存、重绘频繁

- 每次操作 `refreshAll()` 串行请求 7 个端点并全量重绘 `innerHTML`；记忆库大时（几百条）会卡顿，事件流也全量重绘。
- **修改方案**：
  1. 为 memory/events/sessions 增加 `lastFetch` 与内容指纹（如简单 `JSON.stringify` 长度），仅当变化才重绘；
  2. 记忆列表前端分页/虚拟滚动（每页 50 条，滚动加载）；
  3. 事件流只增量 append 新事件（服务端加 `since` 参数）；
  4. 页面右上角显示“上次刷新耗时”，帮助观察。

### 4.2 检索无缓存、真模型慢

- WebUI 每次搜索都走完整检索（可能触发 embedding API）；真模型生成在 server 线程同步阻塞。
- **修改方案**：
  1. 后端为“相同 query + 库 version”加简单结果缓存（LRU，如 64 条）；
  2. 真模型调用如果超时（如 >30s），前端允许“取消生成”并降级 Mock。

## 5. 安全层面

### 5.1 无鉴权

- `--host 0.0.0.0` 时任何局域网用户可重置/删除/查看记忆库。
- **修改方案**：
  1. 默认保持 `127.0.0.1`；若需局域网，增加可选 `WEBUI_TOKEN`，简单 Bearer 校验；
  2. 破坏性端点（reset/forget）在 token 模式下要求确认 token。

### 5.2 XSS 审计

- `innerHTML` 较多，虽然大多先 `esc()`，但 `md()` 只转义后替换 `**`；仍需系统审计任何 `innerHTML` 拼接是否都经过 `esc`。
- **修改方案**：写一个小脚本 grep `innerHTML`，逐个核对是否调用了 `esc`；给 `md()` 增加对 `<` `>` 的强转义（当前 `esc` 已做）。禁止把未清洗的用户输入（goal/messages/review）直接放进 `innerHTML`。

### 5.3 数据隐私

- 记忆内容可能含敏感作战信息；WebUI 无访问控制。同上 token 方案。

## 6. 可维护性 / 工程层面

### 6.1 无前端自动化测试

- `_selftest` 只覆盖 HTTP API，不覆盖页面交互（点按钮、展开详情、页签切换）。
- **修改方案**：引入轻量端到端测试（Playwright 可选）或至少补充“纯函数测试”（`md`、`sessionDetailHtml`、字段契约）用 Node 直接跑；把 `md()` 等纯函数提取出来可测。

### 6.2 代码风格一致性与后端“裸 dict”

- 后端 session 是 dict，缺字段编译期不报错；前端手写 HTML 拼接难读。
- **修改方案**：
  1. 后端 dataclass（见 1.1）；
  2. 前端模板用模板字符串 + 小工具函数（`el()`/`tag()`）减少重复；写一个简单的 `html` 安全标签函数。

### 6.3 接口无版本化/文档

- 21 个端点无版本；自测无契约字段断言。
- **修改方案**：路由前缀统一 `/api/v1/`（保留旧路由兼容一个版本）；`docs/api.md` 记录请求/响应示例。

## 7. 一致性与正确性层面

- **多轮状态机脆弱**：手动开场与战役导入共用同一 `STATsE`，切换无提示，可能“有未关闭场次”报错。
  - 方案：导入战役前若存在未关闭场次，先提示并自动收尾/拒绝。
- **页签/抽屉/曲线各自持有内存态**：刷新后丢失且可能不一致（如 selectedMemId 指向已遗忘条目）。
  - 方案：统一 UI 状态对象（见 1.2），刷新后重算/清空失效选择。
- **健康条仅当前库类型**：用户可能误以为是全库统计。
  - 方案：健康条展示“事实+经验”合并统计，或明确标注“当前库”。
- **遗忘曲线与抽屉重复**：两条路径展示相似信息。
  - 方案：抽屉作为唯一“记忆详情”，曲线作为抽屉内的一个图表区块，去掉卡片重复入口。

## 8. 修改方案（按优先级）

### P0（答辩前，2~3 天，风险最低收益最高）

| 项 | 做法 | 验收 |
|---|---|---|
| 1. 破坏性操作确认 | `confirm()` 包裹 reset/forget；forget 前显示受影响数 | 操作前必弹确认 |
| 2. Toast + Loading | 新增 `showToast`、`withLoading`；慢按钮禁用+提示 | 真模型生成有进度，错误醒目 |
| 3. 运行数据可导出 | “导出快照 JSON”按钮（sessions/events/forgotten） | 一键导出可回放 |
| 4. 前端状态统一 | 引入 `UI` 状态对象，`refreshAll` 只写 UI，渲染从 UI 读 | 消除跨函数状态不一致 |

### P1（答辩后/课程收尾）

| 项 | 做法 |
|---|---|
| 5. 后端分层 | 拆 `state.py/api.py/server.py`；session 用 dataclass |
| 6. 分页/增量 | 记忆列表分页 50/页；事件流 `since` 增量 |
| 7. 评估页签 | 展示 `eval/results/*.json` 摘要 + 系统健康指标 |
| 8. XSS/安全 | innerHTML 审计；可选 token；窄屏响应式 |
| 9. 字段契约测试 | `_selftest` 扩展字段断言 + 纯函数测试 |

### P2（长期演进）

- 真正模块化前端（或多页）、状态持久化 UIState.db、可访问性 aria、OpenAPI、单元测试/端到端测试。

---

## 9. 一句话总结

> 当前 WebUI 作为**演示工具是合格甚至超出预期的**（页签、抽屉、遗忘曲线、事件展开都已完成）；作为**产品/工程系统还不成熟**——主要短板是“单文件大、状态散、无持久化、无确认/加载反馈、缺自动化测试”。按 P0 优先做“确认、反馈、导出、状态统一”四项即可显著提升答辩可靠性；后续再按 P1/P2 逐步演进。
