## 1. 系统概述（一页看懂）

### 1.1 系统是什么

给「智戎」作战规划智能体外挂的**两层四模块记忆系统**：

- **短期槽位**管"本场规划的上下文资源调度"——场生场灭，约束永不压缩；
- **长期双库**管"跨场次的知识沉淀与召回"——事实库（参数级精确）+ 经验库（语义召回）；
- 两层之间只留一条**复盘晋升**通道，由三道门控强制（不靠自觉）；
- 系统按**七步闭环**运行，记忆供给按 **MDMP 七阶段**驱动。

### 1.2 解决什么问题（没有记忆系统会怎样）

| # | 失败模式 | 具体表现 | 系统里的对策 |
|---|---|---|---|
| P1 | 每场从零开始 | 第一场夜战吃过的亏第二场照犯 | 七步闭环 + 复盘进化（§8） |
| P2 | 场内信息超窗 | 战报挤爆上下文，粗暴截断丢掉"禁止越境" | 分层槽位 + 确定性阈值换页（§5） |
| P3 | 查询口径混杂 | 查"T-90 速度"要精确、查"夜战教训"要泛化，单一检索两头不讨好 | 双库 + 三路混合检索（§6/§7） |
| P4 | 记忆库越攒越脏 | 同一教训写十遍、流水账混进知识库、来历说不清 | 建议-执行分离 + 三道门 + 审计（§8） |
| P5 | goal 字面直查没意义 | 任务一句话信息量太薄，检索结果必然泛化 | MDMP 阶段驱动供给 + 阶段亲和（§4） |

> P5 为老师指导意见的落地：记忆需求由**规划进行到哪一步**决定，而非任务陈述字面。

### 1.3 一场任务的完整生命周期

```
【开场】受领任务："夜间夺占 2 号高地"
   ① 建短期槽位：goal + 约束[禁止越境, 限时4小时]（🔒 不可压缩）
   ② 生成查询列表（检索计划显式化，事后可审计）
   ③ 三路检索（vector/bm25/sql 融合重排 + 阶段亲和加分）
   ④ 装载登记（逐条溯源：哪个库/哪场沉淀/召回几次）
   ⑤ 渲染上下文 → 注入规划 LLM → 产出作战方案
   ⑥ 战报持续推入 FIFO（70% 预警 → 100% flush 压缩，存档不丢）
【复盘】任务结束，结构化总结（结果/教训/经验）
   ⑦ 记忆进化：抽取候选 → 三道门控 → 写入长期库（带阶段归因）
【下场】同型任务开场检索，自动召回本场沉淀的教训（自增强回路）
```

### 1.4 论文映射一览（每个组件有出处）

| 组件 | 论文/理论来源 | 我们取什么 |
|---|---|---|
| 短期槽位分层 | MemGPT | 常驻区 + FIFO 滚动 + 阈值换页（改造：确定性阈值替代 LLM 换页） |
| 事实库 | ChatDB | 数据库即符号记忆，属性精确过滤 |
| 经验库 | ExpeL + Reflexion | 经验轨迹召回 + 重要性加权 |
| 三路检索 | MIRIX | 按查询特点路由（我们扩展为按规划阶段路由） |
| θ 查重写入 | PREMem | 链接对判重（θ=0.80，Mock 分布适配） |
| 艾宾浩斯遗忘 | MemoryBank | R=e^(-t/S)，命中强化 S+1（我们加失败教训保护线） |
| 复盘抽象 | TiM Post-thinking | 多条教训 → 一条通用原则 |
| 阶段化记忆 | MDMP（ADP 5-0）+ 事件分段理论（Zacks & Swallow） | 七阶段模板查询 + 阶段亲和 |
| 渲染首尾原则 | LongLLMLingua | 关键信息放上下文首尾 |
| 建议-执行分离 | —（我们的架构决策） | LLM 只建议、代码执行，可审计 |

## 2. 总体架构：两层四模块 + 双循环

### 2.1 分层结构

```
┌─ 编排层 ──────────────────────────────────────────────────────┐
│  pipeline.py    七步闭环编排（只管流程顺序）                     │
│  controller.py  总调度（唯一同时碰四模块的角色；SCM：何时读/写/归档）│
├─ 跨切面 ──────────────────────────────────────────────────────┤
│  boundary.py    长短期边界：两把尺子 + 三道门 + 审计日志           │
│  stages.py      规划阶段：MDMP 七步模板 + 教训阶段归因            │
├─ 能力层（四模块互相不 import，只经 schema 数据对象交互）───────────┤
│  short_term/    working_memory（槽位+FIFO+阈值）+ compression    │
│  long_term/     factual_store（SQLite）+ experiential_store（向量）│
│  retrieval/     bm25 + hybrid（三路路由融合 + 阶段亲和）           │
│  evolution/     memory_evolution（四操作：写/合/忘/抽）            │
├─ 模型层 ──────────────────────────────────────────────────────┤
│  schema.py      统一数据模型（单一事实源）                         │
│  llm.py / embeddings.py  外部能力抽象（Mock 离线可跑 / OpenAI 骨架）│
└───────────────────────────────────────────────────────────────┘
```

**三条耦合铁律**（写在 `long_term/base.py` 接口注释）：
1. **检索只读、进化只写**——独立评测互不污染；
2. **依赖注入**——`MemoryController(llm=?, embedding=?, ...)` 全可替换，Mock 与真模型业务代码零改动；
3. **数据模型改动只从 `schema.py` 出发**——单一事实源。

### 2.2 双循环：七步闭环 × MDMP 七阶段

系统里有两个"七"，是**两个不同的节律**：

| | 七步闭环 | MDMP 七阶段 |
|---|---|---|
| 是什么 | **记忆系统**的运行节律 | **规划过程**的推进节律 |
| 谁的循环 | memsys 内部（①规划→②查询→③检索→④装载→⑤上下文→⑥反馈→⑦进化） | 规划智能体外部（1受领任务→2任务分析→3方案拟制→4方案推演→5方案比较→6定下决心→7命令拟制） |
| 交汇点 | ②查询列表 | 由阶段模板生成（§4） |
| WebUI 体现 | 页首七步进度条（stepper） | 左栏"🎯 规划阶段推进"卡 |

一次典型运行：开场（闭环①）→ 逐阶段推进（每阶段生成查询→闭环②③④→阶段供给完成）→ 消息反馈（闭环⑥）→ 复盘进化（闭环⑦）。

## 3. 核心数据模型（schema.py）

### 3.1 四个数据对象

**① `WorkingMemorySlot`（短期槽位，一场一槽）**

| 字段 | 放什么 | 压缩待遇 |
|---|---|---|
| `goal` / `constraints` | 本次目标、作战约束 | 🔒 **永不被删** |
| `working_context` | 高频关键信息常驻区 | 最后才动它 |
| `fifo_queue` | 战报滚动队列（最旧先出） | **主要压缩对象** |
| `query_list` | 检索计划（含阶段生成的查询） | 不压缩——审计对象 |
| `loaded_memory` | 已装载长期记忆 id 登记 | — |
| `intermediate_results` | 管线中间结果 | — |
| `current_stage` | 当前规划阶段（MDMP stage_id） | — |
| `plan_id` / `status` / 时间戳 | 场次身份与生命周期 | — |

**② `MemoryEntry`（长期条目，双库共用一种格式，13 字段分四组）**

| 字段组 | 字段 | 服务什么 |
|---|---|---|
| 本体（3） | `id`（`fact-1a2b3c4d`）/ `type` / `content` | 条目识别与正文 |
| 溯源（3） | `source` / `session_id` / `timestamp` | 每条注入规划的记忆可回查来历 |
| 遗忘模型（4） | `importance`（S 初值+保护线）/ `decay_strength`（S，召回+1）/ `recall_count` / `last_recalled_at`（t 起点） | 艾宾浩斯 `R=e^(-t/S)`；`mark_recalled()` 间隔效应 |
| 进化回放（3） | `merged_from` / `op_history` / `metadata` | 记忆怎么来的可重演；`metadata.stage` 承载阶段标签 |

**③ `QueryItem`（查询项）**：`{q_id, intent, target(fact/experience), route(vector/bm25/sql), query_text, stage, answer_memory_ids(命中回填)}`

**④ `RetrievedMemory`（检索结果）**：`{entry, score, route, rank}`

### 3.2 遗忘模型白话版

`R = e^(-t/S)`——R=还剩多少（留存率），t=多久没用，S=强度（每被召回 +1）。
越久不用衰减越快（先快后慢）；每用一次巩固一次。**效果**：常用教训自动留存、没人用的教训自然淘汰，无需人工清理。保护线：`importance ≥ 2.0` 永不遗忘（失败教训保命，论文没有、领域常识）。

## 4. 阶段感知记忆（stages.py）

> P5 的对策。核心思想：**"任务分析阶段要情报、方案拟制阶段要战例、推演阶段要教训"**——查询由阶段模板生成，记忆按阶段归因，检索按阶段亲和。

### 4.1 MDMP 七阶段与知识模板

| # | 阶段 | 该阶段需要的记忆 | 生成的查询（target/route） |
|---|---|---|---|
| 1 | 受领任务 `mission_receipt` | 既往同型任务教训 | experience / vector |
| 2 | 任务分析 `mission_analysis` | 情报事实（IPB 式） | fact / vector + sql |
| 3 | 方案拟制 `coa_development` | 相似战例与对策（CBR） | experience / vector + bm25 |
| 4 | 方案推演 `coa_analysis` | 对抗/推演历史教训 | experience / bm25 |
| 5 | 方案比较 `coa_comparison` | 评估维度经验 | experience / vector |
| 6 | 定下决心 `coa_approval` | 决断类历史教训 | experience / bm25 |
| 7 | 命令拟制 `orders_production` | 条令条款与格式 | fact / sql |

表在 `STAGE_TEMPLATES`（"表即文档"，新增阶段加一行）。

### 4.2 三层接线

```
① 查询生成   controller.advance_stage(stage_id)
             → queries_for_stage() 按模板生成（{goal} 占位注入）
             → 追加进 slot.query_list（审计轨迹完整，不覆盖）
             → 只执行本阶段查询（stage 过滤）

② 阶段亲和   hybrid.retrieve() 融合后、min_score 过滤前：
             记忆 metadata.stage == 查询 stage → 融合分 +0.15（stage_bonus 可调）

③ 教训归因   evolution 写入路径：
             attr_stage(教训文本) 按关键词归因 → metadata.stage 落库
             （"侦察/敌情/漏判"→任务分析，"战法/突破口/佯动"→方案拟制，
              "伏击/干扰/超时"→方案推演…无命中默认归推演）
             → 下场同阶段检索优先召回（"阶段对阶段"复用）
```

**幂等保证**：同阶段重复推进返回缓存命中、不重复检索（防止 UI 重复点击把 `recall_count`/S 刷高）。**进化保标签**：merge/abstract 产物继承源条目的 stage 标签。

### 4.3 升级路径

MVP 是确定性模板（可测试可复现）；接真模型后换 LLM 按阶段提示词生成查询/归因——**接口不变**（与 G2 门控同款升级路径）。

## 5. 短期记忆层（short_term/）

### 5.1 WorkingMemory：容量与换页

```
capacity_tokens = 4000（1 中文字 ≈ 1 token）
   ├─ 70% 预警：memory_pressure = True（上层可提前归档）
   └─ 100% flush：驱逐最旧 ~50% → 旧递归摘要 + 被驱逐消息 → 新摘要(≤120词)
                  → 存 archived（不丢！close_session 时并入复盘材料）
```

**渲染顺序**（`render()`）：`【规划阶段】` → 目标/约束 → 历史摘要 → 关键信息 → 查询列表 → 最近 20 条消息——关键信息永远在首尾（LongLLMLingua 位置偏置）。

### 5.2 压缩三档（compression.py，G1 消融一行切换）

| 策略 | 方式 | 状态 |
|---|---|---|
| `truncate` | FIFO 最旧端截断 | ✅ MVP 默认 |
| `summarize` | 历史整体摘要（LLM） | ✅ 可用 |
| `llmlingua` | 删 token 式压缩 | 适配器预留（装包后实现 `LLMLinguaStrategy`） |

**铁律**：约束字段永不被压缩（压缩只动 FIFO，最后才动 working_context）。

## 6. 长期记忆双库（long_term/）

### 6.1 为什么双库（检索需求互斥）

| | 事实库（陈述性："是什么"） | 经验库（程序性："怎么做"） |
|---|---|---|
| 典型内容 | "T-90 最大速度 60km/h" | "夜间突袭要前置电子压制" |
| 最怕 | 召回"差不多"的错数 | 字面不同就漏召回 |
| 检索主路 | `search_attrs()` 属性精确过滤 | 向量语义召回 |
| 打分 | cosine 主 + LIKE 兜底（命中记 1.0） | `0.8×cosine + 0.2×min(imp/3,1)` |

单一存储无法同时满足两种要求：向量库存事实会召回 M1A2 的 67km/h；数据库存经验则"夜战吃亏"查不到"夜间遭伏击"。

### 6.2 形态差异

| 维度 | `FactualStore` | `ExperientialStore` |
|---|---|---|
| 存储 | SQLite 单文件（12 列，`attrs_json` 属性键值） | 内存 dict + 向量索引（留 FAISS 位） |
| 线程安全 | RLock 串行化（webui 多线程用） | — |
| 命中强化 | `persist_recall()` 回写 SQLite（防重启丢） | 内存即时生效 |
| `metadata.stage` | 随 `attrs_json` 自动持久化 | 随条目在内存 |

两库实现同一接口 `BaseLongTermStore`（读方法/写方法分两段——"检索只读、进化只写"的接口化）。

## 7. 检索层（retrieval/）

### 7.1 三路路由（MIRIX 式，按查询特点选路）

| 查询类型 | 例子 | 路由 | 为什么 |
|---|---|---|---|
| 语义相似 | "夜战教训" | vector | "夜战吃亏"≠字面重叠 |
| 型号代号 | "T-90" | bm25 | 专有名词字面最稳 |
| 参数精确 | "红方坦克破甲厚度" | sql | 需要确定性答案 |

### 7.2 融合流程（hybrid.retrieve）

```
1) 主路检索 + 另两路补充（多视角）
2) 归一化：cosine→(s+1)/2 ∈[0,1]；bm25→除以该路最大值；sql 恒 1.0
3) 融合：score = Σ 路由权重 × 归一化分（α=0.5 vector, β=0.3 bm25, γ=0.2 sql，
   同一条记忆多路命中累加）
3.5) 阶段亲和：metadata.stage == q.stage → score += stage_bonus(0.15)
4) 排序 → min_score(0.35) 阈值过滤 → top_k 截断
5) 统一命中强化（mark_recalled 只在这里执行一次——防三路互检虚涨 3 倍）
6) 回填 q.answer_memory_ids（创新点 C：检索计划可审计）
```

**min_score 的意义**（ExpeL/Mem-α/MemP 共同技巧）：低分噪声不返回——噪声进上下文比漏召回更伤。**阶段亲和放在过滤前**：对口记忆应能借亲和分过阈值。

## 8. 进化层与边界（evolution/ + boundary.py）

### 8.1 建议-执行分离（核心架构决策）

```
复盘文本 → LLM 抽取建议 [{op:write, type, content, importance}]  ← 建议侧（可换真模型/RL）
        → 代码执行：门控 → 写入(查重) → 相邻合并 → 遗忘扫描 → 教训抽象 ← 执行侧（确定性可回放）
```

为什么分离：作战复盘必须可审计——"为什么删了这条记忆？谁决定的？"全 LLM 黑盒无法回答。每次进化产出 `EvolutionReport`（四操作计数 + 拒绝原因），消融直接统计此对象。

### 8.2 四操作

| 操作 | 来源 | 本地化改造 |
|---|---|---|
| 写入 | PREMem θ 查重 | θ=0.80（Mock 分布适配；真模型回调 0.6）+ 阶段归因标签 |
| 合并 | TiM merge | `merged_from` 溯源 + **保留 stage 标签** |
| 遗忘 | MemoryBank R=e^(-t/S) | + 失败教训保护线（importance≥2 永不删） |
| 抽象 | TiM Post-thinking | 新经验 ≥2 条触发 + 保留 stage 标签 |

### 8.3 边界：两把尺子、三道门、双向禁止

**两把尺子**（判定长短期的认知判据，写进类型系统）：
- 尺子A 来源：任务内产生 vs 跨场次沉淀
- 尺子B 时间：场次生命周期 vs 持久

**三道门**（短期→长期的唯一通道：复盘晋升 `promote()`）：

```
G1 复盘驱动门：只有场次复盘可晋升——规划中途随手写长期被拒
G2 类别模板门：候选必须命中事实/经验关键词模板——流水账被拒（留短期归档不丢）
G3 θ 查重门：与库内内容余弦相似度 > θ 判重复——同一教训不写十遍
```

**双向禁止**：短期→长期必须走 `promote()`；长期→短期只能以检索结果形态进入（`validate_load()` 拦"整段拷进 FIFO"）。**每道门决策进审计日志**（`boundary.audit_log()`，WebUI 可查）。

## 13. 设计决策速查表 + 术语表

### 13.1 关键决策与理由

| 决策 | 为什么 | 备选方案与取舍 |
|---|---|---|
| 双库分治 | 两类检索需求互斥（参数精确 vs 语义泛化） | 单库+混合打分：无法保证参数级零容错 |
| 确定性阈值换页（70%/100%） | 消融要求可复现；LLM 换页不可测试 | MemGPT 原版 LLM 自主换页 |
| 归档并入复盘材料 | MemGPT 只管压缩、TiM 只管复盘——被压缩信息不能失去晋升机会 | 归档即止（信息孤岛） |
| 建议-执行分离 | 复盘可审计（谁决定删的记忆？） | 全 LLM 黑盒 |
| 失败教训保护线 | 作战失败不能忘（领域常识，论文没有） | 纯衰减（重要教训可能被忘） |
| 阶段模板 MVP 先行 | 可测试可复现；接口留 LLM 升级位 | 直接上 LLM 生成（不可测试） |
| advance_stage 幂等 | UI 重复点击不得虚涨 recall_count/S | 每次重查（强化模型失真） |
| min_score 阈值 | 低分噪声比漏召回更伤 | 全部返回（污染上下文） |

### 13.2 术语表

| 术语 | 含义 |
|---|---|
| **场次（session）** | 一次规划任务的完整生命周期；场次 ID = plan_id |
| **槽位（slot）** | 一个场次的短期工作记忆容器，场生场灭 |
| **flush / 归档（archived）** | FIFO 超容量时驱逐最旧消息并生成递归摘要；被驱逐内容存档不丢，复盘时并入材料 |
| **复盘（review）** | 场次结束后的结构化总结：结果+教训+经验；记忆进化的唯一输入 |
| **晋升（promote）** | 短期内容进入长期库的唯一合法通道（三道门控） |
| **θ（theta）** | 查重相似度阈值（余弦 > θ 判重复），当前 0.80 |
| **R = e^(-t/S)** | 艾宾浩斯留存率：t=距上次召回时间，S=强度（召回 +1） |
| **阶段亲和（stage bonus）** | 记忆的 stage 标签与当前规划阶段对口时融合分 +0.15 |
| **MDMP** | Military Decision-Making Process，军事决策流程七步（ADP 5-0） |
| **min_score** | 融合分阈值（0.35），低于此值的命中不返回 |
| **MockLLM / MockEmbedding** | 确定性离线实现，保证零依赖可跑、测试可断言 |
