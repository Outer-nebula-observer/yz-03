# 18 多轮作战案例《高地群攻防战役》使用指南

> **说明**：本案例是一条 5 场的连续战役剧本，专门用来**直观展示记忆系统的运行、结果与效果**：前场教训被后场召回、多轮复用越用越强、重复复盘被查重、经验抽象为通用教训、跨主题不互相污染。支持两种运行方式：CLI（命令行逐场演示）与 WebUI（一键导入 + 逐步进行）。两者共用同一份数据：`code/课题3_长短期记忆/campaign/campaign_data.py`。

---

## 一、案例背景与设计意图

战役：红方在一条时间线上连续执行 5 场任务。

| 场次 | 剧情 | 记忆系统展示点 |
|---|---|---|
| P1 夜袭首战（2 号高地） | 夜间夺占 2 号高地，遭遇伏击 | 系统从历史种子中召回地形/夜战教训；复盘沉淀"电子压制""预备队投入"两条教训，并触发**抽象** |
| P2 第二夜再战（2 号高地） | 吸取上场教训再次进攻，成功 | **跨场次复用**：检索命中 `source=复盘:P1`；规划上下文携带上场教训 |
| P3 强渡青川河 | 主题切换到渡河 | 召回渡河水文/架桥教训；复盘"假渡口佯动"与种子重复 → **θ 查重跳过（skip_duplicate=1）** |
| P4 山地进攻 5 号高地 | 山地夜间进攻 | 电子压制教训**二次复用**（P1）；新增"制高点观察哨"教训 |
| P5 联合反攻 2 号高地 | 多兵种联合反攻 | **多源复用**：P1/P2 教训与多个抽象条目同时命中；新增"信号误击"教训 |

关键输出形态：
- 检索命中带溯源（`source=复盘:P1` / `campaign-seed` / `abstract`）；
- 进化报告四操作计数（write/merge/forget/abstract）+ `skip_duplicate`；
- 战役记忆轨迹表（每场检索数、复用数、写入/抽象/去重、经验库规模）。

## 二、CLI 使用

在项目目录下：

```bash
cd code/课题3_长短期记忆

# 1) 离线 Mock 演示（推荐，快且稳定）
python examples/campaign_demo.py

# 2) 用 DeepSeek 真模型生成规划/抽取（需 .env 有有效 DEEPSEEK_API_KEY）
python examples/campaign_demo.py --real

# 3) 真模型 + 尝试 GLM embedding（GLM Key 失效会自动回退 Mock）
python examples/campaign_demo.py --real --embed-glm

# 4) 结果落盘 JSON
python examples/campaign_demo.py --json eval/results/campaign_demo.json
```

**预期输出结构（每场）**：
```
① P1｜第一场 · 夜袭首战（2 号高地）
   ③ 检索命中 N 条：       ← 带 🔄 表示该条来自往场复盘（复用）
    ♻️ 跨场次复用 M 条       ← 显示 source=复盘:Pxx
   ⑤ 规划输出摘要
   ⑦ 进化报告 {write/merge/forget/abstract/skip_duplicate}
   库规模：事实 X / 经验 Y
```

**末尾战役记忆轨迹表**：一行一场，关注 `复用数` 和 `经验库` 两列，直观看到"越用越强"（P5 复用 3 条）与"库增长"。

## 三、WebUI 使用（一键导入 + 逐步进行）

### 3.1 启动

```bash
cd code/课题3_长短期记忆
python webui/server.py            # 自动打开 http://127.0.0.1:8765
```

> 提示：如果你配置了 DeepSeek Key，WebUI 会**自动使用真模型**（生成规划/抽取更真实）；没有 Key 或用 `WEBUI_MOCK=1 python webui/server.py` 则走 Mock（离线稳定）。

### 3.2 一键导入

页面左侧新增 **“⚔️ 多轮战役案例”** 卡片：
1. 选择战役：`高地群攻防战役（5 场）`（默认已选中）；
2. 点 **“📥 一键导入战役”**：系统重置两个记忆库并注入战役种子（6 条事实 + 5 条经验），状态区提示“已导入”。

### 3.3 逐步进行

- 点 **“▶ 逐步进行（下一场）”**：每点一次执行**完整的一场**（开场→阶段查询→检索装载→战报消息→复盘进化），随后：
  - 中栏事件流新增该场全过程；
  - 右栏**检索命中**显示本场命中（往场沉淀带 `⏪ 往场` 徽标）；
  - 右栏**进化报告**显示本场 write/abstract/skip；
  - 右栏**场次历史**增加一项沉淀记录；
  - 状态区提示本场复用了几条、下一场是哪场。
- 连续点 5 次跑完全部场次；跑完后状态区显示“🎉 战役全部完成”。

### 3.4 自动跑完全部

- 点 **“⏭ 自动跑完全部”**：系统自动依次执行 5 场（每场约 0.5s+），最后刷新所有面板，可直接从右栏回看每一场的沉淀与复用。

### 3.5 演示时重点指着看（3 分钟话术）

1. **P1 开场检索**：命中 `campaign-seed` 的经验（先遣侦察伏击）——系统不是从零开始；
2. **P1 进化报告**：`write 2 / abstract 1`——复盘变成了长期记忆（可审计）；
3. **P2 检索命中**：出现 `⏪ 往场 P1 沉淀` 徽标、`source=复盘:P1`——**第一场教训被第二场召回**；
4. **P3 进化报告**：`skip_duplicate 1`——重复的"假渡口佯动"没写第二遍；
5. **P5 检索命中**：多条 `复盘:P1/P2` + `abstract` 同时命中——**多轮复用 + 抽象聚合**；
6. **右栏经验库**：从 5 条长到 18 条，支持按重要性/召回/留存排序；
7. **边界审计**：放行/拒绝记录可见——每一条入库都有依据。

## 四、如何自定义自己的多轮案例

所有数据在 `campaign/campaign_data.py`，结构很直接：

```python
CAMPAIGNS = {
    "your_battle": {
        "title": "你的战役名",
        "desc": "一句话说明演示意图",
        "rounds": [
            {
                "plan_id": "B1",
                "title": "第 1 场 · 标题",
                "goal": "作战目标",
                "constraints": ["约束1", "约束2"],
                "queries": [
                    {"intent": "...", "target": "fact/experience",
                     "route": "vector/bm25/sql", "query_text": "...",
                     "attrs": {...}   # 可选，sql 精确查询
                    },
                ],
                "messages": ["战报1", "战报2"],
                "review": "复盘：… 教训：… 经验：…",
                "expect_reuse": [],   # 可选，仅记录意图
            },
            # ... 多场
        ],
    },
}
```

要点：
- **查询文本与要命中的记忆尽量有词面重叠**（Mock 词袋下最稳；真模型/真向量后可以放宽）；
- `review` 里的“教训/经验”句子会被抽取为经验；≥2 条会触发抽象；
- 若想演示去重，让某场复盘写一条与种子/前面场次**措辞相近**的经验；
- 改完 `campaign_data.py`，CLI 与 WebUI **都自动生效**（共用同一数据），无需改别处。

## 五、注意事项

| 事项 | 说明 |
|---|---|
| Mock vs 真模型 | CLI 默认 Mock，`--real` 用 DeepSeek；WebUI 按 `.env` 自动，`WEBUI_MOCK=1` 强制离线 |
| embedding | DeepSeek 无 embedding；默认 MockEmbedding。`--embed-glm` 或 WebUI 会自动尝试 GLM embedding，Key 失效自动回退 Mock（已实测验证） |
| 结果落盘 | CLI `--json` 可导出每场结果；WebUI 的运行过程在浏览器内（可截图/录屏） |
| 与既有演示的关系 | 本案例是 `demoTwoSessions`（两场）的超集：两场演示看“一次复用”，五场战役看“多轮累积与去重/抽象” |

## 六、记忆生命周期案例与右侧抽屉（v0.6 新增）

### 6.1 案例《记忆生命周期》（验证遗忘/进化/合并/抽象）

在 WebUI 战役下拉中新增第二个战役「记忆生命周期（时间推进 · 遗忘/进化/合并/抽象）」（6 场）。
每场结束会**模拟时间推进**（`simulate_days`，15~45 天）并触发 `forget()`：

| 演示点 | 表现 |
|---|---|
| 遗忘 | 低价值/一次性经验长期未召回 → 被删除，进入**遗忘日志** |
| 保护线 | `importance≥2` 的高价值教训即使老化也不删（L2 通信教训保留） |
| 进化 | 每场复盘写入新经验、≥2 条触发抽象；相似经验（L4 与 L1 的"阵地轮换"）可合并 |
| 生命周期 | 经验库规模先增后稳：普通经验被淘汰，高价值经验留存并可被后续场召回 |

CLI 对应：
```bash
python examples/campaign_demo.py --campaign memory_lifecycle
```
（每场结束后自动模拟时间推进并显示遗忘条数；也可直接 WebUI 逐步进行。）

### 6.2 WebUI 右侧抽屉「记忆详情」

右栏顶部新增两个按钮：
- **📑 记忆详情（右侧抽屉）**：从屏幕右侧滑出面板，含三个页签：
  - **🗂 总览**：记忆总数/受保护/已低于遗忘线/已遗忘 统计 + 全库列表（点一条进入历史）
  - **🧬 单条历史**：创建时间、来源/场次、强度 S、召回次数、距上次召回、当前留存、
    **预计遗忘日期**（若不再被召回）、进化轨迹（write→merge→abstract→…）、合并来源、阶段标签
  - **⚰ 遗忘日志**：每条被遗忘记忆的墓碑——内容、遗忘时间、原因（R<threshold）、原重要性、当时留存
- **⏩ 模拟时间+遗忘（30天）**：手动老化全部记忆并触发遗忘，便于现场演示“何时/为何遗忘”。

操作路径：开任意案例/场景 → 点抽屉按钮 → 点记忆条目看单条历史 → 点“模拟时间+遗忘”后切到“遗忘日志”看墓碑。
