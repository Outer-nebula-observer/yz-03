**界面三栏对应七步闭环**：
- **左栏（操作台）**：①② 填目标/约束/查询列表开场 → ③④ 一键检索装载 → 场次消息推入（FIFO）→ ⑥⑦ 复盘文本进化；
- **中栏（结果区）**：⑤ 工作记忆上下文实时渲染（token/预警状态）+ ③ 检索命中卡片（**每条带溯源 badge**）+ ⑦ 进化四操作计数；
- **右栏（记忆库）**：事实/经验双库浏览（留存率进度条=艾宾浩斯可视化）+ 混合检索试验 + 边界审计日志（放行/拒绝可查）。

**现场演示路径（3 分钟）**：进入页面（自动预置战例/教训）→ 左栏"开场 ①②" → "检索并装载 ③④"（中栏出命中+溯源）→ "推入 FIFO"（看 token 增长）→ 改复盘文本 → "复盘并进化 ⑥⑦"（右栏经验库 +1、审计日志出现）→ 顶部场次变"无场次"。

**技术说明（被问时答）**：纯 Python 标准库 `http.server`（零第三方依赖，与 memsys 哲学一致）；`ThreadingHTTPServer` 多线程 + SQLite `check_same_thread=False` + RLock 串行化（`factual_store.py` 内注释）；前端原生 JS 无框架。

### 证据 1：检索命中且可溯源（demo · P001 输出）

```

| 字段 | 说明 |
|---|---|
| 查询"2 号高地地形装甲通行" → 命中地形事实 | **③ 任务感知检索有效**（vector 路，分数显著高于次名） |

| 规划输出含【装载记忆】段 | **v0.3 关键修复**：检索命中的记忆正文真正进入注入 LLM 的上下文（此前只登记 id，"检索增强"最后一公里是断的） |

### 证据 2：进化真的写入新记忆（demo · P001 进化报告）

```

## 三、指标口径（被追问"怎么量化"时答）

实现于 `eval/metrics.py`（检索层）+ `eval/task_metrics.py`（任务层）+ `eval/stats.py`（统计推断），全部零依赖：

| 层 | 指标 | 含义 | v0.3 实测值 |
|---|---|---|---|
| 检索 | hit@k / recall@k / MRR / NDCG@k | gold 命中与排序质量 | G3: 0.636（随机基线 0.357） |
| 检索 | gold_above_distractor | gold 是否排在干扰项之前（参数张冠李戴检验） | G3: 1.0 |
| 任务 | constraint_sat | 约束判别词出现在规划输出的比例 | G0/G1=1.0（Mock 回显）；真模型后有意义 |
| 任务 | memory_citation | 装载记忆的核心片段出现在输出的比例 | G0/G1=**0** vs G3=0.75 |
| 任务 | noise_pollution | 负例查询带入的无关记忆出现在输出的比例 | G3: 0 |
| 统计 | bootstrap CI / 配对置换 p | 均值置信区间与组间显著性 | G3 vs G2: p=0.0001 |
| 基线 | random hit@k | 随机排序期望（解析式） | 0.357（n=14）——所有数字的对照下限 |

## 四、诚实边界（必答题）

> **"Mock 下的数字能说明什么？"**——检索层：机制与脚手架的正确性（双库贡献 p=0.0001、跨场次复用 0.83 vs 0、负例滤噪 0%、参数干扰压制 1.0——这些是**结构正确性**的证据）。**不能外推的**：C 类转述命中与 G5 混合增益（字符词袋无真语义，消融 v2 已如实记录"混合不优于单路"的负结果）；任务层引用率（MockLLM 是回显，度量的是"上下文构造正确"而非"LLM 善用记忆"）。接真模型后**同一脚本重跑即可**（口径不变，含义升级），min_score/θ 按消融 v2 的标定协议重定。

## 五、一行总结（汇报收尾）

> **七步闭环离线跑通且装载记忆真正进入规划上下文；第一场沉淀的教训第二场自动召回（hit@5=0.83 vs 对照 0，可溯源）；G0–G6 消融含显著性检验（双库 p=0.0001）——接真模型与智戎链路即进入实测阶段。**
