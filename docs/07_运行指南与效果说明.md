# 自测（先起服务再跑，20 项断言全过）

**界面三栏对应七步闭环**：
- **左栏（操作台）**：①② 填目标/约束/查询列表开场 → ③④ 一键检索装载 → 场次消息推入（FIFO）→ ⑥⑦ 复盘文本进化；
- **中栏（结果区）**：⑤ 工作记忆上下文实时渲染（token/预警状态）+ ③ 检索命中卡片（**每条带溯源 badge**）+ ⑦ 进化四操作计数；
- **右栏（记忆库）**：事实/经验双库浏览（留存率进度条=艾宾浩斯可视化）+ 混合检索试验 + 边界审计日志（放行/拒绝可查）。

**现场演示路径（3 分钟）**：进入页面（自动预置战例/教训）→ 左栏"开场 ①②" → "检索并装载 ③④"（中栏出命中+溯源）→ "推入 FIFO"（看 token 增长）→ 改复盘文本 → "复盘并进化 ⑥⑦"（右栏经验库 +1、审计日志出现）→ 顶部场次变"无场次"。

**技术说明（被问时答）**：纯 Python 标准库 `http.server`（零第三方依赖，与 memsys 哲学一致）；`ThreadingHTTPServer` 多线程 + SQLite `check_same_thread=False` + RLock 串行化（`factual_store.py` 内注释）；前端原生 JS 无框架。

## 二、效果说明：每个输出证明什么

### 证据 1：检索命中且可溯源（demo · P001 输出）

```
{'id': 'fact-9a96bd38', 'type': 'fact', 'score': 1.07, 'route': 'vector',
 'content': '2 号高地海拔 320 米，北坡缓南坡陡，仅东侧可装甲通行。',
 'provenance': {'source': '', 'session_id': '', 'timestamp': ..., 'recall_count': 1}}
```

| 字段 | 说明 |
|---|---|
| 查询"2 号高地地形装甲通行" → 命中地形事实 | **③ 任务感知检索有效**（vector 路，分数 1.07 显著高于次名 0.59） |
| 查询"夜战侦察伏击教训" → 命中历史教训（bm25 路） | **多路路由有效**：教训类查询走了词法路 |
| 每条带 `provenance`（source/session/timestamp） | **创新点 E 可解释溯源**：注入规划的记忆可回查来历 |

### 证据 2：进化真的写入新记忆（demo · P001 进化报告）

```
----- ⑦ 进化报告 -----
  write: 1          ← 复盘文本中"电子压制/预备队投入"教训被抽取入库
  skip_duplicate: 0 ← 无重复（若重放复盘会变 1，证明 PREMem θ 查重在工作）
库规模: 事实库 2 / 经验库 2  →（复盘后经验库 +1）
```

> **⑦ 记忆进化有效**：不是人工插入，是 `evolve_from_review()` 从复盘文本自动抽取（MockLLM 关键词规则，真模型后为 LLM 抽取，接口不变）。

### 证据 3：越用越强（核心卖点，demo · P002 输出）

```
----- ③ 检索命中（含上一场新沉淀） -----
  {'id': 'experience-b051149e', 'score': 0.60,
   'content': '教训：夜间突袭未前置电子压制，接敌后通信被干扰。经验：预备队投入应提前 10 分钟。',
   'provenance': {'source': '复盘:P001', 'session_id': 'P001', ...}}   ← 关键
```

**P002 是"夜间进攻 3 号高地"**——与 P001 沉淀的"夜间突袭教训"语义相关，系统自动召回并注入 P002 的规划上下文。**这就是"记忆让智能体跨场次变强"的最小可验证闭环**（对应验收底线"跨场次经验复用"）。

### 证据 4：消融分层贡献（ablation 输出解读）

| 组 | 配置 | 输出怎么读 |
|---|---|---|
| G0 | 无记忆 | 基线（规划质量对照，检索指标不适用） |
| G1 | 仅短期 | `store_size=6`：链路通，长期检索被旁路 |
| G2 | +事实库 | `hit@5=1.0`：事实检索的贡献（地形/装备查询全中） |

### 证据 5：约束保护（tests · 工作记忆用例）

测试 3 故意灌 30 条消息触发超限 flush，断言 `slot.constraints == ["禁止越境"]` 通过——**压缩只删历史消息，作战约束永不丢**（对应 docs/04 避坑点 6）。

## 三、指标口径（被追问"怎么量化"时答）

实现于 `eval/metrics.py`（零依赖）：

| 指标 | 含义 | 当前值 |
|---|---|---|
| hit@k | top-k 是否含 gold | 1.0 |
| recall@k | top-k 覆盖 gold 比例 | 1.0 |
| MRR | 首个 gold 排名倒数 | 1.0 |
| NDCG@k | 位置折损加权 | 1.0 |
| store_size | 库规模（G4 对照） | 6→7 |

## 四、诚实边界（必答题）

> **"指标全是 1.0，是不是太好了？"**——是种子集太小（3 条查询 × 6 条记忆，MockEmbedding 词重叠必中）的结果，**不能外推真实效果**。README"当前不足"已列明：接真 embedding（BGE）+ 真模型（extract_memory_ops 质变）+ 扩到 ≥40 条作战测试集后，消融数字才有意义。**框架的价值在于：链路全部打通、消融脚手架就位，换真组件零改动（依赖注入）。**
