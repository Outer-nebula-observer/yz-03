## 16. 为什么 LLM Agent 需要记忆（What is Memory?）

### 16.1 记忆的狭义与广义

- **狭义记忆**：同一任务内的历史交互信息。
- **广义记忆**：
  1. 同一任务内的历史交互信息；
  2. 跨多个任务的历史交互信息；
  3. 外部知识。

### 16.2 三类记忆内容与代表工作

| 记忆类别 | 代表工作 | 要点 |
|---|---|---|
| **01 同一任务内的历史交互信息** | Generative Agent | 为实现特定目标而产生的历史行为 |
| | MemoChat | 基于单个对话会话的历史对话内容 |
| | TiM | 智能体完成任务后，让其自主生成多个思考过程，并将这些思考过程作为记忆 |
| | Voyager | 构建基于《我的世界》（Minecraft）的游戏智能体，其记忆包含完成任务所需的初步基础动作可执行代码 |
| **02 跨多个任务内的历史交互信息** | Reflexion | 以语言形式从过往任务中提取经验，并将这些经验应用于后续任务 |
| | Synapse | 专注于解决计算机控制类任务，记录成功案例 |
| | ExpeL | 智能体在环境中解决一系列复杂交互任务，存储并整理已完成的轨迹，为新任务召回相似轨迹；在召回轨迹中对比成功案例与失败案例，识别成功模式 |
| **03 外部知识** | ReAct | 推理过程中，若智能体缺乏相关信息，可利用维基百科 API 获取外部知识 |
| | GITM | 《我的世界》中的智能体，决策中可参考在线《我的世界》维基百科和攻略 |

## 17. 智能体记忆 vs 大模型记忆 / RAG / 上下文工程

### 17.1 智能体记忆 vs 大模型记忆

- **大模型记忆**：直接干预模型内部状态的机制，例如长上下文架构改造、缓存重写、循环状态保持、注意力稀疏化、外置 KV 存储扩展等；其目标是**扩展或重组底层模型的表示能力**。通常不支持跨任务持久化、环境驱动的适应或有意的记忆操作。
- **智能体记忆**：为决策智能体提供一个**可演化的外部记忆库**。

### 17.2 智能体记忆 vs RAG

- **经典 RAG**：主要为大模型提供对**静态外部知识源**的访问，旨在让生成以最新事实为据、缓解幻觉、提升知识密集型任务的准确率。
- **智能体记忆系统**：内嵌于智能体与环境的**持续交互**之中，不断将智能体自身行为与环境反馈产生的新信息纳入持久记忆库。

### 17.3 智能体记忆 vs 上下文工程

- 上下文工程管 **"窗口内的资源调度"**，记忆管 **"跨时间的认知连续性"**。
- 二者在**短期记忆处理**上，存在压缩、组织、选择等重叠。

> **一句话把握**：大模型记忆改"模型内部"，RAG 管"静态外部知识"，上下文工程管"当前窗口"，而智能体记忆管"跨时间、跨任务、可演化"的持久记忆库。四者的边界与重叠，正是记忆系统设计的核心张力所在。

## 18. 长短期记忆系统：定义与三阶段生命周期

### 18.1 长期与短期的划分标准：信息来源和时间尺度

- **短期记忆**：容量受限、临时存储、主动控制；与**当前任务高度相关**的信息。
- **长期记忆**：
  1. 过去事件、用户特定信息和外部环境状态的**事实记忆**；
  2. 长期积累形成的**经验记忆**。
- **短期 → 长期转换**：用**反思与抽象**完成。

**系统化类比**：

| 认知概念 | 系统实现 |
|---|---|
| 短期记忆 | 用受限的上下文窗口模拟"有限容量＋主动操纵" |
| 长期记忆 | 用可演化的外部记忆库模拟"持久积累＋按需检索" |
| 短期→长期转换 | 用反思与抽象 |

### 18.2 三阶段生命周期

#### (1) 记忆形成（记忆写入）

在时刻 t，智能体产生信息性产物 φ_t（工具输出、推理轨迹、部分计划、自我评估或环境反馈），将这些产物**选择性**地转化为候选记忆，提取具有潜在未来效用的信息，而非逐字存储全部交互历史。
**【任务】确定记忆内容，设计记忆存储结构。**

代表工作：

- **TiM**：从原始信息中提取实体间的关系，存储在结构化数据库中；写入数据库时，将相似内容归为同一组。
- **MemoChat**：智能体对每个对话片段进行总结，提炼核心讨论主题，并将这些主题作为索引，用于后续记忆条目的检索。

#### (2) 记忆检索（记忆读取）

构造**任务感知**的查询，检索记忆库，返回相关记忆内容 m_t，并将其格式化为大模型策略可直接使用的形式（例如文本片段序列或结构化摘要）。
**【任务】调用与任务最相关的记忆内容。**

代表工作：

- **ChatDB**：通过 SQL 语句实现；智能体提前生成一系列"记忆链"，基于这些链条生成 SQL 语句，进而从数据库中检索所需记忆。
- **MPC**：从记忆池中检索相关记忆，通过"思维链"示例，帮助智能体学会忽略无关记忆。
- **ExpeL**：将向量库作为记忆池，检索并获取与当前任务相似度最高的前 K 条成功轨迹。

#### (3) 记忆进化（记忆更新）

将记忆候选整合进现有记忆库，执行冗余条目合并、冲突消解、低价值信息丢弃，或为高效检索而重组记忆结构。
**【任务】生成新的、高阶的记忆。**

代表工作：

- **MemoryBank**：将对话内容提炼为高级摘要（类似人类回忆过往经历时聚焦关键信息的方式）；通过长期交互，智能体持续评估并完善自身知识体系，生成关于用户性格特质的日常洞察。
- **反思机制**：生成更高级别记忆、合并冗余记忆条目、遗忘不重要的早期记忆。

> **对赛题②的启发**：多模态记忆系统同样应把"写入 / 检索 / 更新"拆成三个可独立评估的环节，而不是只做"向量入库 + 相似度召回"。尤其**记忆进化（更新/遗忘/合并）**是最容易被忽略、也最能体现"记忆系统"与"静态 RAG 库"区别的部分。

## 19. 代表性记忆系统一览

### 19.1 总览表

| 系统 | 核心思想 | 关键机制 | 出处（年份） |
|---|---|---|---|
| TiM | "回忆-反思"双阶段长期记忆 | Recalling + Post-Thinking + 记忆更新 | 2023 |
| SCM | 记忆控制器动态激活长期记忆 | 记忆流 + 记忆控制器（archived/flash memory） | 2025 |
| MemGPT | LLM 即 CPU、上下文即 RAM，借鉴虚拟内存分页 | working context + FIFO queue + 外部归档 + Queue Manager + Function Executor | 2024 |
| ChatDB | 数据库作为 LLM 的符号记忆 | NL→SQL、链式 SQL 生成 | 2023 |

| MemSkill | 把记忆操作本身提升为可进化"技能" | 技能库 S + INSERT/UPDATE/DELETE/SKIP | — |

### 19.2 逐系统要点

#### TiM（Think in Memory，2023）

受人类记忆形成机制启发，提出基于 **"回忆-反思"双阶段过程** 的长期记忆框架，使 LLM 能像人类一样通过主动回忆历史信息并深度思考，将重要信息编码到长期记忆中，从而在多轮交互中保持连贯性和个性化。

- **Recalling**：从外部记忆存储中检索与当前上下文相关的历史信息；
- **Post-Thinking**：对检索到的记忆和生成的回复进行深度加工与整合，形成更高层次的记忆；
- **记忆更新**：通过时间衰减和相关性评估记忆，进行插入、遗忘、合并操作。

#### SCM（Self-Controlled Memory，2025）

把历史信息存储到**记忆流**中，并由一个 **"记忆控制器"** 动态决定激活哪些长期记忆、如何将其融入当前模型输入，从而生成精确且连贯的响应。

- **记忆流**：统一存放历史信息；
- **记忆控制器**：同时提供长期记忆（archived memory）与短期记忆（flash memory），并决定应从归档记忆中激活哪些记忆、如何把它们并入模型输入。

#### MemGPT（2024）

将 LLM 比作 **CPU**、将上下文窗口比作有限的 **RAM**；借鉴操作系统中**虚拟内存分页**机制，通过函数调用在上下文与外部存储之间移动数据，使 LLM 能处理远超上下文窗口的记忆信息。

- **主上下文（Prompt Tokens）**；
- **working context**：存储关键事实、用户偏好、角色设定等高频访问信息；
- **FIFO queue**：用户消息、Agent 回复、系统消息；
- **外部归档存储**：存储大量历史记忆；
- **Queue Manager**：消息追加、溢出控制；
- **Function Executor**：执行函数（Function = LLM 输出的结构化指令 / 工具调用）。

#### ChatDB（2023）

将数据库作为 LLM 的 **符号记忆（Symbolic Memory）**，通过自然语言到 SQL 的转换，使 LLM 能利用关系数据库进行精确的结构化知识存储与查询；核心是结合 LLM 的语义理解能力与数据库的符号推理能力，实现优势互补。

- **记忆读写**：写——将对话中的结构化信息（如事实、关系）存入数据库；读——通过 SQL 查询检索精确的符号信息；
- **多记忆类型支持**：支持关系型数据库中的表、记录、关系等结构化存储；
- **链式 SQL 生成**：对复杂查询，支持多步 SQL 的链式生成和执行。

#### MIRIX（Multi-Agent Memory，2025）

用**六种结构化的记忆类型 + 多智能体框架**，动态控制和协调记忆的更新与检索，使智能体能大规模持久化、推理并准确检索多样化的长期用户数据。

- **多种记忆**；
- **多智能体记忆管理模块**：元记忆管理器（中央路由器和协调者）、6 类记忆管理器（每个记忆组件配备一个专用管理智能体）、对话智能体（用户的自然语言交互接口）；
- **主动检索**：embedding_match（向量相似度）、bm25_match（关键词匹配）、string_match（字符串匹配）等多种检索策略，Agent 可根据查询特点自主选择最合适的方法。

#### RMM（Reflective Memory Management，2025）

提出**反思式记忆管理（RMM）**，融合前向反思（Prospective）与后向反思（Retrospective）。

- **前向反思**：跨多个粒度（utterance、turn、session）动态摘要交互内容，构建个性化记忆库；
- **后向反思**：基于 LLM 引用的证据，以在线强化学习方式迭代精化检索过程，使检索能自适应不同对话语境与用户模式。

#### PREMem（Pre-storage Reasoning for Episodic Memory，2025）

提出**预存储推理（pre-storage reasoning）**，在记忆写入时即完成跨会话的信息综合与关系建立，从而减轻推理时的计算负担，同时创建更丰富的记忆表征。

- **记忆构建**：将原始对话会话提取为结构化的记忆片段，分为三类——
  - **事实记忆**：状态、属性、拥有物、关系的客观事实；
  - **经历记忆**：经历过的具体事件、行动、互动；
  - **主观记忆**：偏好、观点、信念、目标、计划。
- **存储前记忆推理**：
  - **聚类**：对每轮会话的记忆片段做嵌入，自动确定最优聚类数，形成语义簇；
  - **记忆池**：保存之前会话中尚未找到语义匹配的簇；
  - **建立链接对**：计算新簇与持久池中旧簇的余弦相似度，若超过阈值 θ=0.6，则建立链接对；
  - **链接对推理**：让 LLM 分析两个簇中的记忆片段，生成推理记忆片段（扩展、积累、细化、转变、连接）。

#### LongLLMLingua（Prompt Compression，2024）

引入 **"问题感知"** 的压缩策略，根据具体问题动态调整压缩过程，并通过文档重排序和子序列恢复等技术，增强模型对关键信息的捕获能力。

- **文档重排序**：将最相关的文档片段置于 prompt 的前部；
- **动态压缩比**：根据文档与问题的相关度分配不同的压缩比例。

> 注：讲义的"Prompt Compression"页以 LongLLMLingua 为例；参考文献中另列 LLMLingua（2023）与 ICAE（2024）作为短期记忆/压缩方向的来源。

#### StructMem（Structured Memory）

以 **"基于时序的、关系性的事件"** 为基本记忆单元，通过 **"双视角提取（事件级绑定）"** 与 **"周期性语义整合（跨事件连接）"** 构建分层记忆框架，在提升长程时序推理和多跳问答性能的同时，显著降低计算开销（token 使用、API 调用、运行时间），优于现有扁平记忆和图记忆范式。

- **事件级绑定**：双视角提取 + 时间戳绑定，将每一轮对话打包成一个完整「事件小包」存在缓存里；
- **跨事件整合**：批量挖掘跨时间隐藏关联，增强推理。

#### MemSkill（Memory Skills）

- **问题动机**：记忆操作本身是固定的、由人事先定义的，系统能学习的仅仅是"在预定义操作之间做选择"，操作集合本身无法更新；而不同任务领域需要完全不同的记忆行为，手工定义的操作集无法覆盖所有场景。
- **核心问题**：能否将记忆操作本身提升为一个**可学习、可进化**的"技能"——系统不仅学习"何时使用哪种记忆操作"，还能学习"记忆操作本身该如何改进和扩展"？
- **方案**：`MemSkill` 将记忆操作建模为一个可进化的技能库 S = {s₁, s₂, ..., sₖ}，每个技能是包含描述、操作规范和约束条件的结构化文本；系统通过 **"学习使用技能"** 和 **"进化技能"** 两个交替过程实现自我进化。
- **组件**：记忆库（Memory Bank，每个 trace 对应一个记忆库）、技能库（Skill Bank，所有 trace 共享、可复用的记忆技能）、控制器、执行器、设计器。
- **Skill 结构**：
  - `description`：技能的嵌入和检索；
  - `content`：`When to use`（使用时机）、`How to apply`（操作方法）、`Constraints`（约束条件）；
  - 操作：`INSERT`（新增一条全新记忆）、`UPDATE`（修改已经存过的旧信息）、`DELETE`（删掉过时、矛盾的旧记忆）、`SKIP`（这段内容没用，啥也不存）。

## 20. 记忆系统评估

### 20.1 两条评估路线

**① 直接评估**：将记忆模块作为独立组件，直接测量其读写能力与内容质量。

- **主观评估**：基于人工标注判断记忆内容的质量。
  - 一致性（Coherence）：记忆是否与当前上下文相关；
  - 合理性（Rationality）：记忆内容是否符合常识。
- **客观评估**：基于数值指标进行自动化的量化比较。
  - 结果正确性（Correctness）—— Accuracy；
  - 引用准确性（Accuracy）—— F1-score；
  - 效率（Time & Hardware Cost）—— 延迟、显存。

**② 间接评估**：通过端到端 Agent 下游任务的完成效果来反推记忆模块的有效性。

- 对话任务 —— 一致性、参与度；
- 多源问答 —— 跨源信息整合能力；
- 长上下文应用 —— 超长文本中的信息定位与利用。

### 20.2 客观评估指标四大类

#### (1) 有效性

> 结果正确性关注"最终答案是否正确"，而引用准确性关注"中间推理依据是否恰当"。

| 指标 | 计算方法 | 评估目标 |
|---|---|---|
| 结果正确性（Result Correctness） | Accuracy | Agent 能否基于记忆正确回答预设问题 |
| 引用准确性（Reference Accuracy） | F1 | 检索到的记忆内容是否包含支撑答案的关键信息 |

#### (2) 检索质量

| 指标 | 说明 | 适用场景 |
|---|---|---|
| Hit Rate | 正确文档是否出现在检索结果中 | 粗粒度检索有效性 |
| MRR | 首个正确结果的倒数排名 | 关注排序质量 |
| NDCG@K | 归一化折损累积增益 | 综合评估排序质量与相关性 |
| Recall@K | 前 K 个结果中相关文档的比例 | 关注查全率 |

#### (3) 生成质量

| 指标 | 说明 |
|---|---|
| 上下文相关性（Context Relevance） | 检索内容与查询的相关程度，减少无关信息引入的处理开销 |
| 答案忠实度（Answer Faithfulness） | 生成答案是否忠实于检索到的上下文，避免幻觉 |
| 答案相关性（Answer Relevance） | 生成答案与原始问题的匹配程度 |

#### (4) 效率

| 指标 | 计算方法 | 说明 |
|---|---|---|
| 时间开销（Time Cost） | Δt = (1/M) Σ(t_end − t_start) | 包含记忆写入/管理（适配时间）与记忆读取（推理延迟） |
| 计算开销（Computation Overhead） | 峰值 GPU 显存分配 | 评估硬件资源消耗 |

### 20.5 记忆评估四步流程

1. **明确评估目标 —— "评什么？"**
   - 记忆形式：评估的是什么格式的记忆？
   - 功能维度：关注的是短期还是长期记忆？
   - 应用场景：面向问答、对话、代码生成还是复杂推理？
2. **选择评估策略 —— "怎么评？"**
   - 若目标是比较不同记忆机制的本质优劣 → 采用**直接评估**；
   - 若目标是验证记忆模块在完整系统中的实际贡献 → 采用**间接评估**；
   - 若缺乏客观真值或需要理解性分析 → 采用**主观评估**；
   - 若追求可复现、可比较的量化结果 → 采用**客观评估**。
3. **设计/选择评估指标 —— "用什么量？"**
4. **构建/选择 Benchmark —— "在什么上评？"**

> **对赛题②的落地建议**：正文第 12 节的指标（Recall@5 / MRR / NDCG@5 / 忠实度 / 引用准确率）已覆盖本节的"检索质量 + 生成质量"两类；可再补两项——**效率指标（Time Cost / Computation Overhead）**与**分记忆形式评估**（Token 级可读性 / 事实记忆召回 / 跨任务迁移），评估体系会更完整、更贴近赛题④的"四层指标体系"要求。
