# 第二部分：赛题②多模态记忆系统完整方案

## 4. 问题定义与目标拆解

### 4.1 一句话定义

构建一个**持久化、可检索、可更新**的多模态记忆系统，把散落在 **表格 / Markdown / PDF / 图像** 中的作战规划知识，统一解析、统一索引、统一检索，并以**带来源标注**的结果增强智戎系统的作战规划流程。

### 4.2 要解决的具体痛点

| 现状痛点 | 具体表现 | 本课题要达成的效果 |
|---|---|---|
| 只认字 | 图像被直接丢弃 | 图片被编码、可被文字查询召回 |
| 不识表 | 表格被拍平成字符串，行列关系丢失 | 保留表格结构，支持"参数类"精确检索 |
| 模态割裂 | 文本/表格/图片各查各的 | 一次查询跨模态统一召回 |
| 不可信 | 答案无来源 | 每个结论标注来源文件/页码，防幻觉 |
| 不可更新 | 知识变更要重建索引 | 支持增量入库、删除、更新 |

### 4.3 验收目标（建议自定量化指标）

- 支持 ≥4 类格式：MD、PDF、CSV/XLSX、PNG/JPG；
- 建库规模：≥ 100 个知识块（文本 40 + 表格 30 + 图片 30），可扩展；
- 检索指标：Recall@5 ≥ 0.7，MRR ≥ 0.5（先达成，再优化到 0.8/0.6）；
- 端到端延迟：单查询 < 3 秒（不含 LLM 生成），满足 30 秒航线重算的时延预算；
- 答案必须带来源引用，引用准确率 ≥ 90%；
- 完成与智戎规划链路的一处真实集成调用。

## 5. 起步必学的基础知识

> 每个概念按"是什么 → 干什么用 → 怎么上手"讲解。建议配合第 15 节的学习资源，2 周内补齐。

### 5.1 向量与 Embedding（嵌入）

**是什么**：把文本/图片变成一串数字（向量），语义相近的内容向量距离近。

```
"99A坦克的装甲厚度"  → [0.12, -0.34, 0.56, ...]
"99A坦克侧面照片"    → [0.11, -0.32, 0.55, ...]   ← 距离近
"空军运输机参数"     → [0.88, 0.21, -0.62, ...]   ← 距离远
```

**本课题用到的嵌入模型**：

| 模型 | 处理对象 | 特点 | 用途 |
|---|---|---|---|
| BGE-M3（BAAI） | 文本/表格文本 | 中文强、支持稠密+稀疏向量 | 文本与表格文本通道 |
| CLIP / SigLIP | 图片（及文本） | 图文对齐 | 图片通道 |
| Chinese-CLIP | 中文图文 | 中文检索图片更准 | 备选 |
| BLIP-2 / Qwen2.5-VL | 图片→描述 | 生成图片 caption | 图片文本化增强 |

**上手练习**：用 `sentence-transformers` 加载 BGE-M3，给 10 句话编码，算两两余弦相似度，观察"同类近、异类远"。

### 5.2 向量数据库

**是什么**：专存向量并做"最近邻检索"的数据库。

**选型建议**：
- 先用 **Chroma**：Python 原生、可持久化、几行代码跑通，适合原型；
- 数据量大后换 **Milvus/Qdrant**：支持更多索引类型与过滤；
- **FAISS** 只是算法库，适合做底层实验对比。

**核心操作只有四个**：add（写）、query（查）、update（改）、delete（删），再加上**元数据过滤**（例如"只查表格"）。

### 5.3 RAG（检索增强生成）

**标准流程**：
```
用户问题 → 向量化 → 向量库检索 Top-K → 组装成上下文 Prompt → LLM 生成答案（带引用）
```

**本课题的"多模态 RAG"扩展**：入库时把 PDF 拆成文本块/表格/图片三类，分别编码入库；查询时统一检索、统一组装、统一生成。

### 5.4 分块（Chunking）与文档解析

- **分块**：长文档切成合适小块，常见 300–1000 字 + 10% 重叠；本课题中"表格一块、图片一块、文本按段落块"。
- **解析库**：PyMuPDF（fitz）取文本/图片，pdfplumber/Camelot 取表格；复杂中文 PDF 优先用 MinerU / Marker。

### 5.5 开发框架

| 框架 | 特点 | 本课题定位 |
|---|---|---|
| LangChain | 生态最全，链式组装 | 快速搭 RAG 骨架 |
| LlamaIndex | 索引能力强，多模态节点支持好 | 多模态索引首选 |
| 原生 Python | 完全可控 | 论文实验与定制创新部分 |

**建议**：先用 LangChain/LlamaIndex 快速跑通 MVP，再逐步用原生 Python 重写关键环节（重写过程本身就是"研究"）。

### 5.6 需要掌握的 Python 能力

- 文件/目录处理（pathlib）、JSON、日志；
- numpy/PIL 基础（图片读写、resize）；
- PyTorch 只需会 `model.encode`、`no_grad`、CPU/GPU 切换，不必会训练（创新点阶段再学微调）；
- 会用 conda/pip 装环境、用 git 管代码。

## 6. 符合题目的前沿技术与研究

> 这些技术都能直接"装"进本课题：**解析、编码、检索、生成**四个层面，每一层选 1–2 个前沿点做对比实验，论文的"相关工作"和"实验"部分就丰满了。

### 6.1 多模态嵌入与对齐

**(1) CLIP / SigLIP / Chinese-CLIP**
- CLIP（OpenAI 2021）：对比学习把图文映射到同一空间，是多模态检索基石；
- SigLIP（Google 2023）：用 Sigmoid Loss 训练更稳定，零样本检索更强——**推荐作为图片编码器**；
- Chinese-CLIP（OFA-Sys）：中文图文对齐，适合中文装备图/态势图。

**(2) BLIP-2 / Florence-2 / Qwen2.5-VL（图片→文本）**
- BLIP-2：轻量、开源、适合离线生成 caption；
- Florence-2（微软）：统一多任务视觉模型，可做描述、OCR、目标检测；
- Qwen2.5-VL / GPT-4o：视觉问答能力强，可用于"看图回答"的生成端；
- **本课题用法**：`图片 = CLIP全局向量 + BLIP描述向量 + OCR文字向量`，三维度联合提升召回。

**(3) ColPali / ColQwen —— Late Interaction 多模态检索（2024 前沿）**
- 传统做法"整页截图→单向量"信息损失大；
- ColPali 用视觉语言模型对页面多个 patch 输出多向量，查询与文档做 Late Interaction（类似 ColBERT），对表格、复杂版式的检索效果显著提升；
- **本课题定位**：进阶路线。先做单向量双通道方案（稳），再用 ColPali/ColQwen 做对比实验或直接作为"视觉通道 2.0"，是很强的创新点。

**(4) 领域对比学习微调（LoRA）**
- 通用 CLIP 对军事术语、装备图对齐效果一般；
- 用少量（装备图片, 中文描述）对，以 LoRA 微调 SigLIP 图文编码器；
- 属于"真研究"工作：**工程期前两周不做**；第 3 周若主创新点已收口、且显存允许，再用 1–2 天尝试；来不及则写入论文"未来工作"。

### 6.2 多模态文档解析

| 工具/模型 | 亮点 | 本课题用途 |
|---|---|---|
| PyMuPDF + pdfplumber/Camelot | 轻量、可控 | 基础 PDF 拆解 |
| Unstructured | 万能文档解析框架 | 快速接入多格式 |
| Marker | PDF→Markdown，保留结构 | 中文 PDF 文本/表格 |
| MinerU（上海 AI Lab） | PDF→Markdown/JSON，中文表格强 | **复杂作战文书首选** |
| GOT-OCR 2.0 | 通用 OCR，版面/表格/公式 | 扫描件、图片文字 |
| PaddleOCR | 中文 OCR 成熟 | 态势图标注文字提取 |

### 6.3 表格感知的 RAG

| 工作 | 核心思想 | 借鉴点 |
|---|---|---|
| TableRAG (2024) | 用 LLM 按查询挑表格的行/列，减少 token | 表格入库时同时存 schema（列名+类型） |
| TRICE 等查询感知表格检索 | 让查询与表格结构交互 | 检索前先"模态路由"到表格通道 |
| 表格双通道编码（工程实践） | Markdown 文本向量 + 渲染图片向量 | 本课题核心方法，可做消融实验 |

**结论**：表格不要只转纯文本。至少保留三层信息：①Markdown 结构文本；②渲染图片的视觉布局；③列名/类型的 schema。

### 6.4 高级 RAG 策略

| 技术 | 思想 | 本课题落地 |
|---|---|---|
| Self-RAG | 模型自己判断要不要检索、检索结果够不够 | 生成端加"自我评估"步骤 |
| Corrective RAG (CRAG) | 检索结果差就纠错/重查 | 对低分结果自动改写查询重检 |
| Adaptive RAG | 按问题复杂度选策略 | 简单问题直答，复杂问题多路检索 |
| HyDE | 先让 LLM 生成假设答案再拿它检索 | 对模糊指挥意图有效 |
| GraphRAG/LightRAG | 图上多跳推理 | 与本课题互补：多模态实体可挂到图上 |

### 6.5 可解释性与知识锚定

- **引用溯源（attribution）**：每个检索块带 `source + page + 模态 + 行号`，生成答案强制标注 `[来源: xxx.pdf 第3页]`；
- **知识锚定约束落地**：系统提供 `knowledge_filter` 接口，只允许从指定库文件集合检索，未命中时明确回答"库中无依据"，从机制上防编造；
- 这也是课程最看重的约束之一，把它做成显式功能比做成口头承诺强得多。

### 6.6 多模态检索评估

- 检索层：Recall@K、MRR、NDCG@K（分模态统计）；
- 生成层：Faithfulness（忠实度）、Answer Relevance、Correctness（可用 RAGAS 或 LLM-as-Judge）；
- 跨模态层：Cross-modal Recall（文本查询能否召回图片/表格）、Modality Coverage；
- 系统层：端到端延迟、建库成本、增量更新时间。

> 更完整的"记忆系统评估"指标框架（直接/间接评估、主观/客观指标、检索质量/生成质量/效率四大类、记忆形式×评估维度、Benchmark 分类），见**第三部分第 20 节**。

### 8.2 解析层实现

```python
# src/parsers/pdf_parser.py
"""PDF 拆解：文本块 + 表格 + 图片。"""
import fitz                       # PyMuPDF
import pdfplumber
import io
from PIL import Image


def parse_pdf(path: str):
    chunks = []

    # ---- 文本与嵌入图片：用 PyMuPDF ----
    doc = fitz.open(path)
    for page_no, page in enumerate(doc, start=1):
        # 文本块（block[6]==0 是文本块）
        for block in page.get_text("blocks"):
            text = (block[4] or "").strip()
            if len(text) >= 10:   # 过滤页眉页脚碎片
                chunks.append({
                    "modality": "text",
                    "text": text,
                    "image_bytes": None,
                    "raw": None,
                    "metadata": {"source": path, "page": page_no}
                })
        # 嵌入图片
        for img_index, img in enumerate(page.get_images(full=True)):
            try:
                base = doc.extract_image(img[0])
                if base and base["image"]:
                    chunks.append({
                        "modality": "image",
                        "text": "",                      # 编码阶段再补 caption/OCR
                        "image_bytes": base["image"],
                        "raw": None,
                        "metadata": {"source": path, "page": page_no,
                                     "img_index": img_index}
                    })
            except Exception:
                continue
    doc.close()

    # ---- 表格：用 pdfplumber ----
    with pdfplumber.open(path) as pdf:
        for page_no, page in enumerate(pdf.pages, start=1):
            for t_idx, table in enumerate(page.extract_tables()):
                if table and len(table) >= 2:
                    # 清理 None 单元格
                    clean = [[c if c is not None else "" for c in row]
                             for row in table]
                    chunks.append({
                        "modality": "table",
                        "text": "",                       # 编码阶段生成 Markdown+描述
                        "image_bytes": None,              # 编码阶段渲染图片
                        "raw": {"rows": clean},
                        "metadata": {"source": path, "page": page_no,
                                     "table_idx": t_idx,
                                     "schema": clean[0]}
                    })
    return chunks
```

```python
# src/parsers/table_parser.py
"""表格 → 三种表示：Markdown(文本通道) + 描述 + 渲染图片(视觉通道)。"""
import io
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

matplotlib.rcParams["font.sans-serif"] = ["SimHei", "Microsoft YaHei", "DejaVu Sans"]
matplotlib.rcParams["axes.unicode_minus"] = False


def rows_to_markdown(rows):
    """二维列表 → Markdown 表格。"""
    header = [str(c) for c in rows[0]]
    md = "| " + " | ".join(header) + " |\n"
    md += "| " + " | ".join(["---"] * len(header)) + " |\n"
    for row in rows[1:]:
        cells = [str(c).replace("\n", " ") for c in row]
        md += "| " + " | ".join(cells) + " |\n"
    return md


def rows_to_description(rows, name=""):
    """自然语言描述：增强语义检索。"""
    header = [str(c) for c in rows[0]]
    desc = f"表格「{name}」，共{len(rows)-1}行、{len(header)}列。" \
           f"列名：{'、'.join(header)}。"
    if len(rows) - 1 <= 15:      # 小表直接写内容
        lines = ["；".join(f"{header[i]}={row[i]}" for i in range(min(len(header), len(row))))
                 for row in rows[1:]]
        desc += "\n内容：" + "。".join(lines) + "。"
    return desc


def rows_to_image(rows, max_col_chars=20):
    """表格渲染成 PNG 字节流（供图片编码器使用）。"""
    # 截断超长单元格，避免图片过大
    clipped = []
    for row in rows:
        clipped.append([(str(c)[:max_col_chars] + "..") if len(str(c)) > max_col_chars
                        else str(c) for c in row])
    df = pd.DataFrame(clipped[1:], columns=clipped[0])
    fig, ax = plt.subplots(figsize=(max(8, len(clipped[0]) * 1.8),
                                    max(2, len(clipped) * 0.45)))
    ax.axis("off")
    tab = ax.table(cellText=df.values, colLabels=df.columns,
                   cellLoc="center", loc="center")
    tab.auto_set_font_size(False)
    tab.set_fontsize(9)
    tab.scale(1, 1.4)
    buf = io.BytesIO()
    plt.savefig(buf, format="png", dpi=150, bbox_inches="tight",
                facecolor="white")
    plt.close(fig)
    return buf.getvalue()


def finalize_table_chunk(chunk):
    """给表格 chunk 补上 text 与 image_bytes。"""
    rows = chunk["raw"]["rows"]
    name = chunk["metadata"]["source"]
    chunk["text"] = rows_to_description(rows, name) + "\n\n" + rows_to_markdown(rows)
    chunk["image_bytes"] = rows_to_image(rows)
    return chunk
```

```python
# src/encoders/multimodal_encoder.py
"""文本用 BGE-M3；图片用 SigLIP；两者都有就融合。"""
import io
import torch
from PIL import Image
from sentence_transformers import SentenceTransformer
from transformers import AutoProcessor, AutoModel


class MultimodalEncoder:
    def __init__(self,
                 text_model_name="BAAI/bge-m3",
                 image_model_name="google/siglip-base-patch16-224"):
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        print(f"使用设备: {self.device}")

        self.text_model = SentenceTransformer(text_model_name, device=self.device)

        # SigLIP 用 transformers 加载
        self.img_proc = AutoProcessor.from_pretrained(image_model_name)
        self.img_model = AutoModel.from_pretrained(image_model_name).to(self.device)
        self.img_model.eval()

    def encode_text(self, text):
        if not text or not text.strip():
            return None
        v = self.text_model.encode(text, normalize_embeddings=True)
        return torch.tensor(v, dtype=torch.float32, device=self.device)

    @torch.no_grad()
    def encode_image(self, image_bytes):
        if not image_bytes:
            return None
        img = Image.open(io.BytesIO(image_bytes)).convert("RGB")
        inputs = self.img_proc(images=img, return_tensors="pt").to(self.device)
        v = self.img_model.get_image_features(**inputs)
        v = v / v.norm(dim=-1, keepdim=True)
        return v.squeeze(0)

    def encode_chunk(self, chunk):
        """返回 {id, vector}；文本+图片同时存在时做归一化平均融合。"""
        vt = self.encode_text(chunk.get("text", ""))
        vi = self.encode_image(chunk.get("image_bytes"))
        if vt is not None and vi is not None:
            # 维度可能不同：线性投影到统一维度（本项目统一取 512 或 1024）
            d = min(vt.shape[0], vi.shape[0])
            vt, vi = vt[:d], vi[:d]
            v = (vt / vt.norm() + vi / vi.norm())
            v = v / v.norm()
        elif vt is not None:
            v = vt
        elif vi is not None:
            v = vi
        else:
            return None
        return {"id": f"{chunk['metadata']['source']}#{chunk['metadata'].get('page',1)}",
                "vector": v.cpu().numpy().tolist()}
```

```python
"""Chroma 封装：写、查、过滤、统计、删除。"""
import chromadb


class VectorStore:
    def __init__(self, path="./chroma_db", collection="mm_memory"):
        self.client = chromadb.PersistentClient(path=path)
        self.col = self.client.get_or_create_collection(
            name=collection, metadata={"hnsw:space": "cosine"})

    def upsert(self, records):
        """records: [{id, vector, text, metadata}]"""
        if not records:
            return
        self.col.upsert(
            ids=[r["id"] for r in records],
            embeddings=[r["vector"] for r in records],
            documents=[r["text"][:1000] for r in records],  # 展示用
            metadatas=[r["metadata"] for r in records],
        )

    def search(self, query_vector, top_k=5, modality=None, source=None):
        where = {}
        if modality:
            where["modality"] = modality
        if source:
            where["source"] = source
        res = self.col.query(query_embeddings=[query_vector], n_results=top_k,
                             where=where or None)
        out = []
        ids = res.get("ids") or [[]]
        for i, cid in enumerate(ids[0]):
            out.append({
                "id": cid,
                "text": (res["documents"][0][i] if res.get("documents") else ""),
                "metadata": (res["metadatas"][0][i] if res.get("metadatas") else {}),
                "distance": (res["distances"][0][i] if res.get("distances") else None),
            })
        return out

    def delete_by_source(self, source):
        hit = self.col.get(where={"source": source})
        if hit["ids"]:
            self.col.delete(ids=hit["ids"])

    def stats(self):
        data = self.col.get()
        mod_cnt = {}
        for m in (data.get("metadatas") or []):
            k = m.get("modality", "unknown")
            mod_cnt[k] = mod_cnt.get(k, 0) + 1
        return {"total": len(data.get("ids") or []), "by_modality": mod_cnt}
```

```python
"""模态路由：先用关键词规则，后期升级为 LLM 分类。"""
TABLE_WORDS = ["参数", "数据", "指标", "性能", "编制", "数量", "多少", "对比",
               "型号", "重量", "速度", "射程", "厚度", "列表", "表"]

def route_modality(query: str):

        return "table"
    if any(w in query for w in IMAGE_WORDS):
        return "image"
    return None   # 不确定则全模态检索

    """简单版查询重写：合并短问题+去除口头禅；工程期第 2 周可换成 LLM 改写。"""
    q = query.strip().rstrip("？?")
    for w in ["请问", "告诉我", "帮我查一下", "我想知道"]:
        q = q.replace(w, "")
    return q or query
```

```python
# src/retrieval/hybrid_retriever.py
"""向量检索 + BM25 关键词检索，RRF 融合。"""
import jieba
from rank_bm25 import BM25Okapi


class HybridRetriever:
    def __init__(self, vector_store, encoder):
        self.store = vector_store
        self.encoder = encoder
        self.bm25 = None
        self.bm25_ids = []

    def build_bm25(self):
        data = self.store.col.get()
        docs = data.get("documents") or []
        self.bm25_ids = data.get("ids") or []
        self.bm25 = BM25Okapi([list(jieba.cut(d)) for d in docs])

    def search(self, query, top_k=5, modality=None,
               vec_w=0.6, bm25_w=0.4):
        qv = self.encoder.encode_text(query).cpu().numpy().tolist()

        # 路1：向量（多取，供融合）
        vec_hits = self.store.search(qv, top_k=top_k * 3, modality=modality)

        # 路2：BM25（先全量打分再按模态过滤）
        scores = self.bm25.get_scores(list(jieba.cut(query))) if self.bm25 else []
        ranked_idx = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)
        bm_hits = {}
        for idx in ranked_idx:
            if len(bm_hits) >= top_k * 3:
                break
            cid = self.bm25_ids[idx]
            meta = {}
            # 从向量库取元数据做模态过滤
            got = self.store.col.get(ids=[cid])
            if got.get("metadatas"):
                meta = got["metadatas"][0]
            if modality and meta.get("modality") != modality:
                continue
            bm_hits[cid] = {"id": cid, "bm25_score": float(scores[idx]),
                            "metadata": meta}

        # RRF 融合：score = w1/(k+r1) + w2/(k+r2)
        k = 60
        fused = {}
        for rank, h in enumerate(vec_hits, start=1):
            fused[h["id"]] = {"id": h["id"], "metadata": h["metadata"],
                              "text": h["text"], "final": vec_w / (k + rank)}
        for rank, (cid, h) in enumerate(bm_hits.items(), start=1):
            if cid in fused:
                fused[cid]["final"] += bm25_w / (k + rank)
            else:
                fused[cid] = {"id": cid, "metadata": h["metadata"],
                              "text": "", "final": bm25_w / (k + rank)}
        return sorted(fused.values(), key=lambda x: x["final"], reverse=True)[:top_k]
```

```python
# src/retrieval/reranker.py
"""可选精排：bge-reranker-v2-m3。"""
from sentence_transformers import CrossEncoder


class Reranker:
    def __init__(self, model="BAAI/bge-reranker-v2-m3"):
        self.model = CrossEncoder(model)

    def rerank(self, query, hits, top_k=5):
        if not hits:
            return hits
        pairs = [(query, h.get("text", "")) for h in hits]
        scores = self.model.predict(pairs)
        for h, s in zip(hits, scores):
            h["rerank"] = float(s)
        return sorted(hits, key=lambda x: x.get("rerank", 0), reverse=True)[:top_k]
```

```python
# src/retrieval/context_builder.py
"""把多模态结果组装成带来源标注的上下文。"""
ICON = {"text": "📄", "table": "📊", "image": "🖼️"}


def build_context(hits, max_len=4000):
    parts, total = [], 0
    for h in hits:
        meta = h.get("metadata", {})
        m = meta.get("modality", "text")
        src = meta.get("source", "未知")
        page = meta.get("page", "?")
        head = f"[{ICON.get(m,'')} {m.upper()} 来源: {src} 第{page}页]"
        block = head + "\n" + (h.get("text") or "")
        if total + len(block) > max_len:
            block = block[:max_len - total] + "…"
            parts.append(block)
            break
        parts.append(block)
        total += len(block)
    return "\n\n---\n\n".join(parts)
```

## 9. 如何"高标准"实现

> "高标准"不是把每个组件都换成最贵的模型，而是**每个环节都有明确的质量目标、有度量、有对照实验**。下面按层给标准。

### 9.1 解析层高标准

| 维度 | 普通做法 | 高标准做法 |
|---|---|---|
| PDF 文本 | 整页提取 | 按块提取 + 过滤页眉页脚 + 段落级分块（300–800 字，10% 重叠） |
| PDF 表格 | 只提取文本 | 表格还原成二维列表，生成 Markdown + 描述 + 渲染图，保留 page/行号 |
| 复杂表格 | 拍平成一串 | 检测合并单元格/多级表头；用 MinerU 兜底 |
| 图片 | 忽略 | 原图 + OCR 文字 + BLIP 描述三件套 |
| 中文 OCR | 无 | PaddleOCR（或 GOT-OCR2），结果作为图片块的 text 字段 |
| 质量校验 | 无 | 对每个解析块记录 `解析置信度/来源页码`，抽检 20% 人工核对 |

**验收指标**：解析层丢块率 < 5%；表格行列还原准确率 > 90%（小样本人工核对）。

### 9.2 编码层高标准

1. **文本与图片统一维度**：BGE-M3 与 SigLIP 输出维度不同，必须投影到同一维度再融合（或分别建集合、检索后融合——更推荐"分别建集合"方案，避免硬拼维度）；
2. **表格双通道**：`表格向量 = 文本通道(Markdown+描述) + 视觉通道(渲染图)`，查询分别召回后 RRF 融合；
3. **图片三表征**：`图片向量集合 = {CLIP全局, BLIP描述, OCR文本}`，同一图片可被三种查询路径命中；
4. **归一化**：所有向量 L2 归一化，配合余弦距离；
5. **Batch 编码 + 进度条**：千级规模也能 10 分钟内建完库。

### 9.3 检索层高标准

- **多路召回**：向量（稠密）+ BM25（稀疏，中文用 jieba 分词）+ 可选 schema 过滤；
- **模态路由**：关键词规则（初版）→ LLM 分类器（进阶，见创新点）；
- **重排序**：bge-reranker-v2-m3 对 Top-30 精排到 Top-5；
- **元数据过滤**：`modality / source / page / schema` 都要支持；
- **结果多样性**：最终 Top-K 中强制保留不同模态（例如至少 1 文本、1 表格、1 图片，当存在时），避免"全是文本"。

### 9.4 生成层高标准

- 系统提示词写死 4 条规则（见 8.6）：只用参考资料、强制引用、无依据明说、模态优先级；
- 每个结论带 `[编号]`，引用列表随答案返回，前端可点击跳转；
- **引用校验**：用脚本检查"答案中出现的编号 ⊆ 提供的编号"，编号错引 = 0 分；
- **防幻觉二次检查**：生成后用第二个 LLM 判断"答案是否只基于参考资料"（Self-RAG 思想）。

### 9.5 工程与集成高标准

- **接口化**：`index/update/delete/query/stats` 五个 API，智戎系统通过 HTTP 或 Python 包调用；
- **知识锚定接口**：`query(..., allowed_sources=[...])` 只检索允许的文件集合，直接落实"只许用库里的数据"；
- **增量更新**：文件修改后按 `source` 先删后建；向量库持久化保存；
- **日志与可复现**：记录模型版本、分块参数、随机种子；所有实验脚本带 `--config`；
- **单元测试**：解析/编码/存储/检索每层 ≥ 5 个测试用例；
- **演示界面**：Streamlit 单页应用（上传文件→建库→提问→显示答案+引用+命中图片），直接用作答辩视频素材。

```python
# demo/streamlit_app.py（骨架）
import streamlit as st
from src.main import MultimodalMemorySystem

st.set_page_config(page_title="多模态记忆系统演示", layout="wide")
sys = MultimodalMemorySystem({"use_rerank": True})

with st.sidebar:
    st.header("知识入库")
    files = st.file_uploader("上传 MD/PDF/CSV/XLSX/图片",
                             accept_multiple_files=True)
    if st.button("入库") and files:
        for f in files:
            tmp = f"/tmp/{f.name}"
            with open(tmp, "wb") as w:
                w.write(f.getbuffer())
            n = sys.index_file(tmp)
            st.success(f"{f.name}: {n} 块")

q = st.text_input("向记忆系统提问（例：99A坦克火力与防护参数）")
if q:
    r = sys.query(q, top_k=5)
    st.subheader("答案")
    st.write(r.get("answer", "（此处接入生成层）"))
    st.subheader("引用来源")
    for i, (cid, h) in enumerate(zip(r["cites"], r["hits"]), start=1):
        st.markdown(f"**[{i}]** {r['cites'][cid]} — {h['metadata'].get('modality')}")
    st.subheader("检索上下文")
    st.text(r["context"])
```

## 10. 优化与增强清单

> 按"性价比"排序，建议逐项做，每做一项跑一次评估并记录增量（这就是实验章节的素材）。

### 10.1 检索端优化（性价比最高）

| 优化项 | 做法 | 预期收益 | 难度 |
|---|---|---|---|
| 混合检索 | 稠密向量 + BM25 + RRF | Recall +10~20% | ★★ |
| 重排序 | bge-reranker-v2-m3 | MRR +10~15% | ★★ |
| 查询重写 | LLM 把口语问题改写成检索式 | Recall +5~10% | ★★ |
| 查询扩展/HyDE | 生成假设答案再检索 | 模糊意图 Recall+ | ★★★ |
| 模态路由 | 规则→LLM 两级路由 | 精确率提升 | ★★★ |
| 多模态结果多样化 | 最终 Top-K 跨模态配额 | 覆盖度提升 | ★★ |
| 负采样难例调参 | 用检索失败的 query 调分块/阈值 | 持续提升 | ★★★ |

### 10.2 数据与索引端优化

| 优化项 | 做法 |
|---|---|
| 语义分块 | 按标题/语义边界切分，替代固定段落 |
| 表格行级索引 | 大表（>50 行）按行切片，每片带表头上下文 |
| schema 索引 | 建一个独立的"列名→所属表"倒排索引，支持"查哪个表有射程列" |
| 数值范围索引 | 解析数值列，支持"重量>50吨"结构化过滤 |
| 图片多尺度 | 同一图片存原图向量 + 局部裁剪向量（态势图局部目标） |
| 元数据完备化 | 时间、密级、任务背景写入 metadata |

### 10.3 记忆管理端优化

| 优化项 | 做法 |
|---|---|
| 增量更新 | 文件哈希变化检测 → 按 source 删旧建新 |
| 记忆衰减 | 长期未被命中的块降低检索权重（加 metadata.weight） |
| 记忆强化 | 被引用进规划的块提升权重 |
| 冲突处理 | 同一装备的新旧参数冲突时，保留版本号并标记时效 |
| 冷启动 | 系统启动时自动重建 BM25、校验向量库一致性 |

### 10.4 生成端优化

| 优化项 | 做法 |
|---|---|
| Self-RAG 反射 | 生成后自评"是否需要检索/检索是否足够"，不够就改写重检 |
| Corrective RAG | 低分检索结果触发自动改写查询重检 |
| 表格问答 | 检索到大表时，让 LLM 先选相关行/列再生成（TableRAG 思想） |
| 视觉答案 | 命中图片时把图片直接交给 Qwen2.5-VL/GPT-4o，产出"看图说话"答案 |
| 结构化输出 | 参数类问题输出 JSON（{参数名:值, 引用:[]}），可直接供技能池计算 |

### 10.5 系统性能优化

| 优化项 | 做法 |
|---|---|
| 缓存 | 相同 query 的向量化结果 LRU 缓存 |
| 批量/异步 | 建库批处理 + 编码异步化 |
| 向量量化 | 用 int8/PQ 压缩，减少存储、加速检索 |
| 预加载 | 常驻模型，避免每次冷启动 |
| 时延预算报告 | 统计 解析/编码/检索/重排/生成 各段时延（答辩必问） |

## 11. 可选的创新点

> 创新点写法公式：**"现有方法在 X 上不行 → 我提出 Y → 在 Z 数据集上验证了提升"**。
> 建议主攻 1 个 + 辅做 2 个，不要贪多。

### 创新点 A：表格"结构-语义-视觉"三通道索引（首选主创新）

- 现有 RAG 把表格当纯文本，行列关系丢失；
- 提出：`Markdown 文本通道 + 渲染图视觉通道 + Schema(列名/类型) 通道`，再加**行级切片 + 数值范围过滤**；
- 验证：构造 30 个表格查询（点查询/范围查询/对比查询），与"纯文本 RAG"对比 Recall/MRR；
- 难度低、工作量可控、消融清晰，非常适合第一学期课题。

### 创新点 B：面向作战查询的"两级模态路由"

- 第一级规则快速分类（表/图/文本），第二级用 LLM 抽取"查询意图 + 目标实体 + 数值约束"；
- 例如"找出射程大于 100 公里的导弹型号" → 路由到表格通道并带上数值约束；
- 验证：对比无路由/纯规则路由/规则+LLM 路由三组。

### 创新点 C：图片"全局视觉 + 语义描述 + OCR 文本"多表征融合检索

- 单 CLIP 向量对中文军事图片召回差；
- 提出三表征 + RRF 融合，并记录每种表征对最终召回的贡献（消融）；
- 可进一步用 Qwen2.5-VL 替换 BLIP 生成更专业的 caption。

### 创新点 D：LoRA 微调 SigLIP 的军事领域图文对齐（进阶研究型）

- 收集/构造 500~2000 对（装备图、中文描述）数据（可从公开装备图册、课程知识库整理）；
- LoRA 微调 SigLIP，冻结主干，只训低秩适配器；
- 验证：微调前后 Cross-modal Recall 提升；
- 这是"真研究"含量最高的点，也是老师最可能给高分的点，但留足失败时间（可先做 A 保底）。

### 创新点 E：带知识锚定约束的可解释多模态 RAG

- 把"只许用库里数据"做成系统机制：`allowed_sources` 过滤 + 生成层强制引用 + 引用编号自动校验；
- 提出一个简单的**引用忠实度指标**（答案结论与引用块是否支持关系成立，可用 LLM-as-Judge 打分）；
- 与赛题④评估组联动，提供"多模态记忆系统评测子集"。

### 创新点 F：ColPali/ColQwen Late Interaction 视觉检索通道（前沿对比型）

- 用 ColQwen2 对整页 PDF/表格截图做多向量检索，与"单向量双通道"方案对比；
- 若效果提升，可作为"视觉通道 2.0"写入论文；若 GPU 不足，可只做 10 页小规模对比实验；
- 论文价值高，但依赖显存（建议 ≥16GB，或租卡/用校园集群）。

### 创新点组合建议

| 目标 | 组合 |
|---|---|
| 稳扎稳打（保底 85 分） | A + B + E |
| 均衡进取（冲 90+） | A + C + E + D(可选) |
| 前沿激进（冲高分但风险大） | A + F + D |

### 12.2 指标与计算

- **Recall@5**：相关块是否出现在 Top-5；
- **MRR**：第一个相关块排名的倒数的平均；
- **NDCG@5**：考虑排序位置；
- **分模态 Recall**：表格查询/图片查询单独统计（答辩重点）；
- **忠实度**：`引用块支持答案的比例`，用 LLM-as-Judge 或人工 30 条抽样；
- **引用准确率**：答案中的引用编号是否都存在且对应正确。

> 本节指标对应讲义的"检索质量 + 生成质量"两大类；建议再补**效率（Time Cost / Computation Overhead）**与**分记忆形式评估**两维，详见**第三部分第 20 节**。

```python
# eval/metrics.py（核心逻辑）
def recall_at_k(relevant, retrieved, k=5):
    return int(any(r in retrieved[:k] for r in relevant))

def mrr(relevant, retrieved):
    for rank, r in enumerate(retrieved, start=1):
        if r in relevant:
            return 1.0 / rank
    return 0.0
```

## 13. 基于代码包的 2–3 周工程计划（2人团队）

> 前提：**老师会发代码包**（预计包含文本 RAG / 检索 / 生成 / 评估的基线工程）；**团队 2 人**；**完整工程时间 2–3 周**。
> 本计划按 21 天（3 周）编排，并附 14 天（2 周）压缩版。前置学习（第 5、6 节知识）应在工程期开始前完成，不计入这 2–3 周。

### 13.0 总体策略：三条铁律

1. **先跑通老师的代码包，再动手改**——永远保留一个可运行的基线版本，任何新功能都在基线之上"增量添加"，不推倒重写；
2. **接口先行、双人并行**——第 1 天冻结 `chunk` 数据模型与 `VectorStore` 的接口，之后两人各自开发互不阻塞；
3. **演示优先、创新其次**——先保"三模态召回 + 带引用回答 + 集成调用"的验收底线，再有余力做创新点；任何做不完的创新一律降级为"未来工作"。

### 13.0.1 第 0 天：代码包基线盘点（拿到代码包立刻做）

| 盘点项 | 要确认什么 | 记录格式 |
|---|---|---|
| 能否跑通 | 按 README 从零装环境并跑通示例 | ✅/❌ + 报错 |

## 14. 常见坑与避坑指南

### 14.1 环境类
| 坑 | 现象 | 对策 |
|---|---|---|
| CUDA 与 torch 不匹配 | GPU 不可用 | 先 `nvidia-smi` 看 CUDA 版本，再选对应 torch |
| 模型下载失败 | 连接 HuggingFace 超时 | `export HF_ENDPOINT=https://hf-mirror.com` |
| 显存不足 | SigLIP/ColPali OOM | 换 `siglip-base-patch16-224`；ColPali 用 CPU/小 batch 或放弃 |
| 中文字体乱码 | 表格渲染图全是方块 | 安装 SimHei/微软雅黑，配置 matplotlib 字体 |

### 14.2 解析类
| 坑 | 现象 | 对策 |
|---|---|---|
| 扫描版 PDF 无文本 | 提取为空 | 走 OCR（PaddleOCR/GOT-OCR2），并标记 `ocr=True` |
| 表格提取错乱 | 行列错位 | 换 Camelot/MinerU；复杂表人工标注后用规则修正 |
| 页眉页脚混入 | 检索到"第 1 页"垃圾块 | 按坐标/长度过滤 |
| 图片被压缩 | PDF 内嵌图分辨率低 | 设置提取 DPI 或保留原图 |

### 14.3 检索类
| 坑 | 现象 | 对策 |
|---|---|---|
| 中文查询命中差 | 嵌入模型不匹配 | 换 BGE-M3 / bge-large-zh；检查是否归一化 |
| 表格查询全错 | 表格被拍平 | 做双通道 + schema；小表全文、大表行级切片 |
| 图片召回差 | CLIP 中文弱 | 加 BLIP 中文 caption + OCR 文本通道 |
| 检索"一边倒" | 全是文本结果 | 加跨模态配额/多样性重排 |

### 14.4 生成与实验类
| 坑 | 现象 | 对策 |
|---|---|---|
| 答案幻觉 | 引用查无实据 | 生成层强约束 + 引用校验脚本 |
| 实验不可复现 | 两次结果不同 | 固定随机种子、记录模型/参数版本 |
| 指标虚高 | 测试集泄漏进知识库 | 测试集与建库数据严格隔离 |
| 演示翻车 | 现场网络/API 失败 | 本地部署 LLM 或提前录视频兜底 |

### 14.5 项目管理类
| 坑 | 现象 | 对策 |
|---|---|---|
| 贪多创新点 | 每个都做一半 | 主攻 1 个，其余降级 |
| 论文拖到最后 | 8000 字写不完 | 冲刺期每天收工时写 300–500 字素材，D19 前完成初稿 |
| 代码无法复现 | 换机器跑不起来 | 从 D1 起维护 README 和依赖清单，D20 换环境验收 |
| 两人分工互相等待 | 一方被另一方阻塞 | 接口 D1 冻结；B 先用样例 chunk 开发；每天 15 分钟站会；卡点超 2 小时合署解决 |

## 附：原文档结语（针对赛题②）

## 结语：给你的三个建议

1. **第 1 周（前 5 天）必须做出 MVP**——以老师代码包为基线，哪怕很简陋，先让"文本/表格/图片都能被查出来"这件事发生，后面的所有优化才有意义；
2. **把每一次改动都变成实验数据**——换模型、加分块、上重排，各跑一遍 30 题测试集并记录，这就是 8000 字论文最扎实的部分；
3. **创新点要"小而实"**——优先做"表格三通道索引"（创新点 A）+ "知识锚定溯源"（创新点 E），这两个与课程约束绑定最紧，也最不容易被质询问倒。

祝你顺利拿下赛题②，做出一个老师认可、自己也骄傲的多模态记忆系统！
