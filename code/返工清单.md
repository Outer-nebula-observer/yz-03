## 0. 为什么现在不能直接接入（两组共性问题）

宿主侧的注册逻辑（server/engines/memory_plugin_registry.py 的 discover_plugins()）是：

1. 只扫描 server/engines/<目录>/，**且只看该目录顶层 __init__.py 里有没有模块级 engine_plugin**（必须是 MemoryEnginePlugin 实例），**不递归子包**。
2. config.json 的 engines.modules 在 server/main.py 里**只做 importlib.import_module()，不会自动注册 engine_plugin**。要走这条路，模块必须在 import 时**自己**调 engine_registry.register_plugin(...)。

结论：**要么把引擎做成「顶层 __init__.py 导出 engine_plugin、可拖进 server/engines/ 即用」；要么 pip 安装成顶层包并在模块内自注册。** 二选一，别两条都半吊子。

## 1. 通用契约底线（两组改完都必须满足）

逐项勾选，缺一不可：

- [ ] engine_plugin 是**真实** server.engines.memory_plugin_api.MemoryEnginePlugin 的实例（不是自己 fallback 的占位类）
- [ ] name 小写下划线 [a-z][a-z0-9_]*，且**目录名 = name**，不以下划线开头、不命中保留名/内建名
- [ ] engine_label 非空、engine_color 是 #rrggbb、contract_version == "1.0.0"
- [ ] capabilities 与已实现方法一致：supports_X=True 就必须实现对应方法；只做检索就显式关掉 supports_generate/supports_stream/supports_ingest
- [ ] search() 每条返回 content / score / source_file / chunk_id / engine 五字段
- [ ] score 归一化 0~1
- [ ] source_file 是检索数据根相对路径或 [xxx] 可辨识标记，**绝不含系统绝对路径**
- [ ] 无同步 IO / 重计算阻塞事件循环（用 asyncio.to_thread）
- [ ] 不吞异常返回空列表（让异常抛出，交给路由器熔断器）
- [ ] check_availability 带 TTL 缓存
- [ ] 附依赖清单（第三方库装进环境）

## 2. A 组：RAG sdk0908 → planning_memory

### 2.1 问题定位

| # | 问题 | 现状 | 后果 |
|---|---|---|---|
| A1 | engine_plugin 不在包顶层 | 在 planning_memory/adapter/__init__.py，planning_memory/__init__.py 只有 __version__ | 拖进 server/engines/planning_memory/ 后 discover_plugins **找不到，静默跳过** |
| A2 | 包内绝对导入 | storage/ core/ schemas/ 里 7 处 from planning_memory.X import ... | 包名变成 server.engines.planning_memory 后顶层无 planning_memory，import 全炸 |
| A3 | 「modules 注册」路径不成立 | 文档写「或 config.json engines.modules 注册」，但 adapter 没自注册 | main.py 只 import 不注册 → 同样不生效 |

### 2.2 修改步骤（推荐方案 A：做成可 drop-in）

**Step 1：把运行时模块里的绝对导入改成相对导入**（只需改下面 7 处，examples/ 是独立脚本不用动）：

| 文件 | 改前 | 改后 |
|---|---|---|
| storage/vector_store.py:15 | from planning_memory._compat import to_thread | from .._compat import to_thread |
| storage/object_store.py:14 | 同上 | from .._compat import to_thread |
| schemas/generate.py:18 | from planning_memory.core.models import ... | from ..core.models import ... |
| core/consolidation/episode_consolidator.py:19 | from planning_memory._compat import to_thread | from ..._compat import to_thread |
| core/evolution/evidence_comparator.py:22 | 同上 | from ..._compat import to_thread |
| core/evolution/skill_inducer.py:20 | 同上 | from ..._compat import to_thread |
| core/evolution/skill_evolver.py:25 | 同上 | from ..._compat import to_thread |

> 规则：storage/ schemas/ 是二级子包 → 用 .. ；core/<子模块>/ 是三级 → 用 ... 。

**Step 2：planning_memory/__init__.py 在末尾导出 engine_plugin**：

~~~python
__version__ = "0.1.0"

# 接入点：discover_plugins() 读取本模块级 engine_plugin 完成自动注册
from .adapter.engine import PlanningMemoryEngine, engine_plugin  # noqa: E402

__all__ = ["PlanningMemoryEngine", "engine_plugin"]
~~~

**Step 3：目录名确认**。目录名 planning_memory 已与 name 一致，无需改；交付时整个 planning_memory/ 拷到 server/engines/planning_memory/。

**Step 4：补依赖清单**（新建 planning_memory/requirements.txt 或交付包根「依赖清单.txt」）：

~~~text
pydantic>=2.0
# 共享底座（集成方已随系统提供，无需另装）：
#   Qdrant（server.engines.qdrant_client）
#   embedding 模型（server.embedding_model，BGE-large-zh）
# 可选 LLM（不配则退化为纯规则模式）：
#   PM_LLM_API_KEY / PM_LLM_BASE_URL / PM_LLM_MODEL / PM_LLM_TIMEOUT
~~~

> 备选方案 B（不推荐）：pip install planning_memory 成顶层包 + 在 adapter/engine.py 末尾自注册 engine_registry.register_plugin("planning_memory", engine_plugin) + config.json engines.modules=["planning_memory.adapter"]。方案 A 更符合 SDK「拖放即用」约定，优先选 A。

## 3. B 组：课题3_长短期记忆 → long_short_term_memory

### 3.1 问题定位

| # | 问题 | 现状 | 后果 |
|---|---|---|---|
| B1 | 绝对导入 | engine.py:106 from memsys import MemoryController, QueryItem | 拖进 server/engines/ 后 memsys 变子包、非顶层，ModuleNotFoundError |
| B2 | __init__.py 静默兜底 | try: from .engine import engine_plugin except Exception: engine_plugin = None | B1 一崩就被兜住，engine_plugin=None，服务照常启动但**引擎不出现、也不报错** |
| B3 | 目录名不符 | 目录 课题3_长短期记忆（中文）≠ name=long_short_term_memory | 不符「目录名=name」约定，中文目录在 Windows 编码下 import 也脆弱 |
| B4 | 默认全 Mock | MemoryController() 默认 MockLLM/MockEmbedding | 接入后是哈希伪向量/关键词检索，无语义质量 |

### 3.2 修改步骤

**Step 1：目录改名**：课题3_长短期记忆/ → long_short_term_memory/（= name）。

**Step 2：engine.py 绝对导入改相对**：

~~~python
# 改前
from memsys import MemoryController, QueryItem
# 改后
from .memsys import MemoryController, QueryItem
~~~

**Step 3：__init__.py 去掉静默兜底**，让错误在启动时暴露：

~~~python
# 改前
try:
    from .engine import engine_plugin
except Exception:
    engine_plugin = None

# 改后（直接导入，出错就让启动日志报出来，别吞）
from .engine import engine_plugin
~~~

**Step 4：接入真实 embedding / LLM**（功能层面，非契约层面）。确认 MemoryController 的构造入参，接入时注入 GLM/智戎网关真实模型，避免默认 Mock；若确需 Mock 起步，至少在上线文档里写清楚。

> 说明：eval/ examples/ webui/ integration/ 里的 from memsys import ... 是**独立脚本**（自己把 memsys 放进 sys.path），不参与 server/engines/ 运行时，可不动；只有 engine.py 这处必须改。
