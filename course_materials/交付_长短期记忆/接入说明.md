# 子课题-3 交付：长短期记忆引擎（long_short_term_memory）

> 依据《记忆引擎开发 SDK v1.0.0》（`memory_engine_sdk.md`）交付。
> 包内目录结构已与目标系统一致（`server/...`），**可直接拖放落位**。
> 本引擎不需要额外检索数据文件：记忆由场次复盘/智戎适配器写入。

---

## 1. 三步接入

1. 把 `server/engines/long_short_term_memory/` 整个目录拖到目标系统
   `server/engines/long_short_term_memory/`；
2. 重启智戎服务；
3. 按 §5 验证（契约自检 + 引擎列表 + 冒烟检索）。

无需修改服务端任何代码：目录名 = 引擎 `name` = `long_short_term_memory`，
`__init__.py` 已导出模块级 `engine_plugin`，`discover_plugins()` 会自动注册。

---

## 2. 包内结构与落位对照

| 本包内路径 | 目标系统路径 | 说明 |
|---|---|---|
| `server/engines/long_short_term_memory/` | `server/engines/long_short_term_memory/` | 引擎实现（`__init__.py` / `engine.py` / `README.md` / `memsys/`） |

`memsys/` 是核心包（事实库 + 经验库 + 混合检索 + 记忆进化），
随引擎一起拖入，引擎内使用相对导入 `.memsys`，不依赖系统顶层包名。

本引擎**不随包附带 `data/`**，因为记忆不是静态文件，而是运行期由
记忆进化模块写入 SQLite/向量索引；如需要预置种子记忆，可通过
`controller.close_session()` 复盘写入。

## 4. 依赖

| 依赖 | 用途 |
|---|---|
| Python | 运行时（我们侧 3.12/3.14 均验证） |
| 标准库 | `sqlite3`、`urllib`、`http.server` 等，零第三方依赖 |

**不依赖** `faiss`、`qdrant-client`、`pandas`、`torch` 等；向量索引为内存实现，
SQLite 使用标准库。若需真模型，只要求运行环境能访问 DeepSeek/GLM API
（通过 `.env` 或环境变量注入）。

## 5. 验证（三条，按顺序）

```bash
# ① 契约自检（离线，无需服务端）——期望 [OK] 契约自检通过，退出码 0
python scripts/validate_engine.py long_short_term_memory

# ② 引擎是否注册（需服务端已启动）——期望列表里出现 "name": "long_short_term_memory"
curl http://127.0.0.1:8000/api/v2/memory-engine/engines

# ③ HTTP 冒烟——期望 “引擎已注册 ... available=true”
python scripts/smoke_test_engine.py long_short_term_memory
```

我们这边的离线自检输出见 `自检结果.txt`；逐项对照见 `契约自检清单（已勾选）.md`。

> 注意：官方冒烟脚本固定用 `"测试查询"`。本引擎**空库**时会正常返回 0 条；
> 可先用复盘接口写入几条记忆，或调用 `/api/v2/memory-engine/search` 传入
> 已写入的实体词（如 `T-90 速度`）做端到端验证。

## 6. 真模型配置（B4）

引擎默认 `MockLLM` / `MockEmbedding`（零依赖离线可跑）。正式接入建议配置：

| 环境变量 | 取值 | 说明 |
|---|---|---|
| `LSTM_LLM` | `deepseek` / `glm` / `mock` | 默认 `mock` |
| `LSTM_EMBEDDING` | `glm` / `mock` | 默认 `mock` |

也可在仓库根放 `.env`（模板见 `.env.example`），`load_env()` 会自动向上查找：

- DeepSeek：`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`
- GLM：`GLM_API_KEY`、`GLM_EMBED_MODEL`

密钥缺失/失效时自动降级 Mock，不阻断服务启动。

| 字段 | 我们的取值 |

## 8. 能力与边界

- **只检索、不生成**：`supports_generate=False` / `supports_stream=False`，
  服务端 SSE 层会自动补 `engine_done(status="unsupported")`；
- **不 ingest / 不 delete**：记忆写入走记忆进化模块（场次复盘），
  不认领文件后缀，不与内建引擎抢路由；
- **双库混合检索**：事实库（SQLite 参数级精确）+ 经验库（向量语义召回），
  同一查询同时检索后按融合分排序；
- **记忆进化**：写入查重、合并、艾宾浩斯遗忘、抽象（由外层复盘触发）。

## 9. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 引擎没出现在列表里 | 目录名/导入有问题 | 确认目录名 `long_short_term_memory`、`__init__.py` 导出 `engine_plugin`、无 `__pycache__` 干扰 |
| 检索 0 条 | 记忆库为空 | 先通过复盘接口写入记忆；或调用 `controller.close_session()` 预置种子 |
| `available=false` | 双库初始化异常 | 看服务端日志；通常为磁盘权限或 SQLite 路径问题 |
| 官方冒烟脚本检索 0 条 | 固定查询词 `"测试查询"` 在空库无命中 | 属正常现象；换已写入的实体词再验 |
| 想要真模型但没网络 | 保持 Mock | Mock 即可演示；真模型在本地演示时配置 `.env` |
